## 必要负控

认证/授权不能只跑“管理员成功请求”。先记录旧实现对每种身份的允许/拒绝，再记录新实现；任何由拒绝变允许必须作为阻塞缺陷，不能用“精简网关”解释。

公开端口与服务直连都测。普通 token 签名正确但已撤销不能继续使用；IAM 不可达时不能回退纯 JWT。所有临时兼容桥、未迁移 Registry 闭包、gateway 剩余 gRPC 调用列入剩余项。

## 自动门禁脚本要求

Lead 在代码仓库实现可重复运行的最终审计工具：

1. 生成 gateway 依赖图并查禁止项，检查运行配置无业务凭据。
2. 读取旧入口快照与 ROUTE-STATUS.csv，确认 operationId 覆盖完整、承接方真实存在；特殊入口另核对。
3. 运行当前契约工具与生成工件漂移检查，不靠手改基线掩盖删除。
4. 保存机器可读结果，失败非零退出；CI 执行。

不要用“测试全绿”替代真实跨进程链路，也不要因媒体硬件不可用无限重试：记录 A13 的实际状态与限制。核心代码、权限与信令验收完成但硬件未做时，最终报告必须明确区分。

## 完成输出

`progress/FINAL-ACCEPTANCE.md` 应写：最终架构、各服务端口/启动命令、148+19 承接矩阵索引、每项验收结果、日志位置、各提交与远程状态、仍未验证的硬件/平台项。`STATUS.json` 只有在所有核心迁移与代码验收通过后才能设 complete。任何旧 105 条仍在 gateway/临时泛业务 BFF 执行均不能标 complete。
