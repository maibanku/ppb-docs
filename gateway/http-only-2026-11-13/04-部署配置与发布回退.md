# 04 配置、部署、CI、提交与回退

## 配置拆分

- gateway.yaml：仅端口/TLS/可信上游代理、固定 HTTP/WS 路由、限流/超时/日志。不能残留 jwtSecret、内部 RPC token、DB/MQ/成员 Redis 配置。
- 各服务 YAML/env：自己的 HTTP/RPC 监听、认证验证/签发与内部依赖。真实密钥沿用私有文件/环境，不能把它们复制到公共模板或文档。
- 目前端口：gateway 8080；IM RPC 9102/HTTP 9112；File 9104/9114；Camera 9106/9116；IAM 9107/9117；LiveKit 7880。新端口先检查占用并登记，不默认杀监听进程。
- 本地 Docker 使用当前容器和卷；新增配置前先以脱敏方式确定 localhost/LAN 地址，不连接历史远程默认库。

## 必须修改的工程入口

逐一搜索并更新：`go.work`、相关 go.mod/go.sum、`deploy/scripts/start-all.sh`、`stop-all.sh`、Docker/Compose/K8s 中真实使用的配置、`.github/workflows/gateway-governance.yml`、`tools/ci.sh`、文档与日常排查命令。只改 Go 文件未改启动脚本不算可交付。

若模块/工具迁移，旧 apicatalog 的依赖、Go internal 可见性、Swagger 静态资源路径与测试包名须一起处理；不要留下旧入口能编译但生产仍启旧二进制的状态。

## 渐进发布

1. 保存当前相关服务二进制、精确 PID、工作目录、参数、环境的私有快照，文件 0600。不要打印环境全量。
2. 构建/测试服务自有 HTTP 和认证；先启动对应服务，旧 gateway 仍能调用旧 RPC；验证服务新 HTTP 的权限负控。
3. 独立验证新透明 gateway（临时只绑定 loopback 测试端口），通过当前客户端 URL 跑真实回归；不能只看 /ping。
4. 切换公开 8080 进程时只停止核对过的旧 gateway PID，保留原环境/参数以便回退；不得 `pkill claude`、按端口乱杀无关进程。
5. 验证 IAM 回调/Cookie、管理权限、WS 重连、文件、通话后再清理旧兼容路径。没有通过的旧执行链不可删除。
6. 回退顺序：先恢复旧 gateway → 确认旧 RPC 能用 → 必要时回退业务服务。不要先关闭旧网关依赖的服务。

gateway 进程启动环境最小化，不需要继承 DB/SMTP/MQ/内部凭据。确认 WebSocket 切换时客户端可重连，记录短暂中断与在途请求处理。

## CI 与验收门禁

- 全 Go 模块 build/test；针对鉴权及跨进程边界增加有意义回归；不要为格式/纯移动写镜像实现的测试。
- API/HTTP 契约相对原基线 148 条保持兼容；所有特殊入口单独核对，聚合目录工具离线可跑。
- 服务 HTTP 工件重新生成零 diff；配置歧义/未知 owner/非法 upstream 启动失败。
- 自动依赖审计：`go list -deps ./server-gateway` 不出现 grpc/grpc_gen、gorm、eventmq/amqp、业务 Hub/Redis route。不要仅 rg 查网关根目录而漏内部转移依赖。
- 模拟上游新增接口后，保持 gateway 二进制不变验证新 URL 可转发；并验证响应大整数、业务失败、Location、Cookie、Range 与 WS 帧不变。
- 生成最终接口承接矩阵与真实证据；pending/blocked 不能改名为 done。

## Git 纪律

每个可运行批次小提交并推送原远程分支，提交说明为具体改动与验证。提交自己的明确路径，禁止 `git add -A` 带入秘密/他人改动；不 force push，不清理未归属改动。文档 ppb-docs 与代码 ppb-base 分别提交。无法推送时保存本地提交并记录原因，不能假装已推送。
