# 02 认证、授权、登录与身份信任

## 迁移原则

最终网关不持有业务 JWT 签发密钥、内部 RPC token、DB/Redis/MQ 口令；它透明传递客户端凭据，由目的服务验证。允许未来配置通用 HTTP external-auth，但不能以此保留成员组织选择等业务编排。

当前 IM HTTP 只验证 edgeauth 网关断言，而不独立验证客户端凭据。因此**不能先删除签名或把 Session 设为可空**。先引入服务端认证中间件，再让 gateway 退出身份签发链。

## 公共中间件与服务所有权

将 `server-gateway/auth` 中可复用的 claims/验签/白名单/上下文能力抽到无 gateway 依赖的服务认证包，分清以下身份：member、org-select、manage、camera-subject、IAM Cookie。鉴权代码复用一处，服务配置明确；不把鉴权复制成四份并逐渐漂移。

- member：验证签名/issuer/到期、sid，向 IAM 权威会话核对撤销/账号状态，并核对 Chat 成员/工作区状态。缺检查器或下游不可用均拒绝。
- org-select：只允许组织选择建立成员会话，不能访问业务接口。
- manage：保留管理主体类型隔离。身份合法不等于有业务应用权限。
- camera-subject：保持独立 token 密钥、typ、guest 流程与原 4 条匿名白名单，不接受 Chat member/manage 作为 Camera 主体。
- IAM Cookie：向 IAM 获取新鲜管理 context；保留业务桥原有同源/CSRF、最小 Cookie 转发和 IAM Actor 语义。

HTTP 验证后的身份进入服务 request context；原 gRPC 链路由共享适配注入可信 actor/internal credential/IAM assertion。客户端自带 `X-Ppb-*` 或 operator 字段均不可信。HTTP 直连服务也必须通过同样验证；不能只靠“内网端口”授权。

## 登录/注册编排归属

源文件 `proxy/member_auth.go`、`member_oidc_exchange.go`、`member_invite_mint.go`、RegisterUserDomain 注册/邀请成功后的 token mint、`main.go` 的 IssueMemberSession 回调，迁至 IAM 的业务会话应用层（组织成员数据仍由 IM 权威提供）。

必须原样保留：

1. 登录认证→ResolveUser→组织列表→IAM 会话锚→org-select。
2. 选择组织→校验 select token/sid/账号/成员/工作区→member token；无可用组织不得签伪有效凭据。
3. OIDC accessToken 由 IAM userinfo 权威验证，组织映射仍向 IM 查询；浏览器认证与桌面环回/PKCE/nonce 回调不改变。
4. 注册/邀请接受后的凭据签发统一调用 IAM，不在 gateway 包装返回值。
5. 退出时撤销 IAM 会话及必要 token 防重放；已建立 WS 的撤销/踢线仍能抵达所有 IM 接入节点。
6. 成员凭据签发密钥统一配置给真正签发/验证服务；从 gateway 配置与运行环境移除，不打印或提交真实值。

旧 `/api/v1/auth/member/{login,session,oidc-exchange}` 地址通过透明兼容路由到 IAM；不以客户端必须升级为本轮前提。

## 管理权限等价迁移

源 `internal/permguard`、`proxy/{policy,perm_codes,iam_business_bridge}.go`、各服务 `AdminMethodPerms` 与 `server-pkg/authzport` 一起核对。逐路由建立矩阵，不只靠单个 RPC 是否“已有授权”。

- app_perm：按 (app_key, permission) 判定，跨应用同名码不能互通。
- self：只允许原本声明的身份自助入口。
- super_gov：保持治理入口语义，不能因 is_super 扩大 IAM 业务权限。
- 动态 resolver：GET roles 的 roleScope 等必须服务端解析；query/body 冲突优先级与旧实现一致。
- legacy super 与 IAM is_super 的语义不同：现有 authzport legacy 分支可超管直通，IAM 分支明确不通配业务权限。不能把两者合并成一个 bool。
- 权限版本 revision 权威验证、撤权下一请求拒绝、授权回源失败拒绝；移除网关守卫前，服务端必须有完整等价实现。
- `/iam/api/v1/business/manage/**` 的兼容桥按每个 owner 路由，不能让 IAM 管理 Cookie 无条件访问所有下游。
- 审计 actor 取认证上下文，不取客户端字段；治理/业务审计归对应库，不输出消息正文或私密内容。

负控至少覆盖：无凭据、过期、撤销、无 sid、org-select 冒充、成员停用、工作区停用、无应用权限、跨应用权限、IAM super 无业务码、错误治理权限、CSRF、伪造 actor、IAM 不可用。
