# 实施步骤与文件清单

状态：待执行。文件名属于实施目标；执行者应先核实现有抽象，避免为符合目录而机械移动代码。各阶段先通过验收再进入下一阶段。

## G0：建立可复核基线

读取 `ppb-base/server-gateway/README.md`、工作区指令、`main.go`、`gateway_routes.go`、`proxy` 注册/权限/绑定实现及已有测试；读取本设计目录。

修改：新增离线路由目录导出工具与基线快照；在 `ppb-docs/gateway/ac/` 保存基线说明。

输出：记录两仓 HEAD、工作区已有变更、Registry 与直接 Gin 路由清单、RPC 实际 upstream、身份/权限、处理器来源、现有测试结果及失败。生成目录不得依赖拨通生产或本地业务服务。

必须清点文件直通、认证桥、WebSocket 和文档/健康入口。尚未识别的策略标记 unknown 并阻止对应接口迁移，不能默认 public。

提交建议：`docs(gateway): capture route and compatibility baseline`。

## G1：修复 Registry 的确定性

修改：`server-gateway/proxy/method_registry.go`、相应测试、`main.go` 校验装配。

实现：统一路径校验；精确重复、模板同构及歧义拒绝；保留精确优先；排序导出；注册结束只读。先扫描现有重叠，对有意精确覆盖模板的场景形成记录。

测试：重复精确、同名模板、异名同构模板、交叉歧义、不同方法不冲突、固定路径优先、路径优先于 query、非法模板、注册顺序无关。

失败必须可定位到具体注册项；不能用删除业务接口的方式消除冲突。

提交建议：`fix(gateway): reject duplicate and ambiguous routes`。

## G2：建立完整元数据与目录

修改：Registry 的 RouteMeta/RouteSpec、`proxy/policy.go` 的适配边界、各域注册文件、`gateway_routes.go` 特殊入口登记；新增 `internal/apicatalog` 与 `cmd/api-catalog`（如无现成工具）。

实现：稳定 operationId；显式身份类别；连接现有管理策略；特殊处理器登记；目录导出含来源、RPC/upstream；检测孤立策略和未归属接口。

迁移方式：先补元数据，保持调用与返回逻辑原样。现有 UncodedManageRoutes 不得删除；新校验通过后才讨论合并实现。

测试：未声明匿名、缺策略、未知身份、未绑定 RPC、重复 operationId、孤立清单、错误 upstream 均失败。身份与权限字段不进入普通用户响应。

提交建议：`feat(gateway): add validated API catalog metadata`。

## G3：todo 域生成试点

修改：`idl/todo.proto`、`idl/buf.yaml`、`buf.gen.yaml`、依赖锁文件、`api/policies/todo.yaml`、HTTP 生成产物、todo 兼容钩子与装配开关、现有相关测试。

先迁移两个读取端点：GET `/api/v1/todo/tasks/{todoBizKey}`、GET `/api/v1/todo/todos`；成功后迁移其余创建、更新、状态变更和删除，共六条已有接口。不要创造另一套路径。

配置固定版本生成工具，提供一条可复现的生成命令；禁止 generate_unbound_methods 自动暴露未标注 RPC。策略由同一目录校验，HTTP 注解是映射事实源。

保留旧注册函数用于回滚；通过启动时确定的域级开关选择整域处理器。切换时从旧 Registry 移除相应运行条目，但可保留基线快照；禁止运行期双写或把生产请求同时发给两套处理器。

兼容测试先使用可控上游验证边界，再在真实本地 IAM/IM/MySQL/Redis 等现有环境完成业务闭环。可控上游仅用于错误、超时、身份伪造等测试，不替代运行环境。

退出条件：六条接口全覆盖；当前客户端无需修改即可调用；错误/身份/字段行为等价；生成与旧实现目录一致；回滚可执行。若不满足，保持旧实现并记录 ADR，不继续扩大迁移。

提交建议：契约与工具链、读取适配、写入适配与回滚各独立提交。

## G4：文档与 CI 门禁

修改：`swagger/swagger.go`、相关测试、现有 CI 工作流（先查明仓库实际使用的系统）。

实现：继续输出 OpenAPI 3.0；补齐参数位置、鉴权、稳定 operationId 与 tags；内部策略细节按现有文档暴露策略过滤。文档目录与运行目录互相核对，覆盖显式特殊入口。

门禁：生成后无非预期差异；路由/策略校验；HTTP 契约兼容性 diff；已有 gateway 测试；试点端点契约测试。仅 Proto breaking 检查不够，还需检测路径删除、方法变化、参数位置/必填变化及响应字段不兼容。

CI 不要求提交本地凭证，不依赖个人电脑服务；真实本地验收单独记录。

提交建议：`ci(gateway): enforce route contract and generation checks`。

## G5：按域推广

依赖 G3/G4 全通过。建议顺序：IM 普通查询→IM 写操作→管理端普通接口→其他域。

认证编排、邀请签发、动态授权 resolver、文件流、WS 不纳入机械批量转换。跨域 legacy UserService 必须按真实 upstream 分别处理。

每域独立提交并验证；批量替换前形成端点映射表，迁移后更新验收矩阵。负责人不能用“生成成功”代替业务验收。

## 每次提交的检查

1. 仅暂存本任务明确文件，保护现有其他任务变更。
2. 运行受影响模块测试；涉及治理链时运行整个 gateway 测试。
3. 检查 diff 中是否包含凭证、日志、生成噪声或无关格式化。
4. 记录提交 SHA、实际命令、结果和剩余风险；有远程推送授权时分批推送，失败如实记录。
5. 本轮没有数据库变更；若实施中发现必要性，应先说明具体业务需求并更新设计。
