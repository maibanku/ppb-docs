# 数据模型

> 概念与约束设计，不是已执行 DDL。物理列名、长度和迁移脚本在实施时复核。

## 1. IAM 权威数据

| 实体 | 关键字段/约束 |
|---|---|
| users | 稳定内部 ID、展示资料、全局状态、禁用/删除时间 |
| identities | user_id、identity_type、规范化登录值、verified_at；按显式命名空间唯一 |
| external_identities | user_id、provider_config_id、issuer、sub；外部身份不可重复归属 |
| credentials | user_id、类型、哈希及算法版本、锁定状态、更新/吊销时间 |
| tenants / memberships | IAM 组织、成员与状态；不隐式映射业务工作空间 |
| applications | app_key 唯一、状态、应用元数据与注册策略 |
| oauth_clients | client_id 唯一、application_id、客户端类型、redirect_uri 允许列表、scope、密钥引用 |
| application_assignments | 用户/组到应用的显式访问分配，默认最小权限 |
| sessions | 不可预测会话标识、user_id、认证强度、过期/撤销时间和版本 |
| grants | user_id、client_id、scope、IAM session、授权与撤销状态 |
| authorization_codes | code 摘要、client、redirect_uri、PKCE、nonce、过期与消费状态 |
| refresh_tokens | 摘要唯一、grant、family、前驱、过期/消费/撤销状态 |
| subject_mappings | user_id、issuer、client/sector、sub；遵循选定 public/pairwise 策略 |
| audit_events / outbox | 操作主体/对象、结果、事件 ID/版本、投递与重试状态 |

IAM 组织、目录组与管理角色若第一期实施，须补独立关联表和授权作用域。认证管理权限不得复用业务 is_super。MFA secret 加密保存，恢复码/验证码摘要保存，均不作为审计正文。

邮箱/手机号规范化策略须先确定；不能泛化小写规则到所有身份。唯一键必须同时定义软删除后的保留、重用与恢复政策，禁止不同表各自给出矛盾的账号占用规则。

## 2. 业务身份映射

业务库新增外部身份关联：provider_config_id、issuer、sub → local principal type + local ID。唯一性和授权规则防止一个外部身份被错误绑定到多个同类本地主体；允许同一人员分别绑定 member 与 admin，但管理员绑定独立审核。

本地稳定 user_id/biz_key 保留；IAM 内部 user_id 不直接替换业务外键。不同客户端若使用 pairwise sub，显式维护各客户端映射；不得通过邮箱猜测关联。

现有 user_identities.provider 长度 32 不适合直接存 issuer URL，应使用独立 provider 配置引用。现有 user_oauth_binding 与身份表的重复映射，在迁移期明确单一权威、对账和退役顺序。

## 3. 会话关联与一致性

业务会话记录本地 sid、身份关联、应用/客户端、IAM 会话或 grant 关联、状态版本与撤销时间。不同设备与 grant 按实际关联范围撤销，不通过用户 ID 粗暴替代“退出当前设备”。

授权码兑换、刷新轮换、绑定身份通过数据库事务/条件更新及唯一约束保证单次消费与并发唯一。缓存不是认证状态的唯一事实源。生命周期修改和 outbox 同事务。

不跨 IAM 与业务库做假原子事务：采用幂等接入、映射唯一键、状态查询、补偿与对账。JIT 创建失败不能留下已登录但无本地准入检查的会话。
