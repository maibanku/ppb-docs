以上是抽样代码核查，实施前按最新提交重新盘点调用方、数据量和部署状态；不代表完整安全审计。代码参考见 [README](../README.md)。

## 2. 能力搬迁

| 当前内容 | 目标 |
|---|---|
| 身份/凭证、密码策略、验证码、找回、第三方登录 | server-iam |
| 用户业务主键、偏好、签名、文件关联 | 保留业务侧 |
| 组织成员、离职及业务 RBAC | 保留业务侧 |
| 管理员资格与授权 | 保留业务侧；认证凭证迁 IAM |
| 旧会话 | 分批退役，不直接转换成 IAM token |
| OAuth 绑定双表 | 对账、迁移、停止双写、最终退役旧权威 |

## 3. 阶段

P0：列数据和调用方清单，固定协议/时限/权限边界，备份恢复演练，建立冻结或增量捕获方案与回退检查点。

P1：新增 IAM module、独立库和门户，完成账号/凭证、应用客户端、协议、密钥和基础会话；使用测试应用验证，不切生产认证。

P2：管理端小范围绑定与登录；补服务端管理员会话、MFA、撤销和业务资格检查。未登记为管理员的 IAM 用户不得进入后台。

P3：成员账号按批映射，接入 chat/camera 等；复核业务租户和应用准入。移动端独立接入计划；游客身份、额度合并和订单归属仍按业务规则处理。

P4：迁移批次通过观察期后停用旧认证写入口，明确旧凭证过期窗口；最后移除旧密码能力和冗余表，清理前保留审计与恢复材料。

## 4. 密码和身份迁移

旧 user_id/biz_key 与数据归属保持。迁移生成 IAM 主体和映射；账号冲突、重复邮箱、已停用/软删除、同人多个管理员账号进入人工处置清单，不自动合并。

密码哈希只有在算法、参数和校验语义验证兼容后才受控迁移；无法兼容则采用验证旧凭证后的首次登录迁移或安全重置。首次登录迁移只限明确未迁移账号，通过独立审计流程运行，不作为 IAM 不可用时的自动回退。

明确每批迁移后的唯一密码权威。密码修改/重置与切换并发必须锁定或有增量对账，禁止长期双向同步密码。

## 5. 灰度与回退

按应用/客户端和账号批次配置路由，保留迁移批次 ID、映射版本、切换时间、旧凭证状态和验收记录。关键数据库修改先兼容后收敛。

回退前检查迁移后改密、停用、绑定与角色变更；不得恢复旧密码或撤销状态绕过新的安全策略。需要回退时可停止新登录、保留合法业务会话并人工恢复；不得只切流量就声称安全回退完成。

验收包含：新旧用户、重复身份、并发迁移、改密、停用、组织切换、权限隔离、HTTP/WS 撤销、服务故障和恢复后凭证状态。
