# 注册与登录调用流程

> v0.4。端点名为拟定契约；数据库字段名与OIDC对外字段映射，不直接透传数据库结构。

## 1. 平台普通注册

iam-web进入注册 → IAM发送并保存verification_challenges → 验证目标、限流与一次性凭证 → 同库事务创建user、user_identities、user_profile → 密码方式写user_credentials，第三方方式写user_external_identities → 写audit_events/event_outbox → 提交。

验证码登录不强建空密码。已有身份进入登录或受控绑定，不重复注册。自助注册不写platform_admins和管理员角色。注册成功如自动登录，再创建auth_sessions；协议登录按实际过程写grant/code/refresh相关记录。

## 2. 相机首次登录/注册

camera使用独立客户端、系统认证会话/PKCE或Web后端发起授权 → IAM完成认证与应用准入 → 授权码回调 → 业务接入后端验证身份 → camera事务按user_id幂等创建camera_accounts，可延迟创建camera_user_profiles → 建camera_sessions → 返回公共资料与相机业务状态。

已有IAM用户不重新创建user；camera已停用/注销时走恢复或拒绝策略，不当新用户重建。camera开通失败保留IAM账号，可幂等重试。游客作品/额度归并独立明确确认；额度赠送由现有账本幂等机制处理，不包含在本SQL。

公开camera应用无需每人插application_assignments；assigned模式才检查显式分配。注册/开通不重复创建applications、oauth_clients。

## 3. 聊天用户

IAM认证 → chat准入 → 按需创建chat_user_profiles → chat_sessions。创建/加入组织时才写chat_workspaces/chat_memberships；邀请接受时写成员角色/部门关系。无组织可进入创建/加入引导，不自动成为组织管理员。

登录初始化返回公共用户、聊天账号状态、是否选组织；选定组织后返回该成员身份与组织权限。组织列表、通讯录、会话和WS凭证分别加载；切换组织必须重新校验成员资格。

## 4. 平台管理员开户与登录

授权治理人选择已有用户或邀请新用户确权注册 → 创建/恢复platform_admins → 分配platform_admin_roles → 审计。is_super仅专用治理入口；不随邮箱或外部角色自动授予。

登录时验证user_status、IAM会话和MFA → 验证admin_status及有效期 → 校验后台应用准入 → 建platform_admin_sessions → 汇总角色菜单按钮与后端权限 → 返回后台初始化快照。配置assigned的后台应用时，管理资格与对应应用分配应作为受控开户流程一起处理。

成员登录不返回平台后台角色菜单；管理登录不自动取得所有聊天组织权限。

## 5. 返回和凭证

Web通过HttpOnly/Secure Cookie建业务会话，JSON只返回必要用户/业务摘要；原生端按受控流程取得业务凭证并放系统安全存储。IAM令牌不直接塞入旧HS256解析器。API结果不暴露数据库ID/敏感凭证全集，按需要使用biz_key和脱敏邮箱手机。

平台改角色后更新授权版本与缓存，前端刷新菜单，后端实时按有效快照拒绝已撤销操作。全局退出与业务退出范围分别展示，未完成不得虚报成功。
