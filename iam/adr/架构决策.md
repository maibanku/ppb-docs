# 架构决策

> 2026-10-27 · v0.4。记录本轮方案选择，未代表工程落地。

## ADR-001 自研 Go 认证中心

方向：参考 MaxKey 的认证产品形态，自研 PPB IAM。此前“接入 MaxKey”的方案不作为实施方向。首期专注身份认证、应用注册、标准接入和会话，不复制全部企业 IAM 功能。

## ADR-002 当前同仓 server-iam，保留未来独立 ppb-iam

| 维度 | ppb-base/server-iam | 独立 ppb-iam 仓库 |
|---|---|---|
| 认证能力与外部接入 | 可完整实现 | 可完整实现 |
| 初期迁移 | 同仓协调代码和契约方便 | 跨仓协调与版本管理更多 |
| 构建部署 | 需建立按目录 CI 和独立镜像 | 天然独立工程 |
| 依赖边界 | 容易意外引用业务包 | 边界更明确 |
| 权限与产品化 | 仓库权限通常共用，后期可提取 | 更适合专门团队与外部交付 |
| 运维隔离 | 由实际部署资源决定 | 同样由部署决定 |

当前选择同仓独立服务。独立 module、数据库、镜像和版本化 API；禁止跨库和业务内部包依赖。产品名 PPB IAM，工程名 server-iam 不限制服务其他项目。

拆仓触发条件：独立团队/访问权限、独立交付与支持周期、多个外部项目稳定使用，或同仓发布协调成本已明显增加。拆仓保持 issuer、用户/subject、client_id 和协议兼容，不能因仓库改名重建身份。

## ADR-003 统一用户与IAM，业务组织独立

最新决定替代v0.1：server-iam内部合并通用用户/公共资料/认证/平台授权，server-user逐步退役。chat组织、成员、部门、邀请与组织角色归server-im。业务扩展各自保存，统一内部用户ID。首期不额外创建IAM企业组织、目录组或重复平台用户映射。

## ADR-004 独立认证前端

iam-web、iam-manage-web、业务前端独立构建。先落门户和业务后端回调；Web 目标使用后端会话，原生客户端独立 PKCE 接入。会话传播和退出必须真实完成才能展示成功。

## ADR-005 尚待固定的实现决策

**已定（2026-10-27，阶段2 调研裁决）——OIDC 协议库：`github.com/zitadel/oidc/v3`，拟锁 `v3.42.0`（2026-06-01，Apache-2.0）**。理由：P0 能力面全内置（授权码+PKCE S256/Discovery/JWKS/ID Token/UserInfo/refresh 轮换/撤销）、近月仍在发版且 ZITADEL 商业产品自用（dogfooding）、`op.Storage` 接口小而清晰 + 泛型 Session，与 GORM + 自有会话模型集成成本最低；集成方式为薄封装（实现 op.Storage 的 GORM adapter + 自有 Session 类型，端点挂现有 HTTP mux），不 fork、不自研协议层。备选 `ory/fosite v0.49.0`（发版停滞 22 个月、依赖已归档的 square/go-jose.v2、Discovery 需自建，仅作退路）；明确排除 `go-oauth2/oauth2`（无 OIDC 层且停更）。
**落锁硬门槛**：go.mod pin 时必须 `go mod graph` 核对实际解析的 go-jose 模块路径与版本（go-jose 生态 2025 年有维护权交接风波，快照中曾出现未核实 fork 指向 `jeremysolanas/go-jose/v4`）——若非 `go-jose/go-jose` 主线，先评估该 fork 再落锁；同时复查 releases/latest 是否已有 v3.43+。CI 引入 govulncheck 盯 jose 链。调研全文：ppb-base `.superpowers/sdd/CLAUDE_CODE_PROMPT/task-2-report.md`（归档后将随工作区清理，结论以本 ADR 为准）。

其余 P0 待定项（设责任人与截止阶段）：subject 策略（pairwise/public，阶段2 接口定稿前）、令牌/会话时限数值（阶段2 联调前）、撤权 SLA（阶段2 联调前）、MFA 恢复方案（阶段2 管理端前）、HA 指标（生产开放前）、开发数据库方言适配（阶段2 前端联调前）。本轮不虚构选型已验证。


## ADR-006 平台角色菜单按钮授权

选择platform_role_menus为角色普通授权入口，platform_menu_permissions映射节点实际授予的API权限；不同时维护platform_role_permissions。人员分配角色后批量获得菜单按钮，变更角色统一生效。is_super放platform_admins，管理会话独立表。菜单统一platform_命名，当前不拆placements。

## ADR-007 数据库风格与字段命名

沿用ppb-base雪花ID+表专属业务键、公共时间软删、逻辑外键与KV。用户明确要求全部字段至少两个单词以下划线连接，优先于既有单词列习惯；协议标准名保持。新建库SQL选MySQL 8.0.16+，开发方言适配、依赖库和安全时限仍需工程验证。物理SQL v0.4为目标态，旧库升级另交付。
