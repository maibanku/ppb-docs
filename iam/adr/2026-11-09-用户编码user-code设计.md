# 用户编码(user_code)设计 — 2026-11-09

## 意图与背景

- 管理台与客户端都需要一个**给人看的用户标识**:管理台列表不再展示 `user_biz_key`/雪花 id(2026-11-09 决策),客户端需要一个可口述/可检索的短号码。
- 现有标识分工不变:`user_id`(雪花)= 库内关联键;`user_biz_key`(`acct_`)= 对外契约键(wire/JWT/审计)。**新增第三标识只做展示与检索,不挤占前两者任何职责。**

## 目标

1. `user` 主表新增 `user_code`:系统分配、全局唯一、永不变化、8 位纯数字字符串。
2. 管理台(iam-manage-web)用户相关列表/筛选/弹窗以 user_code 取代 biz_key 的**展示位**;biz_key 从所有页面渲染中退出(API 载荷照旧返回,寻址语义不动)。
3. 客户端(C 端)可见:个人资料页展示自己的编码;成员信息结构带编码供他人名片展示(渐进接入)。

## 非目标 / 反目标

- **不做登录标识**:8 位数字可登录即成撞库枚举面(红线)。
- **不做 API 寻址键**:wire 寻址/JWT subject/审计 actor_key 继续 biz_key,永不切换。
- 不迁移、不改写既有 biz_key;不动 `user_identities`/工号(identity_type=4)语义。
- 不承载任何权限/状态语义。

## 约束

- 权威 schema:`ppb-docs/iam/tech/sql/schema.sql` 必须与迁移同步更新(`deploy/sql/ppb_iam/` 镜像)。
- 生成不派生自雪花 id/biz_key(零信息泄露);随机 8 位数字(10^8 空间,自用规模 + 唯一索引兜底重试)。
- proto 变更一律 **additive**(新字段追加,不触碰既有 bizKey 字段编号),老客户端无感知。
- 管理台写操作端点内部仍是 biz_key 寻址;`user_code` 仅在「人输入」处被接受并翻译。

## 已定设计(对话拍板)

| 决策点 | 定案 |
|---|---|
| 落表 | `user` 主表(与 biz_key 同类:系统分配不可变锚点;非资料、非登录标识) |
| 形态 | `VARCHAR(16)` 存 8 位纯数字(允许前导零),注册/Provision 时生成 |
| 唯一性 | `uk_user_code` 唯一索引;生成冲突重试(上限后报错) |
| 存量回填 | 一次性迁移:全量生成 → 加唯一索引 → 置 NOT NULL |
| 展示位(管理台) | UsersView 列与关键词筛选;AdminsView/SessionsView/MfaView/TokensView 的用户列与其 userKey 筛选;「新增管理员」「准入授予」弹窗输入框改收 user_code |
| 展示位(客户端) | `common.MemberInfo` 追加 `userCode`;user.proto 自视角资料响应追加;ppb-chat 个人资料页渲染;成员名片展示编码为后续客户端迭代 |
| 审计页 | 列表响应服务端解析 actor_key 与 target_key(user/admin 类目标 → 编码+昵称展示副本;menu/role 等其他 target 类型暂显原 key;admin actor 经 platform_admins→user join 解析);actor_key 筛选框改收用户编码;归档 `actor_key`/`target_key` 原文不动 |

## 范围裁定(2026-11-09 评审后拍板)

1. **审计页做全**(actor+target 解析、筛选改编码)——否则审计页成为唯一残留 biz_key 的管理页面。
2. **C 端按编码搜人本期不做**:需要新增 iamx RPC + SearchMembers 接线,超出 additive 范畴;管理台弹窗翻译走 manage API 直连(不动 iamx 冻结面)。留作后续增量。
3. **chat-manage-web 本期不动**:该台 user biz_key 仍可见,退场列为后续批次(已知口径,非遗漏)。
4. **成员名片**:proto 本期带字段,名片渲染随客户端后续迭代;**不做**用户可控隐私开关。

## 实施面(供计划展开)

1. **DB/迁移**:schema.sql + 000N 迁移(加列→回填→唯一索引→NOT NULL);cmd/migrate 入口。
2. **server-iam**:注册(`account_service.go`)、Provision(`account_provisioning.go`)、demo seed 三处生成;manage 用户/管理员/会话/MFA/令牌列表与详情响应带 code;关键词搜索含 code;按 code 查人(供管理台弹窗翻译;C 端检索后续增量)。
3. **idl**:`common.MemberInfo.userCode`、user.proto 资料响应与 `MemberIdInfo.userCode`(id 面回查供 im/mail/file 填充)、相关 Resolve 响应——全部 additive。
4. **server-im**:`local_user_client.go`/`user_compat_*.go` 的 MemberInfo 填充链带出 code。
5. **iam-manage-web**:5 页列/筛选/弹窗替换;`menu-row` 寻址逻辑不动。
6. **ppb-chat**:个人资料页「用户编码」行(读自资料响应);名片可选展示。
7. **测试**:生成/重试/回填幂等(TDD);列表响应契约;翻译端点;前端列快照。

## 风险

- 回填锁表:自用规模用户量极小,瞬时完成;迁移内分批兜底。
- 码空间枯竭:10^8 对自用为天文数字;重试上限 + 报错兜底。
- 双标识滥用:靠本 ADR 红线条目约束评审。
