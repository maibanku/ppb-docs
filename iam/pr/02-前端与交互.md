# 前端拆分与交互

[需求基线](../PRD.md) · [技术大纲](../tech/技术大纲.md)

## 1. 三类前端（IAM-05）

| 工程 | 页面职责 |
|---|---|
| iam-web | 登录、注册、找回密码、验证码、MFA、第三方登录、个人安全、设备会话 |
| iam-manage-web | 用户目录、认证组织、应用客户端、应用分配、策略、审计 |
| base-manage-web / 各业务前端 | 业务页面、管理员资格、业务组织、角色权限、登录入口 |

同仓独立构建部署。可共享轻量 UI 组件，不共享认证会话状态或业务插件运行时。具体 UI 框架在工程建立时锁定；可复用现有组件规范，不要求业务页面迁入 IAM。

## 2. 页面流程

业务前端未登录时导航到本应用后端 /auth/login，由后端创建登录事务并进入 IAM 授权流程。IAM 授权端点根据事务展示 iam-web，不允许直接登录页绕过客户端校验。

登录页展示经服务端注册的应用名称/图标，支持账号密码及启用的第三方方式。已有 IAM 会话仍检查目标应用准入与所需认证强度。

回调在后端处理。成功返回经过允许列表验证的原业务路径；无业务资格显示申请或联系管理员入口，不反复跳转登录。过期、取消、网络错误提供重试并创建新事务。

## 3. 账户中心

基础资料、安全、密码、身份绑定、MFA、设备和会话分区。业务昵称/头像若由业务维护，应清楚区分，禁止双向自动覆盖。

解绑前检查剩余可用登录方式，避免锁死账号。修改凭证与撤销会话要求必要的再认证。

## 4. 业务管理端改造

现有账号密码表单改为统一登录入口；管理员密码修改进入 IAM 账户中心；业务管理员分配、权限和菜单继续由业务后台提供。

Web 目标采用后端会话与 HttpOnly Cookie；/auth/me 返回本地登录状态与身份摘要，角色菜单走原业务接口。迁移期 Bearer 客户端单独版本化，不混用同一隐式凭证来源。

## 5. 退出和安全展示

明确区分“退出当前应用”“退出所有关联应用”“撤销其他设备”。全局退出尚在传播或失败时显示处理中/部分失败，不虚报所有应用已退出。

不得在 URL、本地存储、错误提示、监控日志或页面中暴露密码、授权码、刷新凭证。支持键盘、错误聚焦、移动端和多标签登录；并发事务不得互相覆盖。
