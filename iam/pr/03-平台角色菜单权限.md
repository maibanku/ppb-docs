# 平台角色、菜单与按钮

> v0.4。平台普通授权只有一条权威路径。

## 1. 表关系

platform_admins → platform_admin_roles → platform_roles → platform_role_menus → platform_menus → platform_menu_permissions → platform_permissions。

管理员可有多个角色，取有效角色的授权并集。平台角色限定application_id；IAM角色属于iam域，运营角色属于base/chat/camera/wardrobe。聊天组织角色仍由server-im管理。

## 2. 菜单树

platform_menus.node_type：1目录、2页面、3按钮、4隐藏操作。surface_key区分后台入口；父子同应用同入口，跨域统一后台按应用组合树。首期不建placements，同一页面如需出现在不同入口，可注册不同menu_key/route_key映射；复杂复用以后再拆。

工程注册基础菜单、路由和权限目录；平台后台维护展示、角色勾选及受保护的映射。route_key只允许注册路由，不能填写任意组件、脚本或外部跳转。权限目录及菜单映射编辑受提权保护，不能绕过授权范围。

## 3. 勾选与生效

- 给角色勾选页面和按钮，保存platform_role_menus；不为每个人复制授权。
- platform_menu_permissions表示“勾选该节点授予哪些后端权限”，不再表示菜单可见条件。
- 勾选页面不自动获得所有按钮；新按钮不自动授予既有角色。
- 按钮必须有对应有效页面，保存时补齐或拒绝缺失依赖。目录祖先只补展示，不自动授权。
- menu_status停用/删除阻断节点及子树；is_hidden只隐藏导航，不撤销权限。
- 有权限仍须通过管理会话、应用准入和业务资源检查。跨组织资源需业务额外授权。

## 4. 缓存和批量变更

角色菜单变化递增role_version及应用authz_version；菜单权限映射变化递增应用版本；个人角色分配变化递增管理员authz_version。所有相关管理员使用新快照，不逐人更新菜单行。发布可靠失效事件、更新前端菜单，高权限过期/不可用快照拒绝。

is_super通过单独治理分支校验；最后有效超管不可被普通操作移除。不是用户资料字段，管理编辑必须专门鉴权、再认证并审计。
