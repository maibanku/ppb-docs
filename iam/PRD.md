# PPB IAM · 需求基线

> v0.1 · 2026-10-27 · 待实施设计。

## 1. 目标与形态

建设可服务多个 Go 或非 Go 应用的统一身份认证中心，统一账号安全、认证、单点登录与应用接入。产品名 PPB IAM，当前工程形态为 ppb-base 内的 server-iam。认证门户与业务前端独立。

MaxKey 仅作产品形态参考。本方案不依赖其运行时，不复制其代码或承诺首期覆盖全部功能。

## 2. 职责边界

| 能力 | 权威模块 |
|---|---|
| 全局账号、登录标识、密码、验证码、MFA、第三方身份 | server-iam |
| 应用注册、客户端、认证协议、认证会话、认证审计 | server-iam |
| 用户/组的应用访问资格 | server-iam |
| 本地用户资料、业务组织和成员资格 | server-user 或对应业务服务 |
| 管理员资格、超级管理员、base/chat/camera 分域 RBAC | server-user |
| 菜单、API、数据范围、会员、额度和内容归属 | 业务系统 |
| 业务凭证校验、可信身份注入和路由准入 | server-gateway |

IAM 认证组织与业务工作空间不得默认一一对应。IAM 全局停用阻止所有关联应用访问；业务组织停用只影响对应业务范围。应用访问资格不等于业务权限。

## 3. 原则

- 保留已有业务 user_id 和 biz_key，迁移身份不改变消息、文件及订单归属。
- 登录成功后仍校验账号状态、应用资格、业务成员或管理员资格。
- IAM 管理员与业务超级管理员分别授权；外部角色不自动提升为超级管理员。
- 认证中心与业务服务独立数据库，通过协议/API 协作，禁止跨库读写。
- 认证失败、权限失败和系统不可用分开处理，不通过回退旧密码绕过认证策略。
- 设计目标与测试结果分开记录。

## 4. 功能范围

| 编号 | 需求 | 阶段 |
|---|---|---|
| IAM-01 | 全局用户、登录身份、凭证及安全状态 | P1 |
| IAM-02 | 登录、验证码、找回密码与账号绑定 | P1 |
| IAM-03 | 应用/客户端注册、OIDC 授权码与 PKCE | P1 |
| IAM-04 | 管理端试点接入及身份与业务资格隔离 | P2 |
| IAM-05 | 认证门户、账户中心、独立认证后台 | 门户 P1；账户中心/后台 P2 |
| IAM-06 | 可撤销会话、刷新轮换、退出及禁用联动 | 基础 P1；跨应用联动 P2 |
| IAM-07 | 旧账号身份映射与分批迁移 | P2–P3 |
| IAM-08 | 第三方身份、多应用推广 | P3 |
| IAM-09 | MFA 与高权限认证策略 | P2，高权限生产开放前完成 |
| IAM-10 | 目录同步、SCIM/SAML 等扩展 | 后续，另立契约 |

P1 即使开放自助注册，也只创建 IAM 账号，不自动授予受限应用或业务管理员资格。具体应用可关闭注册或要求邀请。

## 5. 非首期范围

集中替换业务 RBAC、完整企业目录同步、全部 SSO 协议、通用策略引擎、把 IAM 再拆成微服务。业务匿名主体和相机游客额度仍由业务服务维护。

## 6. 阶段出口

P0 固定协议、租户/主体策略、依赖版本、会话时限与撤权目标；P1 完成认证闭环；P2 用管理端试点并验证安全和迁移；P3 接入成员端及其他应用。

每阶段按 [验收门槛](ac/00-验收总则与发布门槛.md) 留证，不以文档或页面存在证明功能完成。
