## 任务

### 1. 独立入口的入口键

`src/main.ts` 里独立部署入口写的是 `surfaceKey: 'mail'`。IAM 没有这个入口，拿它去取 `/manage/context` 会被拒。改成 `platform`，注释同步改。页面测试里有一条断言锁住它。

### 2. 投递日志导出改成带凭据的请求

现在 `deliveryLogsExportUrl` 给出一个地址，页面直接打开它。改成：

- iam 模式：`fetch('/iam/api/v1/business/manage/mail/logs/delivery/export?<筛选参数>', { credentials: 'include' })`，拿到的是字节流。先看响应头：`Content-Type` 是 JSON 说明对方回的是信封（出错、超限、没权限），读出来把 `message` 显示给用户；是 CSV 才存文件。
- legacy 模式：请求头里带管理凭据，取法照底座 http 客户端的写法（看 `ppb-base/base-manage-web/src/api/http.ts`，只读）。
- 文件名取 `Content-Disposition` 里的，取不到用「投递日志-<起>-<止>.csv」。
- 筛选参数和列表一致，顺序固定，分页和排序参数不带（照 `contracts-mail/api/streaming-routes.md` 里这一条的说明）。时间范围最长 90 天、最多 10 万行这类限制在页面上提示。
- 失败（401、403、429、503、网络错误）各有清楚的提示，不留半截文件。
- 用 mock 的 `fetch` 测：成功的流存成文件、JSON 信封显示原因、403 的提示、文件名的两种来源。

### 3. 开通邮箱的选人框

邮箱页「开通邮箱」现在只能手填用户标识。加一个选人框：

- 输入关键字（防抖 300 毫秒）后请求 IAM 的用户列表（上面那个接口），只列状态正常的；每行显示「昵称(登录邮箱)」，没有登录邮箱的显示「昵称（标识 <用户标识>）」；身份的写法沿用平台的约定「昵称(邮箱地址)」。
- 选中后把用户标识填进表单；也保留「手动填写用户标识」的入口（直接贴标识）。
- 线上字段名照 IAM 自己的管理页解析这份响应的写法来（`/Users/pipi-ban/Desktop/code/vscode/ppb-iam/iam-manage-web/src/api/` 里和用户列表有关的文件，只读，别猜字段名）。请求用底座的 http 客户端还是自己发，看它的拦截器对「路径以 `/iam/api/v1/manage` 开头、不走业务桥改写」的请求怎么处理；改写会把它带错的，就绕开改写，并写清楚原因。
- 没有结果、请求失败、用户没有权限时各有提示，并且还能退回手填。
- 测试：关键字防抖、只列状态正常的、选中后表单里的值、失败时的提示。
