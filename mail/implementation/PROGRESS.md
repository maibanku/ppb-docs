## 7. 自己做的判断

设计阶段做的一些取舍，列出来供评审时检查。每条写了判断错了的后果。

| 编号 | 判断 | 理由 | 错了的后果 |
|---|---|---|---|
| J1 | 邮件标识用带签名的不透明字符串，不建映射表 | 无状态；和标准客户端是同一份数据 | 文件夹重建后标识失效，客户端要重新拉列表 |
| J2 | 业务数据物理删除，不用软删 | 删除后地址和域名要能重新分配 | 丢失“曾经有过什么”的记录。审计表里还有 |
| J3 | 日志靠读文件采集，断点存数据库 | 链路短，出问题好查；断点丢了可以从头重读，靠去重兜底 | Postfix 或 Dovecot 改了日志格式时要跟着改解析 |
| J4 | 用户脚本放在独立的数据卷，不放邮件目录里 | 控制面对邮件目录只有只读挂载 | 多一个数据卷要备份 |
| J5 | 容量预警由控制面每天检查，不用 Dovecot 自带的预警脚本 | 要做“7 天内只提醒一次”，要统一通知邮件的写法 | 预警最多晚一天 |
| J6 | 一封邮件只按第一条命中的过滤规则处理 | 确定性，好理解 | 想让一封邮件同时命中多条规则的用户做不到 |
| J7 | 过滤规则里的转发地址不需要验证 | 规则是登录后设置的，等同于用户自己转发 | 登录态被盗后可以被用来外传邮件。但那时直接读邮件也一样能外传 |
| J8 | 附件合计上限是 35 MB，不是规则里原来写的 50 MB | 附件编码后膨胀约三分之一，整封邮件要落在 50 MB 以内 | 通过 HTTP 接口发不了接近 50 MB 的附件。用标准客户端不受这个限制 |
| J9 | 主机名和公网地址是部署配置，线上页面不能改 | 改主机名要同时换证书、改 DNS，是部署层面的事 | 需要一个带外通知的步骤：页面提示需要同步修改 DNS |
| J10 | 控制面自己发出的通知邮件，信封发件人为空 | 避免退信和自动回复堆积 | 这些邮件的送达失败没有人知道 |
| J11 | 认证日志靠 Postfix 和 Dovecot 两侧的日志拼出来 | SMTP 认证由 Dovecot 执行、由 Postfix 记录 | 两侧日志行格式要等 M2 核对 |
| J12 | 备份目的地必须在服务器之外 | 全量恢复要求换一台服务器也能恢复 | 需要一个对象存储或另一台机器 |
