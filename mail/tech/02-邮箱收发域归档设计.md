## 2. 服务形态

- 独立的 mail 服务，内部 RPC 端口 9103，HTTP 健康检查端口 9113。
- 独立数据库 ppb_mail。
- 经网关对外提供成员侧 9 组和管理侧 4 组 HTTP 接口。
- 附件字节由文件服务保管，邮件域只存引用。

## 4. 数据模型

| 表 | 作用 | 关键列 |
|---|---|---|
| mail | 邮件副本，每个用户每个方向一行 | user_id、mail_direction、folder_type、thread_id、deliver_status、unread_flag、purge_time |
| mail_recipient | 收件人及逐人投递结果 | mail_id、rcpt_addr、rcpt_type、deliver_status、bounce_reason、member_id |
| mail_attachment | 附件引用 | mail_id、file_id、file_name、file_size |
| domain_config | 企业域名，全局单行 | domain_name、check_status、missing_checks |
| quota_stat | 邮箱容量水位，每用户一行 | user_id、used_bytes、warned_flag |
| user_mailbox（在 ppb_user 库） | 邮箱账号 | user_id、mailbox_addr、outbound_perm、mailbox_status |

枚举：

| 字段 | 取值 |
|---|---|
| mail.mail_direction | 1 收，2 发，3 系统 |
| mail.folder_type | 1 收件箱，2 已发送，3 草稿箱，4 已删除，5 已清理 |
| mail.deliver_status | 0 草稿，1 发送中，2 投递中，3 已送达，4 已退信，5 发送失败，6 已撤回 |
| mail_recipient.rcpt_type | 1 收件人，2 抄送，3 密送 |
| mail_recipient.deliver_status | 0 待投，1 成功，2 退回 |
| user_mailbox.mailbox_status | 1 正常，2 已停用，3 已删除 |

## 5. 跨域依赖

| 方向 | 调用 | 目的 |
|---|---|---|
| mail → user | ResolveMailboxes、GetOutboundPermissions | 发信前校验外发权限 |
| mail → user | RecalcMailboxAddrs | 域名变更后重算邮箱地址 |
| 网关 → mail | GetMailboxQuota | 登录和个人信息里附带容量 |
| 网关 → mail | ListPendingMailEvents | 事件拉取兜底 |
| file → mail | ParticipantOfMail | 附件下载的参与方裁决 |
| user → mail | 停用联动 | 停用成员时联动停箱 |
| mail → file | 引用登记 | 附件元数据与内容 |

## 6. 设计评价与设计债

合理之处：

- 每个收件人一份副本，权限天然隔离，删信和已读互不影响。
- 邮箱账号和外发权限归用户域，容量和投递归邮件域，边界清楚。
- 事件推送加拉取兜底，降低漏通知的概率。

重启前必须先解决的问题：

| 问题 | 说明 |
|---|---|
| 存储放大 | 正文按收件人整份复制，收件人上限 200 时一封邮件有 200 份正文，配额也按副本计。更合理的做法是正文单存，每人只留元数据 |
| 没有幂等键 | 写邮件请求里没有客户端幂等标识，重试会重复投递 |
| 搜索方案 | 对正文大字段做模糊匹配，没有全文索引 |
| 跨服务一致性 | 发信涉及用户域校验、邮件落库、文件引用和配额扣减，契约里没有 saga 或本地消息表的安排 |

此外：

- 只能内网直投和经中继外发，没有接收外部来信的链路。
- 撤回只支持内网且限 10 分钟。
- 外发中继缺省未配置，此时外发按投递超时退信。
- 外部 HTML 正文需要净化，是持续的攻击面。
