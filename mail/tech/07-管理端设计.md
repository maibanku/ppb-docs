> v0.2 草案；目标态设计，未实施。规则来源：[管理端](../pr/06-管理端.md)。操作清单见 [接口契约](09-接口契约.md) 第 4 节。

## 1. 组成

管理端由三部分组成：

| 部分 | 位置 | 职责 |
|---|---|---|
| 管理页面 | mail-manage-web 插件 | 页面和交互 |
| 管理接口 | service-mail，路径前缀 /api/v1/manage/mail | 业务规则、权限复检、审计 |
| 辅助服务 | service-mail 内部 | 运维代理的客户端、策略服务、日志采集、状态采集、后台任务 |

管理接口经网关访问，网关做权限前判，控制面再复检一次。

管理面的处理代码和成员面的处理代码放在不同的包里。管理面的代码不能引用任何读写邮件内容的包，这是 FP-G18 在代码结构上的落实，见第 15 节。

## 2. 运维代理

### 2.1 为什么需要

查看和管理 Postfix 队列、读取 Dovecot 的配额、编译检查脚本、删除邮件目录，都要在邮件核心容器里执行命令。控制面不在那个容器里。让控制面挂载 Docker 套接字去别的容器里执行命令风险太大，所以加一个只做白名单操作的代理。

### 2.2 形态

- 一个小型的静态可执行程序，放在邮件核心镜像里，随容器启动。
- 监听一个 Unix 套接字，套接字文件放在两个容器共享的目录里，权限只允许控制面的用户组连接。
- 每次连接处理一个请求，内容是 JSON，返回 JSON。
- 代理以容器内的 root 身份运行，这是队列命令的需要。和邮件存储有关的操作切换到虚拟用户身份执行。

### 2.3 白名单命令

| 命令 | 参数 | 执行的操作 | 调用方 |
|---|---|---|---|
| queue.list | 队列类型 | 列出队列 | 队列页、状态采集 |
| queue.flush | 无 | 立即重发全部 | 队列页 |
| queue.requeue | 队列标识列表 | 把选中的邮件重新入队 | 队列页 |
| queue.hold | 队列标识列表 | 改为暂缓 | 队列页 |
| queue.release | 队列标识列表 | 释放暂缓 | 队列页 |
| queue.delete | 队列标识列表 | 删除 | 队列页 |
| quota.get | 邮箱地址 | 读取配额用量 | 邮箱详情页 |
| sieve.compile | 脚本文件路径 | 编译检查脚本 | 成员接口保存设置时 |
| mailbox.delete | 邮箱地址 | 删除该邮箱的邮件目录和脚本目录 | 邮箱彻底删除时 |
| reload.postfix | 无 | 重新加载 Postfix 配置 | 设置变更、证书续期 |
| reload.dovecot | 无 | 重新加载 Dovecot 配置 | 同上 |
| status | 无 | 返回两个进程是否在运行 | 状态采集 |

表里没有的命令一律拒绝。以后要加命令，先改这张表，再改代理的白名单。

### 2.4 安全约束

- 队列标识只接受大写字母和数字，长度 8 到 16，批量上限 1000 个。
- 邮箱地址由控制面校验后传入；代理再校验一次格式，并且要求这个地址的邮件目录确实位于约定的根目录之下。
- 脚本路径必须是 Sieve 目录内的绝对路径，解析后不能逃出这个目录。
- 命令直接执行，不经过 shell，不拼接字符串。参数逐个传入。
- 每次调用记一行日志：命令、参数摘要、结果。
- 单次请求有超时，默认 30 秒。队列列表数据量大时可以调长。

## 3. 出站限额策略服务

### 3.1 协议

Postfix 支持一种简单的文本协议，用来在投递的各个阶段向外部服务提问。每个收件人发来一批属性行，每行是“名称=值”，以空行结束；服务端回复“action=动作”，同样以空行结束。控制面在私有网络监听这个协议。

用到的属性：

| 属性 | 含义 | 用途 |
|---|---|---|
| protocol_state | 当前阶段 | 只在 RCPT 阶段处理，其他阶段直接放行 |
| sasl_username | 认证账号 | 空表示不是认证用户提交的 |
| sender | 信封发件人 | 写日志 |
| recipient | 当前这个收件人 | 写日志 |

回复的动作：

| 情况 | 回复 | 客户端看到的 |
|---|---|---|
| 没有认证账号 | action=DUNNO | 交给后面的规则处理 |
| 账号不存在，或外发权限关闭 | action=REJECT 外发权限已关闭 | 554，被拒绝 |
| 没有超限 | action=DUNNO | 正常投递 |
| 超出限额 | action=DEFER_IF_PERMIT 出站额度已用完，请稍后再试 | 451，稍后重试 |

回复的提示语用中文。

### 3.2 处理流程

1. 读取属性。读取有超时，非法的请求直接断开。
2. 阶段不是 RCPT，或者没有认证账号：放行。这一类请求来自入站或内部提交端口。
3. 用认证账号查内存里缓存的账号权限。缓存有效期 30 秒。查不到缓存时查数据库。账号不存在、不是正常状态、外发权限关闭：拒绝。
4. 取这个账号的限额：有覆盖值用覆盖值，没有用全局默认值。
5. 查小时计数和天计数。都没超限就把两个计数各加一，回答放行；有超出的回答稍后重试，不计数。
6. 记一行服务日志。

### 3.3 计数器

- 计数器放在控制面的内存里，按账号维护两个小时窗口和两个天窗口的计数。窗口边界是固定的整点和零点。
- 控制面重启后计数清零。这是已接受的偏差：重启后短时间内可能多发。
- 通过 HTTP 接口发送的邮件也计入同一组计数器，由控制面在提交前检查并累加。计数单位都是收件人数。
- 限额默认值和覆盖值的修改即时生效，下一次判定就用新值。

### 3.4 不可用时

Postfix 在策略服务不可达或超时时按放行处理，超时时间 10 秒。限额是防护措施，不能让它拖垮全员发信。不可达时控制面告警，见 [部署与运维](10-部署与运维.md) 11.2。

## 5. 日志采集

### 5.1 Postfix 和 Dovecot 的日志

```
Postfix 日志文件 ─┐
                  ├─► 控制面采集器 ─► 解析 ─► 入库
Dovecot 日志文件 ─┘
        ▲
   轮转的旧文件也保留，采集器追上后才清理
```

| 项 | 设计 |
|---|---|
| 读取方式 | 监听文件变化，增量读取 |
| 断点 | 每个日志源在 checkpoint 表里记一行：当前文件的标识、已读到的字节偏移、偏移处上一行的摘要。采集器重启后先核对位置，对得上就接着读 |
| 位置对不上时 | 从最早的还在保留的文件的开头重读。重复的行会被去重键挡住 |
| 轮转 | 按改名的方式轮转，不用清空再写的方式。旧文件至少保留到采集器读完 |
| 去重 | 每行算一个摘要作为唯一键。摘要由四部分算出：日志源、文件标识、文件内偏移、行内容。同一个位置重读得到同一个摘要，所以重读不会重复入库；不同位置的相同文字是两条记录 |
| 解析不了的行 | 跳过并计数，数量异常时告警 |

断点的文件标识取文件首行的摘要。文件轮转或重建后，新文件的首行不同，标识就不同。

**Postfix 日志里要认得的行。** 同一封邮件的多行日志靠队列标识归并：

| 日志行 | 提取的内容 |
|---|---|
| 客户端和认证信息行 | 队列标识、客户端地址、认证账号 |
| 邮件进入队列的行 | 队列标识、发件人、大小、收件人数 |
| 写入邮件头的行 | 队列标识、邮件追踪号。这是队列标识和追踪号之间的对应关系 |
| 逐个收件人的投递结果行 | 队列标识、收件人、投递状态、状态码、原因、耗时、是否加密 |
| 在连接阶段就被拒绝的行 | 没有队列标识。发件人、收件人、拒绝原因、客户端地址 |

方向的判定：有认证账号，或者客户端是内部提交端口，算出站；其余算入站。

状态的映射：投递成功对应“已投递”；临时失败对应“重试中”；永久失败对应“已退信”；收件方或本系统拒绝对应“被拒收”；因垃圾评分或病毒被拒对应“因垃圾或病毒被拒收”。退信邮件本身也产生一条投递记录，方向是出站，收件人是原发件人（见 [投递与反垃圾](05-投递与反垃圾.md) 第 6 节）。

**Dovecot 日志里要认得的行。**

| 日志行 | 提取的内容 |
|---|---|
| 登录成功 | 账号、协议、客户端地址 |
| 登录失败 | 账号（可能没有）、协议、客户端地址、原因 |
| 主账号的登录 | 识别出来后跳过，不入库 |

**登录成功的回写。** 采集器每入库一批登录成功的记录，就把其中每个账号的最近登录时间和地址更新到账号表。控制面自己用主账号做的访问不算。

### 5.2 评分记录

控制面每分钟读一次 Rspamd 的历史记录，把新增的入库：时间、发件人、收件人、评分、处置、命中的主要规则、邮件追踪号。按历史记录自带的标识去重。

Rspamd 的历史记录默认只保留很少的条数。要把上限调大，保证两次读取之间的记录不会挤掉。入站邮件在验收里有峰值，按每分钟 1000 条的余量配置。

### 5.3 表与保留期

| 表 | 内容 | 保留期 |
|---|---|---|
| 投递日志表 | 每个收件人的每次投递尝试 | 180 天 |
| 登录日志表 | 每次登录尝试 | 180 天 |
| 评分记录表 | 每封入站邮件的评分 | 30 天 |

清理在每日维护里做，按时间分批删除。

## 6. 队列管理

队列列表、重发、暂缓、释放、删除都通过运维代理执行。

- 队列列表用 Postfix 的 JSON 格式输出，字段稳定，便于解析。
- 入站方向的队列项只读：控制面拒绝针对入站队列项的重发和删除请求。判断依据是请求里的队列标识是否属于出站集合。M4 时核对 JSON 输出里区分方向的方式；如果无法区分，改为只允许操作“发件人是本系统账号”的队列项。
- 所有队列操作记审计。批量操作的审计只记一条，对象是队列标识列表的摘要和数量。

## 7. 系统状态

| 指标 | 取法 |
|---|---|
| Postfix、Dovecot 是否存活 | 运维代理的 status 命令，加一次协议握手 |
| Rspamd、Redis、数据库 | 各自的探活接口或连接测试 |
| 三类队列长度 | 运维代理的队列列表，按类型计数 |
| 邮件存储磁盘用量 | 控制面以只读方式挂载邮件存储目录，统计文件系统用量 |
| 数据库用量 | 查询数据库的统计信息 |
| 证书剩余天数 | 读取证书文件 |
| DNS 校验汇总 | 读域名表的最近一次校验结果 |

控制面每 30 秒采集一次并缓存，页面和指标接口读缓存。采集失败时保留上一次的结果，并把这一项标成未知。

## 8. 账号操作

### 8.1 开通

1. 校验操作者有 mail.account.manage。
2. 向 IAM 确认用户存在且状态正常（M01-1）。
3. 这个用户已经有邮箱时，返回已有的账号，不做任何改动（M01-4）。
4. 域没指定就用默认域。校验域的状态正常。
5. 按地址分配的加锁流程校验账号名，见 [数据模型](08-数据模型.md) 9.1。
6. 写入账号记录，状态为正常。密码：管理员填了就用它；没填就生成 12 位以上的随机临时密码，设置 7 天后的过期时间。
7. 用主账号经 IMAP 登录一次这个新邮箱。Dovecot 在第一次登录时创建邮件目录和标准文件夹。
8. 写审计。

第 7 步失败不影响开通的结果：Dovecot 会在第一次投递时再创建。但要在服务日志里记一条告警。

### 8.2 状态操作

停用、恢复、删除、彻底删除都是先改账号表上的输入，再由推导函数得到状态，见 [数据模型](08-数据模型.md) 5.3。两个额外的检查：

- 恢复时，对应的 IAM 用户必须是正常状态，否则拒绝（M09-5）。
- 立即彻底删除要求请求里显式带上确认标记（M10-2）。彻底删除的步骤见 [数据模型](08-数据模型.md) 9.4。

已经用标准客户端登录的会话不会因为邮箱被停用而立刻断开，要到下次登录才被拒。这是 Dovecot 的行为，记在 [账号与认证](04-账号与认证.md) 6.3。

### 8.3 批量任务

1. 创建任务时解析对象清单：来自勾选的标识列表，或者把筛选条件解析成标识列表。最多 500 个（G04-2）。
2. 写任务记录，状态为运行中，立即返回任务标识。
3. 后台逐个对象执行动作。每成功或失败一个，就更新任务的计数；每 10 个对象或每 2 秒把进度写回数据库一次。
4. 每个对象的操作单独记审计，操作者是发起任务的管理员。
5. 全部做完后把任务标为成功、部分失败或全部失败。

控制面重启后，遗留的运行中任务在每日维护里标为中断。页面看到中断后由管理员决定是否重新发起。

### 8.4 按组织开通

选择一个或多个组织，为其中还没有邮箱的成员开通。这是批量任务的一种：

- 对象清单来自 IM 的成员列表。
- 账号名用成员的用户编码。取不到时用用户标识的十进制串。
- 这些邮箱没有密码。成员要设置初始密码之后才能用标准客户端登录（M04-8）。在成员界面上线之前，管理员可以用重置密码给它们生成临时密码。

### 8.5 对账

手动触发对账就是立即跑一次对账任务。对账的逻辑见 [账号与认证](04-账号与认证.md) 2.3。页面上显示最近几次对账的时间和各项数量。

### 8.6 容量预警

每日维护里执行。查用量表，找出用量达到配额 90% 的邮箱，再排除两种：7 天内提醒过的；状态不是正常的。给剩下的每个邮箱发一封提醒，并更新它的提醒时间。提醒邮件的做法见 [成员接口设计](06-成员接口设计.md) 6.7。

不用 Dovecot 自带的预警脚本，原因有两个：它不能做“7 天内只提醒一次”，也不能统一管理系统通知邮件的写法。

## 9. 域名与 DKIM

### 9.1 添加域

1. 校验域名格式和唯一性。
2. 生成 DKIM 私钥，RSA 2048 位，写入密钥目录。文件名包含域名和选择器。
3. 选择器的命名是字母 s 加年月，例如 s202611。同一个月里轮换多次时在后面追加序号，保证域内不重复。
4. 由私钥算出 DNS TXT 记录值并存库。
5. 保存域名记录。这是第一个域时，把它设为默认域。
6. 为这个域插入两条保留地址记录，指向添加域时填写的邮箱。
7. 写审计。
8. 立即执行一次 DNS 校验。校验是异步的，不等它返回。

第 2 步和第 5 步之间有一个文件操作不在事务里。规定顺序是先写文件再写数据库：数据库写入失败时留下一个没有记录的私钥文件，不影响运行，由每日维护清理孤立的私钥文件。反过来做的话，数据库里会有一个找不到私钥的域，签名会失败。

### 9.2 主机名登记

对外主机名和公网地址来自部署配置。控制面每次启动时把它们写进登记表。值和以前不同时，重新执行一次全局检查，并在 GetEndpoint 的响应里把 changed 置为真，页面据此提示需要同步修改 DNS（D02-4）。

### 9.3 DKIM 密钥目录

- 每个域的每个选择器一个文件，放在密钥目录下按域名分的子目录里。
- 私钥文件权限只允许 Rspamd 的运行用户读取。
- 控制面渲染 Rspamd 的签名配置：每个域用哪个选择器、私钥在哪里。添加域、轮换、删除选择器之后都重新渲染并让 Rspamd 重载。
- 轮换：生成新选择器和新密钥，把新密钥标为当前签名用的，旧密钥保留（D04-3）。管理员确认新选择器的 DNS 记录生效之后再删除旧选择器。

### 9.4 DNS 校验

用 DNS 工具库直接向配置里的公共递归服务器查询，不走系统解析缓存。单项超时 10 秒，整轮不超过 60 秒（D03-5）。

| 检查项 | 查询 | 通过条件 |
|---|---|---|
| MX | 域的 MX 记录 | 至少有一条指向登记的主机名 |
| SPF | 域的 TXT 记录 | 至少有一条以 v=spf1 开头，并且含登记的 IP 或 mx 机制 |
| DKIM | 选择器._domainkey.域 的 TXT 记录 | 解析出的公钥与本地密钥一致。TXT 记录被拆成多段时先拼接 |
| DMARC | _dmarc.域 的 TXT 记录 | 至少有一条以 v=DMARC1 开头 |
| 主机名解析（全局） | 主机名的 A 或 AAAA 记录 | 至少有一条等于登记的 IP |
| 反向解析（全局） | IP 的 PTR 记录 | 至少有一条等于登记的主机名 |

结果的三种取值：通过、失败、未检测。查询超时或出错时是未检测。每项带一句不含敏感信息的说明，例如“找到的 MX 记录指向别的主机”。

## 10. 黑白名单的生效

| 名单 | 生效方式 |
|---|---|
| 黑名单 | 存数据库。Postfix 查黑名单视图，视图直接反映变更 |
| 白名单 | 存数据库。控制面把它渲染成 Rspamd 的映射文件，再通过控制接口让 Rspamd 重载 |

白名单变更后控制面立即渲染并重载；另外每分钟做一次对账，保证文件与数据库一致。渲染是先写临时文件再改名。

渲染成映射文件而不做成数据库查询，是因为 Rspamd 查映射文件时把它整份读进内存，重载一次的代价很小；让它逐封邮件去查数据库反而增加一个依赖。

## 12. 审计

- 审计记录存在本地的审计表里。
- 能和业务写入放在同一个数据库事务里的，放在一起。
- 不能的，先写审计再执行操作；审计写入失败则操作失败。
- 审计内容不含秘密：重置密码的审计只记“已重置”，不记临时密码；改设置时，值里不含任何口令。
- 审计只追加，不修改，不删除。到期后由每日维护清理。

动作码用“对象.动作”的形式：

| 对象 | 动作码 |
|---|---|
| 域 | domain.create、domain.set_status、domain.set_default、domain.delete、domain.rotate_dkim、domain.delete_dkim、domain.set_system_alias |
| 邮箱 | account.create、account.update、account.reset_password、account.suspend、account.resume、account.delete、account.purge、account.provision_by_org、account.sync |
| 批量 | batch.create |
| 别名 | alias.create、alias.delete |
| 转发 | forward.create、forward.update、forward.delete |
| 名单 | blocklist.add、blocklist.delete |
| 限额 | policy.set_default、policy.set_override、policy.delete_override |
| 队列 | queue.flush、queue.requeue、queue.hold、queue.release、queue.delete |
| 设置 | settings.update |

用户自助的写操作也记审计，操作者类型标为用户：修改主地址（M07-4）、添加和删除别名、设置和删除转发、修改密码和设置初始密码。自动回复和过滤规则不记，它们改动频繁，也没有追溯价值。操作失败时同样记一条，结果标为失败。

### 13.2 工程约定

- 基于 base-manage-web 底座，列表用底座的表格组件。工程的目录和构建方式照 file-manage-web。
- 本地开发端口 8274（8270 已被衣橱的后端占用）。

## 14. 权限接入

1. 权限点登记在 IAM。M4 时核对 IAM 里应用和权限点的登记方式，是初始化数据还是管理接口。
2. 菜单在 IAM 登记，并挂上对应的权限点。
3. 网关按路由策略做权限前判，策略写在契约 JSON 里，见 [接口契约](09-接口契约.md) 第 4 节。
4. 控制面收到请求后向 IAM 复检操作者的管理权限，做法参照其他服务对 IAM 授权接口的包装。控制面要认两种来源：带管理登录态的直接请求，和业务桥转来的带签名断言头的请求，做法照 service-file。

## 15. 隐私边界

FP-G18 规定管理员不能查看成员的邮件内容。在代码结构上落实成两条：

- 访问邮箱内容的能力只放在一个包里，包名带 mailbox 字样。只有成员面的处理代码引用它。
- 有一个依赖方向测试：用 go list 取管理面处理代码所在包的全部传递依赖，断言其中没有这个包。测试失败意味着有人从管理接口接通了读邮件的路径。

除此之外的两条硬规定：日志表里不存主题和正文；管理接口的任何响应结构里没有正文类的字段。
