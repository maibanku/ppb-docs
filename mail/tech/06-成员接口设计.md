# 成员接口设计

> v0.2 草案；目标态设计，未实施。规则来源：[成员接口](../pr/05-成员接口.md)。操作清单、字段和错误码见 [接口契约](09-接口契约.md)。

[需求基线](../PRD.md) · [域导航](../README.md)

## 1. 总体思路

控制面不保存邮件，也不实现邮件协议。它扮演两个角色：

- **IMAP 客户端**：用主账号登录 Dovecot，代替用户读写邮箱。
- **邮件提交者**：组装好邮件后，通过内部可信提交端口交给 Postfix 发出。

邮件只有一份，存在 Dovecot 的邮件目录里。标准客户端和 HTTP 接口看到的是同一份数据，这是规则 A00-3 的保证。

## 2. 身份映射

1. 网关校验成员登录态，把请求转给控制面，并在请求里带上操作者字段，值是成员标识。
2. 控制面按平台的服务认证组件再校验一次登录态。
3. 把成员标识换成用户标识。成员标识是组织内的成员编号，邮箱账号对应的是 IAM 用户编号，两者不是同一个量。做法是调 IM 的 `ResolveMemberIds`（入参是成员标识的十进制串，应答里用户标识为 0 表示没命中）。**不能用 `ResolveMembersByIds`**：它的入参虽然叫 memberIds，真实的实现按用户标识查，拿成员标识去查要么全部未命中，要么撞上另一个用户。显示名在拿到用户标识之后再用 `ResolveMembersByIds` 按用户标识取。结果放进进程内缓存，有效期 5 分钟。这一步失败返回 503，不放行。
4. 用用户标识查本地数据库，得到邮箱账号。查不到，或邮箱不是正常状态，返回 403 和 MAIL-2001。
5. 之后所有操作都限定在这个邮箱上。

同一个用户在多个组织里各有一个成员标识，但只有一个邮箱，所以不论用哪个组织的登录态进来，看到的都是同一个邮箱。

## 3. 邮件标识

### 3.1 格式

邮件、文件夹、附件的标识都是带签名的不透明字符串，格式见 [接口契约](09-接口契约.md) 3.1。三个要点：

- 服务端用密钥对内容做签名，客户端不能伪造。
- 内容里带邮箱账号的主键。解析时校验签名，再比对账号和当前用户的是否一致，防止拿到别人的标识来访问。
- 文件夹重建后有效性标识会变，旧标识随之失效。控制面检测到失效后返回 404，客户端应重新拉取列表。

### 3.2 文件夹名

对外用 UTF-8 的文件夹名，与 IMAP 内部的编码之间做转换。五个标准文件夹对外固定叫 INBOX、Sent、Drafts、Trash、Junk。用户建的子文件夹对外用“父文件夹名加斜杠加名字”表示层级，最多两层（A02-3）。

## 4. IMAP 访问

| 项 | 设计 |
|---|---|
| 连接 | 连 Dovecot 的隐式 TLS 端口，校验证书，证书上的主机名是配置里登记的对外主机名。即使在容器网络内部，主账号的口令也不明文传输 |
| 登录 | 主账号加真实用户名，主账号口令从密钥文件读取 |
| 并发 | 每个用户同一时刻最多 4 个 IMAP 连接，超出的请求排队 |
| 只读打开 | 读操作以只读方式打开文件夹，不会意外改动标记 |
| 读取正文 | 用不标已读的方式取正文 |
| 连接复用 | 同一请求内复用一个连接；不做跨请求的长连接池，实现简单且状态可靠 |
| 超时 | 建连 3 秒，单次操作 15 秒 |
| 访问日志 | 每次打开邮箱，在控制面的服务日志里记一行：接口名、邮箱地址、操作。不含邮件内容 |

**主账号的登录不进登录日志。** Dovecot 的日志里会有这些登录，用户每发一次 HTTP 读请求就是一次。采集器识别出主账号的登录后跳过，不写登录日志，也不更新账号表上的最近登录时间。登录日志只记用户用标准客户端的登录。

## 5. 读路径

### 5.1 列表

1. 打开文件夹。
2. 按筛选条件转成 IMAP 搜索条件：未读、星标、带附件、时间范围。
3. 对结果取标题、标记、时间、大小和正文开头。
4. 正文开头取前 2 KB，解码后截取前 100 个字符作为摘要。
5. 按时间倒序排列，截取请求的页。

总数在同一个连接里取。深翻页时 IMAP 要先取回全部匹配的编号，大邮箱会比较慢，这是已知的取舍。

### 5.2 搜索

关键字搜索在服务器端执行，转成 IMAP 的搜索条件：发件人、收件人、主题、正文、附件名。指定了文件夹就只搜这个文件夹，否则逐个文件夹搜索后合并，再按时间排序分页。草稿文件夹不参与搜索。

### 5.3 读邮件

1. 取整封邮件的原始内容。
2. 解析邮件结构：标题、正文各部分、附件各部分。
3. 正文转成 UTF-8。声明了字符集的按声明转；没声明的先按 UTF-8 试，失败再按常见中文字符集转。
4. HTML 正文经净化后返回，净化规则见第 9 节。
5. 不改动已读标记。
6. 密送地址按 A04-5 处理：原邮件的密送头里只保留本人那一个地址；本人发出的邮件全部保留。

### 5.4 附件与原邮件

- 附件按标识定位到邮件里的某一部分，以流式返回。
- 原邮件按标识取原始内容，直接返回。
- 响应头设置成强制下载，并禁止浏览器猜测类型。

### 5.5 会话视图

- 聚合范围是除草稿以外的全部文件夹，所以一个会话里的邮件可以分散在收件箱和已发送等不同文件夹（A17-2）。
- 优先用服务器的会话聚合命令（THREAD REFERENCES），Dovecot 支持，一次调用就能得到聚合结果。所选的 Go 客户端库如果不支持这个命令，就退回在内存里按引用关系头聚合。
- 为了控制耗时，每个文件夹只取最近 90 天或最近 1000 封邮件，取其中较小的一个。两个数值是可配置项。
- 会话标识取会话里最早那封邮件的标识。展开会话时按同样的范围重新聚合，找到包含这封邮件的会话。

### 5.6 缓存

文件夹的邮件总数和未读数每次都向 Dovecot 查，不做缓存，保证与标准客户端一致。概览接口只查计数，开销小。

概览接口还要返回本人的显示名和头像（A01-4）。这两项属于平台成员资料，控制面只是取来转发给界面，不保存。显示名同时用于发信时 From 的显示名，见 6.1。从哪个接口取，在 M3 核对后写在这里。

## 6. 写路径

### 6.1 组装邮件

| 部分 | 处理 |
|---|---|
| From | 用户指定的本人地址；显示名取用户资料里的名称 |
| To、Cc | 写入邮件头 |
| Bcc | 只出现在交给 Postfix 的信封里，不写入邮件头 |
| Subject | 原样使用，编码成标准形式 |
| Date、Message-ID | 服务端生成。Message-ID 的域名部分用邮箱所在的域 |
| 回复关联头 | 回复和全部回复时，根据原邮件写入 |
| 正文 | 纯文本和 HTML 组成二选一的多部分结构；只有纯文本时只放纯文本 |
| 附件 | 每个附件一个部分，文件名含非 ASCII 字符时按标准方式编码 |

### 6.2 发送

步骤固定，顺序不能换：

1. 取邮箱账号。查不到或不是正常状态，返回 403。
2. 取请求头里的幂等键，校验长度。查幂等记录：
   - 命中，且请求内容的摘要相同：直接返回第一次的响应，后面的步骤都不做。
   - 命中，但摘要不同：返回 409 和 MAIL-1014。
3. 外发权限关闭：返回 403 和 MAIL-2002。
4. 发件地址必须是本人的主地址或别名，否则返回 400 和 MAIL-1007。
5. 收件人逐个校验格式，再校验总数。
6. 附件标识逐个解析：必须属于本人、没有过期；校验个数和总大小。
7. 查出站限额，超限返回 429 和 MAIL-4290，不计数。
8. 组装邮件。
9. 通过内部提交端口交给 Postfix。信封发件人是 From 地址，收件人是收件人、抄送、密送的并集。同时把出站限额的计数加上收件人数。
10. 往已发送文件夹追加一份副本。
11. 写幂等记录。
12. 返回副本的邮件标识和 Message-ID。

三点说明：

- 第 2 步排在权限和限额之前。重试的请求应该拿到第一次的结果，哪怕两次请求之间权限或额度变了。
- 第 9 步失败时返回 503 和 MAIL-3002，不写幂等记录，也不计入限额。客户端用同一个幂等键重试。
- 第 10 步失败时照常返回成功，并告警。此时返回的邮件标识指向一个不存在的副本，投递状态查询会返回 404，这是已知的取舍。

同一个幂等键并发到达时，后到的请求等先到的做完，再按第 2 步返回同一个结果。控制面是单实例，用进程内按键的互斥实现。过期和清理见 6.6。

### 6.3 草稿

保存草稿就是往草稿文件夹追加一封带草稿标记的邮件。更新草稿是追加新的、删除旧的。列出、读取草稿与普通邮件相同，只是文件夹固定是草稿文件夹。从草稿发送成功后，这份草稿被删除（A07-4）。

### 6.4 标记与移动

用 IMAP 的标记、移动、复制命令实现。支持移动扩展的服务器用移动命令，否则用“复制、标删除、清除”三步。彻底删除只在已删除文件夹里执行。

批量操作逐封执行，单封失败不影响其余的，失败的标识和原因收集起来一起返回。

### 6.5 恢复时的原文件夹

通过 HTTP 接口把邮件移入已删除时，控制面把原文件夹记到 mail_trash_origin 表里，保留 30 天。恢复时查这张表，查不到就恢复到收件箱。用标准客户端删除的邮件没有这条记录，也恢复到收件箱。邮件离开已删除文件夹后，这条记录随之删除。

### 6.6 幂等

幂等记录存在数据库里，内容是：用户、幂等键、请求内容的摘要、第一次的响应。保留 24 小时，由每小时一次的清理任务删除过期的记录。

摘要的计算范围是请求体里影响结果的部分，去掉空白差异后的规范形式。同一用户、同一键、同一内容返回记录里的响应；内容不同返回 409。

### 6.7 控制面自己发出的通知

有三种邮件由控制面发起，不在用户的任何文件夹里留副本：

| 邮件 | 收件人 | 触发 |
|---|---|---|
| 转发地址确认信 | 用户填的转发地址 | 设置转发、重新发送确认信 |
| 初始密码设置成功的通知 | 用户在 IAM 的登录邮箱 | 用户设置了初始密码 |
| 容量预警 | 该邮箱本身 | 用量达到配额的 90%，7 天内最多一次 |

统一的做法：

- 经内部提交端口发出，同样经过滤接口做 DKIM 签名。
- 信封发件人为空，这样对方回信或自动回复产生的退信无处可去，不会堆积。
- 邮件头的 From 用默认域的 postmaster 地址，这个地址一定存在，因为它由域保留地址指向一个真实邮箱。
- 带 Auto-Submitted 头，内容是纯文本，不含链接以外的格式。
- 确认信里的链接是网关地址加上转发确认的匿名接口，令牌放在网址参数里。令牌 48 小时有效，只能用一次。

## 7. 暂存附件

| 项 | 设计 |
|---|---|
| 存储 | 控制面的数据目录，按用户分目录，文件名用随机标识 |
| 元数据 | 数据库表 mail_attachment_temp：所属用户、原文件名、类型、大小、存储路径、过期时间 |
| 校验 | 文件名、大小、数量、类型黑名单、用户的暂存总量 |
| 使用 | 发送或存草稿时，按标识读取文件并入邮件 |
| 清理 | 每小时清理过期记录和文件 |
| 归属 | 只能读到自己的暂存附件。标识带签名，见 [接口契约](09-接口契约.md) 3.1 |

文件名先去掉路径部分，再拒绝控制字符和改写后为空的名字。类型黑名单按扩展名判断，不信任客户端声明的类型。

## 8. 设置如何生效

三种用户设置落在不同的位置：

| 设置 | 落地位置 | 生效方式 |
|---|---|---|
| 自动回复 | 用户的 Sieve 脚本 | 投递时由 Dovecot 执行 |
| 过滤规则 | 用户的 Sieve 脚本 | 投递时由 Dovecot 执行 |
| 转发 | 数据库，别名视图能读到 | Postfix 解析地址时生效 |

### 8.1 Sieve 目录

- 用户脚本不放在邮件目录里，放在一个独立的数据卷 /var/mail-sieve，按域名和账号名分层。控制面对邮件目录只有只读挂载，写不了那里的文件；这个数据卷是给控制面写的。
- Dovecot 的脚本路径配置成指向这个目录。投递时的用户就是真实用户，所以路径里的用户变量是准确的。
- 目录和文件的属主是邮件存储的虚拟用户。控制面的容器以同一个系统用户运行。

### 8.2 写入流程

控制面把一个用户的过滤规则和自动回复合并渲染成一份脚本。顺序是先过滤规则，后自动回复。

1. 渲染脚本内容。
2. 先写入同目录下的临时文件，再改名覆盖原文件。改名是原子的，Dovecot 不会读到写了一半的脚本。
3. 经运维代理调用 Dovecot 自带的脚本编译工具做编译检查。
4. 编译失败时把原文件内容写回去，接口返回 400 和 MAIL-1012。原有设置保持有效（A15-3）。

编译检查必须在脚本落盘之后做，因为编译工具读的是文件。所以第 4 步要有回滚。渲染、落盘、回滚三步放在一个函数里，配测试。

### 8.3 脚本的生成规则

全局脚本写在镜像里，内容是：邮件头标记为垃圾的，放进垃圾邮件文件夹。

用户脚本由规则渲染而来：

| 规则里的条件或动作 | 脚本里的写法 |
|---|---|
| 发件人包含某串 | 对 From 头做包含判断 |
| 收件人包含某串 | 对 To 头和 Cc 头做包含判断，任一命中即可 |
| 主题包含某串 | 对 Subject 头做包含判断 |
| 邮件大小超过 N 字节 | 大小判断，超过 N |
| 多个条件 | 用“全部满足”包起来 |
| 移动到文件夹 | 投递到该文件夹 |
| 标星 | 加星标标记 |
| 标为已读 | 加已读标记 |
| 转发到地址 | 重定向到该地址 |
| 删除 | 投递到已删除文件夹 |

- 一封邮件只按第一条命中的规则处理。每条规则后面跟一个停止语句。
- 保存规则时就校验目标文件夹存在，不存在返回 400。
- 要匹配的字符串按 Sieve 的字符串字面量规则转义：反斜杠和双引号各加一个反斜杠，换行替换成空格。有一个专门的转义函数，配一组用例。
- 自动回复渲染成休假命令。同一发件人多长时间内只回一次，由命令自带的参数控制，这里取 7 天（S16-3）。命令本身不会回复自动生成的邮件、群发邮件、退信和空信封的邮件（S16-4）。
- 自动回复的开始和结束时间不由脚本表达。控制面每分钟检查一次：到了开始时间，把休假命令写进脚本；到了结束时间，把它移除。

### 8.4 转发

- 转发记录带“是否已验证”。只有已验证的、或管理员设置的记录才进入别名视图。
- 用户提交转发地址后，控制面生成一次性令牌，把令牌的哈希和过期时间存库，然后发确认信。用户打开信里的链接后标记为已验证，并清掉令牌（S18-3、A14-4）。
- 保留副本时，别名视图返回本邮箱主地址和转发地址；不保留时只返回转发地址。
- 管理员关闭了用户自助转发时，成员接口返回 403；已有的转发设置保留但不生效，重新开启后恢复。

## 9. HTML 净化

对邮件里的 HTML 正文和用户提交的 HTML 正文做同样的净化：

- 移除脚本、内联事件、表单、框架、对象和插件嵌入。
- 移除 CSS 里的脚本类内容。
- 图片、链接保留；链接的打开方式不修改。
- 相对地址不补全。

用一个成熟的白名单库实现，候选是 bluemonday：策略取最严格的一档，再放开图片和常用排版标签。净化在解析邮件之后、返回之前做一次，不落盘，所以净化规则升级后对新请求立即生效。M3 时先用一批包含常见攻击手法的样例验证策略。

## 10. 主地址与别名自助

### 10.1 修改主地址

1. 校验新账号名符合 M06-1，不是保留字（M06-2）。
2. 查用户是否已经用过这个机会。用过返回 409 和 MAIL-1018（M07-1）。
3. 按地址分配的加锁流程检查新地址没有被占用，见 [数据模型](08-数据模型.md) 9.1。
4. 在同一个事务里：更新账号的主地址；把旧地址以“修改主地址后保留”为来源写进别名表；把用过标记置位；写一条用户自助的审计（M07-4）。

旧地址从此是别名：来信照常投到这个邮箱，也能继续作发件地址。它不能被用户删除。

用户正在登录标准客户端时用的是邮箱地址。主地址改了以后，旧地址不能登录，要用新地址。这一点在接口文档里写明。

### 10.2 别名

- 添加：校验地址格式、保留字、没有被占用；自助别名不超过 5 个，别名总数不超过 20（M08-2）。来源记为用户自助。
- 删除：只能删除来源是用户自助的别名。管理员加的和改主地址保留的不能删，返回 400 和 MAIL-1022。
- 添加和删除都写一条用户自助的审计。

### 10.3 生效

两者都是写入数据库后由视图即时反映。规则里写的“1 分钟内生效”留有余量。

## 11. 限速

计数在控制面内存里，按用户维护三个固定窗口：读每分钟 300 次，写每分钟 60 次，上传每分钟 30 次。超限返回 429 和 MAIL-4291，Retry-After 给出到窗口结束的秒数。控制面重启后计数清零，可以接受。
