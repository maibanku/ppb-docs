# SQL 基线

[schema.sql](schema.sql)：ppb_mail 库的目标态建表语句，24 张表、8 个视图，MySQL 8.0.16 及以上。全新建库，不是存量升级脚本。

[verify/](verify/)：一组验证脚本，在一次性容器里执行 schema.sql 并做断言。

[数据模型](../08-数据模型.md)：每张表的说明、状态取值、并发控制和保留期。

## 怎么读这份 SQL

- 文件分五节：系统级登记、域名、账号与策略、过程与日志、Dovecot 维护的表与视图，最后是数据库账号的权限说明。
- 邮件正文不在这个库里。这里只有元数据。
- 主键是应用侧发的雪花号，没有自增列，没有物理外键。
- 列名都是至少两个单词。通用的时间列和软删标记列沿用平台约定。
- 本库不使用软删，原因见 [数据模型](../08-数据模型.md) 第 4 节。业务表带着 deleted_flag 列只是为了和平台一致，取值恒为 0。
- 第 5 节的数据库账号不在这个文件里创建，由部署脚本创建。

## 怎么执行

实施时不是直接拿这个文件去建库，而是：

1. 把它的内容拆成第一个迁移脚本的 up 和 down 两个文件，放进 service-mail 的迁移目录。
2. 用迁移工具执行。迁移工具的用法照 service-file 或 service-iam。
3. 部署脚本另外执行数据库账号的创建语句。

这样做的原因是以后每次变更都有版本可查、可回滚（O06-2、O06-3）。

## 验证过什么，没验证什么

2026-11-24 做过的验证，命令是 `bash verify/run.sh`：

| 项 | 结果 |
|---|---|
| 执行环境 | 一次性的 mysql:8.0 容器，实际版本 8.0.45。不联网，不发布端口，跑完即删 |
| schema.sql 整体执行 | 通过，无报错 |
| 对象数量 | 24 张表、8 个视图 |
| 命名约定 | 226 列里没有一个单词的列名；没有自增列；没有物理外键 |
| 样例数据断言 | 20 条全部通过，见下 |
| 负向约束 | 13 条应当被拒绝的语句全部被拒绝 |
| 被拒绝的语句是否留下改动 | 没有 |

**样例数据断言**覆盖的是 8 个视图的行为：正常的域、停用的域、默认域；正常、停用、待删除的邮箱；临时密码过期的邮箱；管理员单独停用的邮箱；别名、域保留地址、保留副本和不保留副本的转发、未验证的转发；黑名单和白名单；用户视图的字段；密码视图对过期密码的排除。还验证了两件事：彻底删除邮箱后地址可以重新分配、域名删除后可以重新添加；切换默认域之后仍然只有一个默认域。

**负向约束**覆盖的是：状态取值越界、同一用户第二个邮箱、地址重复、第二个默认域、别名重复、选择器重复、同一邮箱第二条转发或自动回复、名单类型越界、同一行日志重复入库、第二行主机名登记、同一幂等键重复。

**这个验证发现过一个设计错误。** 第一版的发件地址视图和密码视图没有排除“所在域已停用”的账号，断言 A11 没通过。修正之后才有了现在这一版。

没有验证的：

- 只在 8.0.45 上跑过。平台实际的 MySQL 版本如果不同，要重跑一次。
- 没有用迁移工具执行过，只直接执行了文件。
- 没有在真实的 Postfix 和 Dovecot 上用这些视图跑过。视图返回的列名和查询方式要等 M2 核对。
- 容量用量表由 Dovecot 写入，这里的验证只插了一行，没有验证 Dovecot 的写法。

这些都不能当作已经通过。生产迁移的验收在 [验收标准](../../ac/02-邮箱系统验收标准.md) 的 MG-2。

## 重跑验证

需要本机有 Docker，并且有 mysql:8.0 镜像。

```bash
bash verify/run.sh
```

通过的标志是四段都符合输出里括号标注的期望值，最后脚本退出码为 0。完整输出在系统临时目录的 ppbmail-schema-check-out 里。

三个文件的分工：

| 文件 | 内容 |
|---|---|
| run.sh | 起容器、执行、清理 |
| seed_assert.sql | 插入样例数据，然后对视图和约束逐条断言。域名和地址都是文档专用的保留值 |
| negative.sql | 13 条应当被数据库拒绝的语句 |

改了 schema.sql 之后要重跑。新增表或视图时，在 seed_assert.sql 里补对应的断言。
