## 2. 组件与职责

| 组件 | 类型 | 职责 |
|---|---|---|
| Postfix | 成熟组件 | 入站 SMTP、出站投递与队列、SMTP 提交与认证对接 |
| Dovecot | 成熟组件 | LMTP 收信入箱、IMAP 与 POP3、为 Postfix 提供认证、配额、投递时执行过滤脚本与自动回复 |
| Rspamd | 成熟组件 | 垃圾评分、SPF/DKIM/DMARC 校验、出站 DKIM 签名、灰名单 |
| Redis | 成熟组件 | Rspamd 的缓存与历史记录 |
| ClamAV | 成熟组件，可选 | 病毒扫描 |
| ACME 客户端 | 成熟组件 | 向证书机构申请和续期 TLS 证书 |
| service-mail | 自研 | 控制面：域名、账号、别名、转发、配额、成员 HTTP 接口、管理接口、出站限额策略、日志采集、状态采集 |
| mailops | 自研，小工具 | 装在 Postfix 和 Dovecot 所在的容器里，只执行白名单内的运维命令，供控制面调用 |
| mail-manage-web | 自研 | 管理端插件 |

成熟组件负责协议兼容、投递、存储和反垃圾。控制面不解析 SMTP 或 IMAP 协议，只做业务和编排。

Postfix 和 Dovecot 装在同一个镜像里，由进程管理器托管，在同一个容器里运行。原因见 [投递与反垃圾](05-投递与反垃圾.md) 第 1 节。

## 3. 数据流

### 3.1 入站

1. 外部邮件服务器连到 Postfix 的 25 端口。
2. Postfix 查数据库视图：域是否存在，收件人是否存在，账号是否正常。不存在的在收件人阶段拒收。
3. Postfix 把邮件交给 Rspamd 评分。
4. 评分超过拒收线的，Postfix 返回拒收。其余的，Rspamd 把评分结果写进邮件头。
5. Postfix 通过 LMTP 把邮件交给 Dovecot。
6. Dovecot 先查容量，超限返回拒收。然后执行过滤脚本和自动回复，最后把邮件放进收件箱或垃圾邮件文件夹。
7. Postfix 和 Dovecot 各自写日志。控制面读取日志，生成投递记录。

### 3.2 标准客户端发信

1. 客户端连到 587 或 465 端口，建立 TLS。
2. 客户端提交邮箱地址和密码。Postfix 把认证交给 Dovecot，Dovecot 查数据库视图里的密码哈希。
3. 认证通过后，Postfix 检查 From 地址是不是这个账号的主地址或别名，不是就拒绝。
4. Postfix 就每个收件人向控制面的策略服务询问：这个账号的外发权限是否开启，是否超出限额。策略服务回答放行、拒绝或稍后重试。
5. 邮件经 Rspamd 做 DKIM 签名，进入出站队列，直投收件方。
6. 投递结果写入日志，控制面采集。

### 3.3 标准客户端收信

客户端用 IMAP 连 Dovecot，认证后直接读写邮件存储。控制面不参与，所以控制面停了不影响已登录的客户端。

### 3.4 HTTP 接口读写

1. 请求经网关到控制面，控制面校验成员登录态，找到这个用户的邮箱。
2. 读操作：控制面用主账号通过 IMAP 连 Dovecot，以这个用户的身份读取，返回结果。读不改已读状态。
3. 发送：控制面校验发件地址、收件人、大小、外发权限和限额，组装邮件，通过内部提交端口交给 Postfix，再往已发送文件夹写一份副本。
4. 设置：控制面把自动回复、过滤规则、转发写成 Dovecot 能读的文件或数据库记录。

## 4. 端口与网络

| 端口 | 协议 | 监听方 | 暴露范围 | 用途 |
|---|---|---|---|---|
| 25 | SMTP | Postfix | 公网 | 入站收信 |
| 465 | SMTP | Postfix | 公网 | 提交，隐式 TLS |
| 587 | SMTP | Postfix | 公网 | 提交，STARTTLS |
| 143 | IMAP | Dovecot | 公网 | IMAP，STARTTLS |
| 993 | IMAP | Dovecot | 公网 | IMAP，隐式 TLS |
| 110、995 | POP3 | Dovecot | 公网，默认关闭 | POP3 |
| 24 | LMTP | Dovecot | 私有网络 | Postfix 投递 |
| 11332 | Milter | Rspamd | 私有网络 | Postfix 调用 |
| 11334 | HTTP | Rspamd | 私有网络 | 控制接口，供控制面查历史记录 |
| 6379 | Redis | Redis | 私有网络 | Rspamd 使用 |
| 3310 | TCP | ClamAV | 私有网络，可选 | 病毒扫描 |
| 80 | HTTP | 证书客户端 | 公网 | 证书验证；其余请求一律不响应 |
| 10028 | SMTP | Postfix | 私有网络 | 控制面的可信提交 |
| 11433 | Postfix 策略协议 | service-mail | 私有网络 | 出站限额判定 |
| 9108 | gRPC | service-mail | 平台内网 | 内部 RPC |
| 9118 | HTTP | service-mail | 平台内网 | 成员接口、管理接口、健康检查、指标 |

内部端口 10028 和 11433 是本设计新分配的，9108 和 9118 延续平台端口序列，见 [ADR-005](../adr/005-与平台集成.md)。

网络分三层：

- 公网：只有 Postfix 和 Dovecot 的对外端口。
- 邮件节点私有网络：各组件之间。控制面的主账号口令、内部提交端口都在这一层。
- 平台内网：网关到控制面的 HTTP，控制面到 IAM 和 IM 的 gRPC。

## 5. 数据存储

| 存储 | 内容 | 读写方 |
|---|---|---|
| MySQL 库 ppb_mail | 域名、邮箱账号、别名、转发、自动回复、过滤规则、黑白名单、限额规则、全局设置、日志、审计；另有给 Postfix 和 Dovecot 读的视图，以及 Dovecot 配额插件维护的容量用量表 | 控制面读写；Postfix 和 Dovecot 用只读账号读视图；Dovecot 配额插件用专用账号写容量用量表 |
| 邮件存储目录 | 每个邮箱一个目录，格式 Maildir++ | Dovecot 读写；控制面只读挂载用来统计用量，读写邮件一律经 IMAP |
| Sieve 目录 | 用户脚本，按域名和账号名分层 | 控制面写；Dovecot 读 |
| 控制面数据目录 | 发送前暂存的附件 | 控制面 |
| 邮件队列目录 | Postfix 队列 | Postfix；运维代理代控制面执行队列命令 |
| 密钥目录 | DKIM 私钥、TLS 证书和私钥 | 控制面写入 DKIM 私钥；Postfix、Dovecot、Rspamd 读取 |
| 日志目录 | Postfix 和 Dovecot 的日志文件 | Postfix 和 Dovecot 写；控制面读 |
| Redis | Rspamd 的缓存、贝叶斯数据、历史记录 | Rspamd；控制面读历史记录 |

邮件正文不在 MySQL 里。这避免了旧设计里正文按收件人复制的存储放大，见 [ADR-004](../adr/004-存储与数据归属.md)。

## 7. 信任边界

| 主体 | 能访问 | 不能访问 |
|---|---|---|
| 公网 | Postfix 和 Dovecot 的对外端口 | 其余一切 |
| Postfix 与 Dovecot（同一容器） | 数据库视图（只读账号）、容量用量表（配额插件专用账号）、邮件存储、Sieve 目录（只读）、Rspamd、控制面的策略服务 | 数据库的其他表 |
| 控制面 | 数据库全部表（容量用量表只读）、邮件存储（只读挂载，经 IMAP 读写）、Sieve 目录（写）、密钥目录、日志目录（只读）、运维代理 | 容器宿主机的 Docker 套接字 |
| 网关 | 控制面的 HTTP 端口 | 邮件节点的任何其他端口 |
| 管理端 | 经网关的管理接口 | 邮件内容 |

控制面不挂载 Docker 套接字。需要操作 Postfix 队列或 Dovecot 时，经运维代理执行白名单命令，见 [管理端设计](07-管理端设计.md) 第 2 节。

## 8. 规模与部署形态

- 单节点。按 3000 用户、每用户日均 50 封设计。
- 邮件组件跑在同一台服务器上，用容器编排。
- 控制面与邮件组件同机部署，便于访问日志目录、密钥目录和内部端口；它同时接受来自平台内网的网关请求。
- 数据库用平台现有的 MySQL，另建 ppb_mail 库和专用账号。
- 扩展到多节点不在本期范围。
- 开发环境：控制面按平台现有方式作为本机进程启动；邮件组件用一份开发用的编排在本机拉起，端口只绑回环地址，证书用自签的。见 [部署与运维](10-部署与运维.md)。
