## 1. 架构

```
客户端
  │ POST /iam/api/v1/register/code | password/forgot | identity/change-email/start
  ▼
IamHTTPHandler（internal/transport/iam/iam_http.go）
  │
  ▼
AccountService（internal/account/service）
  ├─ 规范化邮箱、限流计数、生成 6 位码
  ├─ 存挑战：verification_challenges，只存 HMAC 摘要
  └─ delivery.SendCode(target, code, purpose)
        ▼
     LogSendCodeSender（internal/notify）── 写 iam_email_send_log（码位掩码）
        └─ next.SendCode
             ├─ SmtpDeliverySender（internal/platform/smtp）  生产
             └─ LogDeliverySender（internal/notify）          开发态

管理端 ── GET /api/v1/manage/email-log ── 网关 ── AdminCompatHandler.ListEmailSendLog ── iam_email_send_log
```

职责划分：

| 部件 | 职责 |
|---|---|
| notify.DeliverySender | 投递端口，只有一个方法 `SendCode(target, code, purpose)` |
| notify.LogDeliverySender | 开发态投递，把码打进服务日志 |
| notify.LogSendCodeSender | 装饰器，包在真实投递器外，每次投递后落一行记录 |
| platform/smtp.SmtpDeliverySender | 生产投递，标准库 net/smtp |
| platform/smtp.AssembleDeliverySender | 按配置和环境变量决定装配哪种投递器 |
| account.AccountService | 限流、生成、存挑战，然后调用投递端口 |

## 2. 三类发码流程

| 流程 | 入口 | 是否校验账号 | 失败的对外表现 |
|---|---|---|---|
| 注册 | `IssueRegisterCode` | 不校验是否已注册 | 429、503 如实返回 |
| 找回密码 | `IssuePasswordResetCode` | 仅存在且状态正常的账号才发码 | 恒返回成功，差异写服务端日志 |
| 换绑 | `StartChangeEmail`，确认走 `ConfirmChangeEmail` | 须登录并校验当前密码；新值唯一性预检 | 如实返回 |

公共骨架 `issueScopedCode`：统计同一目标近 1 小时未消费挑战数 → 达上限即拒 → 生成码和随机 nonce → 计算 HMAC 摘要 → 判断投递器是否可用 → 保存挑战 → 投递。明文码只作为投递调用的参数出现。

## 3. 装配矩阵

`AssembleDeliverySender` 的判定顺序：

| 条件 | 结果 |
|---|---|
| 端口环境变量非数字或不在 1 到 65535 | 不装配真投递，返回告警 |
| 主机、账号、发件人均非空，端口合法，且 `PPB_SMTP_PASSWORD` 非空 | 真投递 |
| 以上不满足，且 `dev_delivery_log_only` 为真 | 日志投递 |
| 以上不满足 | 不装配，发码返回 `IAM-3001` |

启动装配在 `cmd/server/boot_wire.go`：取得投递器后，若为空且开发态开关开启则补日志投递器；只要投递器非空就用 `LogSendCodeSender` 包一层，再注入 `AccountService`。

## 4. 响应与错误码

| 情况 | HTTP | 代码 | 内部 RPC |
|---|---|---|---|
| 请求非法 | 400 | `IAM-1001` | InvalidArgument |
| 发码超限 | 429 | `IAM-4290` | `IAM-1002`，ResourceExhausted |
| 投递通道不可用 | 503 | `IAM-3001` | Unavailable |
| 换绑确认错码 | 400 | `IAM-1003` | InvalidArgument |

找回密码接口只对请求非法返回 400，其余错误一律吞掉并返回成功。

## 5. SMTP 投递

- 标准库 `net/smtp`：`SendMail(地址, PlainAuth, 发件人, 收件人, 邮件)`，一次调用完成拨号、EHLO、STARTTLS、认证、投递、退出。
- 不复用连接，无共享状态，并发安全。
- **没有超时**：目录内没有任何 deadline 或 timeout 设置。
- 不重试：失败原样返回，由调用方映射错误。
- 口令只从环境变量 `PPB_SMTP_PASSWORD` 读取。

邮件构造 `buildCodeMessage`：

- 主题 `【PPB】<用途词>验证码`，经 MIME 编码词编码。
- 正文三句：验证码、有效分钟数、安全提示。
- 头部含 `MIME-Version: 1.0` 和 `Content-Type: text/plain; charset=UTF-8`。
- 收件人或发件人含 CR 或 LF 即返回非法输入。

## 6. 投递记录

表 `iam_email_send_log`，位于 ppb_iam 库，迁移脚本 `000001_baseline.up.sql`：

| 列 | 类型 | 说明 |
|---|---|---|
| iam_email_send_log_id | bigint unsigned，自增 | 主键 |
| from_addr | varchar(254) | 发件人 |
| to_addr | varchar(254) | 收件人，有索引 |
| subject | varchar(254) | 主题 |
| body | varchar(1024) | 正文摘要，码位掩码 |
| mail_type | varchar(64) | 类型，有索引 |
| send_status | tinyint | 1 成功，2 失败 |
| error_msg | varchar(254) | 失败摘要 |
| create_time、update_time、deleted_flag | — | 通用列 |

写入规则（`LogSendCodeSender.SendCode`）：

1. 先调用真实投递器。
2. 成功记 1，失败记 2 并把错误文本截断到 254 字节。
3. 正文固定为“您的验证码：******（类型，10 分钟内有效）。如非本人操作请忽略。”
4. 主题取自 `email_send_log.go` 自己的映射表，文案是“【ppbChat】…”。
5. 发件人固定为占位值 `no-reply@ppbchat.internal`。
6. 写入失败被忽略，不影响投递结果。

类型映射：

| 投递用途 | 邮件类型 |
|---|---|
| register | verify_code |
| reset_password | reset_password_code |
| change_identity | change_email_code |
| 其他 | verify_code |

## 7. 接口契约

发码端点在 `iam_http.go` 的文件头注释里有完整清单。推送记录接口分三处：

- 路由声明：`ppb-iam/service-iam/api/user-manage-http.json`，路径 `/api/v1/manage/email-log`，对应 RPC `/iam.AdminCompatService/ListEmailSendLog`，权限策略为应用 chat 的 `mail.read`。
- 消息定义：`ppb-iam/contracts-iam/proto/admincompat.proto`。

| 字段 | 说明 |
|---|---|
| page、pageSize | 分页 |
| to | 收件人模糊 |
| type | 类型精确 |
| startTimeUnix、endTimeUnix | 发送时间范围，含端点 |
| sortBy | 只认 createTime |
| sortOrder | asc 或 desc，缺省 desc |
| operatorId | 由网关注入 |

查询实现 `notify.ListEmailSendLogs`：筛选条件动态拼接，先 count 再查；排序追加主键列保证稳定；时间按 UTC 比较。

## 9. 管理页

`ppb-chat/chat-manage-web/src/views/ops/EmailLogsView.vue`，页面标题“推送记录”。

- 列：发件人、收件人、主题、类型、状态、发送时间。
- 筛选：类型下拉、发送时间范围；搜索框的关键字作为收件人模糊条件。
- 每行有“查看”浮层，显示主题、正文摘要，失败时显示失败原因。
- 不可多选，接口也不返回行标识。

## 10. 需求与实现的差距

对应 [需求细则](../pr/01-系统通知邮件.md) 中的缺口和待决策条目：

| 需求 | 现状 | 影响 |
|---|---|---|
| 04-1 投递超时 | 无超时 | 中继挂起时发码请求无限期阻塞 |
| 04-4 发码不长时间占用请求 | 投递同步发生在请求内 | 用户等待完整的 SMTP 会话 |
| 05-5 模板单一来源 | 实发与记录是两套文案 | 审计记录与实际发出的邮件不一致 |
| 06-5 记录标明通道 | 无通道字段 | 管理页无法区分真投递和日志投递 |
| 06-6 保留期 | 无清理 | 记录表只增不删 |
| 06-7 排序列索引 | create_time 无索引 | 数据量大时分页变慢 |
| 07-8 类型筛选 | 只有 verify_code | 另两类无法单独筛选，显示原始代码 |
| 02-9 生成无偏 | 取模有偏差 | 实际风险很低 |
| 01-7 换绑进行态 | 进程内 map | 多实例部署前必须外置 |
| NFR-N04 指标 | 无 | 投递成功率、时延不可见 |
