## 1. 总则

| 项 | 约定 |
|---|---|
| 库 | 平台现有 MySQL 实例里新建一个库 ppb_mail，版本 8.0.16 及以上 |
| 内容 | 只有元数据：域、账号、别名、策略、日志、审计、临时数据。邮件正文不在本库，见第 2 节 |
| 字符集 | utf8mb4_unicode_ci；地址、域名、选择器、设置键这类需要精确比较的列用 utf8mb4_bin |
| 主键 | 雪花号，BIGINT UNSIGNED，应用侧发号，不用 AUTO_INCREMENT。接口里按字符串传输 |
| 时间 | DATETIME，一律 UTC。连接会话时区固定为 +00:00 |
| 命名 | 表名以 mail_ 开头；列名至少两个单词，下划线连接；索引名带表名缩写，唯一索引 uk_，普通索引 idx_ |
| 外键 | 不建物理外键。引用、同域、状态由应用校验 |
| 枚举 | TINYINT 加 CHECK 约束，取值写在列注释里。接口里也按数值传输 |
| JSON 列 | 只存不需要按内容检索的结构，服务端校验结构后才写入 |
| 键值表 | 只有全局设置用键值表。依据是 [存储建模准则](../../../ppb-base/.claude/rules/storage-modeling.md)：键集合会增长、不需要按值检索的配置才键值化；一旦要筛选或连表，就提升为字段 |

## 2. 邮件正文不进数据库

邮件只存在 Dovecot 的邮件目录里，一份。本库只记录“谁有邮箱、状态如何、配额多少、曾经投递过什么”。

由此带来三条实现约束：

- 成员接口读写邮件一律经 IMAP，不读邮件目录里的文件，见 [成员接口设计](06-成员接口设计.md)。
- 管理端的投递日志、评分记录只有元数据，不含主题和正文，见 [管理端](../pr/06-管理端.md) 的 FP-G18。
- 备份要同时备份数据库和邮件目录，见 [部署与运维](10-部署与运维.md)。

## 4. 删除策略：物理删除

本库不使用软删除。原因在规则里：删除后的域名必须可以重新添加（D01-1、D01-5），删除后的别名地址立即拒收并且以后可以再用（M08-6），邮箱彻底删除后地址可以重新分配、用户可以重新开通（M06-5、M10-3）。唯一索引是按全表算的，软删除的行会一直占着地址。

| 类别 | 做法 |
|---|---|
| 域、邮箱、别名、转发、自动回复、过滤规则、限额覆盖、黑白名单、DKIM 密钥、保留地址 | 删除即物理删除 |
| 历史 | 由审计表 mail_admin_audit_log 保留。用户自助的写操作也记审计 |
| deleted_flag 列 | 为沿用平台约定保留，取值恒为 0。视图里按它过滤只是防御，代码里不写它的值 |

一个例外是别名到期待删除的邮箱：邮箱转待删除时，别名和转发随之失效，靠视图的过滤实现；邮箱恢复时它们自动恢复；邮箱彻底删除时它们随之物理删除。

## 5. 关键表

### 5.1 mail_endpoint

全库只有一行，主键固定为 1，由 CHECK 约束保证不能再插第二行。两组内容：

- 对外主机名和公网地址。证书、MX 记录、PTR 记录都指向这里登记的值，见 FP-D02。
- 全局 DNS 检查项的结果：主机名的 A 或 AAAA 记录、PTR 记录。逐项结果存在 JSON 列里，结构是 `[{item, status, message, time}]`。

主机名和公网地址来自部署配置。控制面每次启动时把配置里的值写进这一行，没有就插入，有就更新。线上页面不提供修改它们的接口，因为改主机名要同时换证书、改 DNS，是部署层面的操作。值发生变化时控制面重新执行一次全局检查，管理端显著提示需要同步修改 DNS（D02-4）。

### 5.2 mail_domain、mail_domain_dkim_key、mail_system_alias

**mail_domain**

| 列 | 说明 |
|---|---|
| domain_name | 小写，全库唯一 |
| default_flag | 默认域。生成列 default_slot 加唯一索引保证默认域至多一个；“至少一个”由应用在切换默认域的同一个事务里保证，见 7.2 |
| domain_status | 1 正常，2 停用 |
| dkim_selector | 当前签名用的选择器，指向密钥表里 active_flag 为 1 的那一行 |
| dns_check_status、dns_check_detail、dns_check_time | 这个域的 DNS 校验结果。detail 的结构同 5.1，检查项为 MX、SPF、DKIM、DMARC |

删除一个域之前，应用要确认它下面没有邮箱、别名、保留地址（D01-5）。删除时在同一事务里删掉它的 DKIM 密钥行和保留地址行，事务提交后再删除磁盘上的私钥文件。私钥文件删除失败只告警，不影响删除结果，因为密钥行已不存在，不会再被用来签名。

**mail_domain_dkim_key**

每个域可以有多个选择器，轮换时新旧并存（D04-3）。同一域内选择器唯一。`dkim_key_path` 是密钥目录内的相对路径；`dkim_public_record` 是要写进 DNS 的 TXT 记录值。私钥本身不进库（D04-1、D04-2）。

**mail_system_alias**

每个域的 postmaster 和 abuse 两个保留地址指向的邮箱（M06-3）。添加域时由应用插入两行，初始指向值由添加域时填写的管理员邮箱决定；之后可经管理接口修改。

### 5.3 mail_account 与密码历史

**mail_account** 是账号域的核心表。

| 列 | 说明 |
|---|---|
| user_id | IAM 用户主键，唯一。这就是“一个用户最多一个邮箱”的硬约束（M01-1） |
| mail_domain_id、account_local、mail_address | 主地址。mail_address 小写，全库唯一 |
| account_status | 实际状态，1 正常，2 停用，3 待删除。由下面两个输入推导，见 6.1 |
| admin_suspended_flag | 管理员是否单独停用了这个邮箱 |
| iam_status | 最近一次对账得到的 IAM 用户状态：1 正常，2 停用，3 注销 |
| password_hash | Dovecot 可验证的密码哈希。自动开通且还没设密码的邮箱，这里是一段不可猜测随机串的哈希，没有人知道原文，所以无法登录 |
| password_expire_time | 临时密码的过期时间。为空表示不过期 |
| password_changed_time | 最近一次改密码的时间 |
| address_changed_flag | 用户是否已经用掉那一次自助修改主地址的机会（M07-1） |
| outbound_perm | 外发权限，1 允许，0 禁止 |
| quota_bytes | 容量配额 |
| quota_warn_time | 最近一次发容量预警的时间，用于“7 天内最多提醒一次”（M11-4） |
| last_login_time、last_login_ip | 最近一次标准客户端登录成功的时间和地址。由采集器在登录日志入库后回写，控制面自己用主账号登录不算 |
| purge_time | 不为空表示处于待删除，值是彻底清除的时间 |

**状态推导。** account_status 不由接口直接写入，统一由一个函数根据输入推导：

| purge_time | admin_suspended_flag | iam_status | account_status |
|---|---|---|---|
| 不为空 | 任意 | 任意 | 3 待删除 |
| 为空 | 1 | 任意 | 2 停用 |
| 为空 | 0 | 不是 1 | 2 停用 |
| 为空 | 0 | 1 | 1 正常 |

这个函数只有一处实现，配一张真值表的单元测试。所有改变状态的操作都先改输入，再调用它得到结果，见 [账号与认证](04-账号与认证.md) 第 2 节。

**“已删除”不是存储状态。** 彻底删除时账号行和它的从属数据一并物理删除，所以表里没有取值 4。M09-4 描述的“已删除”是删除之后的行为：地址不在视图里，来信按地址不存在拒收。

**mail_account_password_history** 每次用户改密码成功后写入一行旧密码的哈希，供“不得与最近 3 次相同”的校验（M05-3）。写入后删掉该邮箱第 4 旧的行。

### 5.4 mail_alias

| 列 | 说明 |
|---|---|
| mail_account_id | 目标邮箱 |
| alias_address | 别名地址，小写，全库唯一 |
| alias_source | 1 管理员添加，2 用户自助添加，3 修改主地址后保留的旧地址 |

- 别名不是独立账号：没有密码，不能登录（M08-5），登录视图里不出现它。
- 自助别名最多 5 个、别名总数不超过 20（M08-2），由应用在插入前计数校验。
- 目标邮箱转待删除期间，别名视图里不出现它；恢复后自动回来。
- 同一个地址不能既是主地址又是别名（M06-4）。两个表各自有唯一索引，跨表的部分由应用加锁校验，见 7.1。

### 5.5 用户设置三张表

| 表 | 数量 | 关键列 | 落地位置 |
|---|---|---|---|
| mail_forward | 每个邮箱最多一行 | forward_address、keep_copy_flag、enable_flag、verify_status、verify_token_hash、verify_expire_time、forward_source | 别名视图 |
| mail_autoreply | 每个邮箱最多一行 | enable_flag、start_time、end_time、reply_subject、reply_body | 用户的 Sieve 脚本 |
| mail_filter_rule | 每个邮箱最多 50 行 | rule_order、rule_name、enable_flag、condition_json、action_json | 用户的 Sieve 脚本 |

- 转发的 verify_status 为 2（已验证）、或 forward_source 为 2（管理员设置，免验证）时才生效。verify_token_hash 存确认令牌的 SHA-256，验证成功后清空。
- 过滤规则的 condition_json 是条件数组，action_json 是动作对象。结构见 [接口契约](09-接口契约.md) 3.4，服务端按白名单校验字段和取值后才写入，也才渲染成脚本。
- 修改主地址时，旧地址以 alias_source 为 3 写进别名表（M07-2、M07-3）。

### 5.6 策略表

**mail_outbound_rule** 是按账号的出站限额覆盖值。没有行的账号用全局默认值。删除一行就是恢复使用默认值。

**mail_blocklist** 的唯一键是名单类型、条目类型、条目值三元组。同一个值可以既在黑名单又在白名单，但那是管理员的误操作，管理接口在添加时拒绝与另一张名单重复的值。

**mail_setting** 是全局设置，键名全局唯一，一行一键。默认值、类型和取值范围在代码里登记，不进库；初始化时把全部键按默认值写入。键名清单见 [管理端设计](07-管理端设计.md) 第 11 节。

### 5.7 过程表

| 表 | 说明 |
|---|---|
| mail_attachment_temp | 暂存附件的元数据。文件本体在控制面的数据目录，路径是相对路径 storage_path。接口返回的附件标识由主键生成，带签名 |
| mail_trash_origin | 经 HTTP 接口把邮件移进已删除文件夹时记一行：邮箱、文件夹、有效性标识、邮件编号、原文件夹。恢复时按前四项查；查不到恢复到收件箱（A12-3） |
| mail_idempotency | 幂等记录。唯一键是发起人加幂等键；request_hash 是请求内容的 SHA-256，用来识别“同一个键配了不同内容”（A09-3） |
| mail_admin_batch | 批量操作任务。控制面按 request_json 里的对象清单逐个执行，边执行边更新计数，失败明细累积在 result_json 里。控制面重启后把遗留的“运行中”任务标为中断（G04-2、G04-4） |
| mail_sync_run | 对账每次执行一行（M03-7） |
| mail_collector_checkpoint | 采集断点。三个来源各一行：Postfix 日志、Dovecot 日志、Rspamd 历史记录。前两个记文件标识、偏移和上一行的摘要，第三个只记游标。用法见 [管理端设计](07-管理端设计.md) 5.1 |

### 5.8 日志表

三张日志表由采集器写入，都是只追加、按时间清理。去重靠唯一键：

| 表 | 去重键 | 来源 |
|---|---|---|
| mail_delivery_log | log_line_hash，来源日志行的摘要 | Postfix 日志 |
| mail_auth_log | log_line_hash | Dovecot 日志 |
| mail_filter_log | history_uniq，Rspamd 历史记录的标识 | Rspamd 历史记录 |

- 投递日志一行对应一个收件人的一次投递尝试。同一封邮件重试几次就有几行，用 queue_id 加 recipient_address 归并。
- 三张表都不存邮件主题、正文、附件名（G18-1、G18-2）。评分记录的 hit_symbols 存命中的规则名和分值，也不含邮件内容。
- mail_admin_audit_log 由控制面写入，记什么、什么时候记见 [管理端设计](07-管理端设计.md) 第 12 节。before_json 和 after_json 不含密码、密钥这类秘密。

### 5.9 mail_quota_dict

Dovecot 的配额插件读写这张表，控制面只读。主键是邮箱地址。用量在 Dovecot 投递和登录时重算，可能略滞后，展示层面可以接受。

## 7. 视图

视图是给 Postfix 和 Dovecot 查的，控制面不读视图。控制面只写表，视图随表即时变化。

| 视图 | 使用方 | 配置里的用途 | 返回列 | 包含的行 |
|---|---|---|---|---|
| v_mail_domain | Postfix | 本系统接收的域 | domain | 状态正常的域 |
| v_mailbox | Postfix | 判断收件人是不是有效邮箱 | address | 状态正常、所在域正常的账号的主地址 |
| v_mail_recipient_policy | Postfix | 收件人检查，返回自定义拒绝信息 | address、action | 状态为停用或待删除的账号的主地址，action 固定为 REJECT Mailbox disabled |
| v_mail_alias | Postfix | 别名和转发解析 | address、goto | 别名；域保留地址；已验证或管理员设置的转发 |
| v_mail_sender | Postfix | 认证用户允许使用的发件地址 | login_name、address | 每个正常账号一行主地址，外加每个别名一行 |
| v_mail_blocklist | Postfix | 发件人检查 | address、action | 黑名单条目 |
| v_mail_dovecot_user | Dovecot | 用户信息 | userid、uid、gid、home、mail、quota_rule | 状态正常、所在域正常的账号 |
| v_mail_dovecot_passwd | Dovecot | 密码哈希 | userid、password | 同上，再排除临时密码已过期的账号 |

要点：

- 视图里对 deleted_flag 的过滤是防御性的，取值恒为 0。
- 别名视图的 goto 是逗号分隔的目标地址。转发且保留副本时是“主地址,转发地址”，只写转发地址且不留副本时只有转发地址。
- 邮箱视图包含临时密码已过期的账号：它们仍然能收信，只是不能登录。
- 别名自己所在的域停用时，这个别名不出现在别名视图和发件地址视图里：不能再收信，也不能再作发件地址（D01-2）。
- 主账号的口令不在视图里，在 Dovecot 自己的口令文件里，见 [账号与认证](04-账号与认证.md) 第 5 节。

| 账号 | 使用方 | 权限 |

## 9. 并发与一致性

### 9.1 地址分配

地址在主地址表和别名表之间要全局唯一，而唯一索引只能管一张表。做法是把域这一行当作锁：

1. 开启事务。
2. 按主键升序锁住涉及的所有域的行：`SELECT mail_domain_id FROM mail_domain WHERE mail_domain_id IN (...) FOR UPDATE`。主地址改到别的域、别名属于别的域时会有两个域，按固定顺序加锁避免互相等待。
3. 依次检查三张表：mail_account.mail_address、mail_alias.alias_address、mail_system_alias 按“账号名加域名”拼出来的地址。
4. 执行插入或更新。
5. 提交。

开通邮箱、添加别名、修改主地址都走同一个仓储函数。并发测试：两个协程同时申请同一个地址，恰好一个成功。

### 9.2 默认域切换

“默认域恰好一个”分两半保证：至多一个由生成列加唯一索引保证；至少一个由应用保证，切换时在同一个事务里先把旧默认域置 0，再把新默认域置 1。默认域不能停用或删除（D01-4），所以不会出现零个。

### 9.3 审计与业务写入

能放进同一个事务的审计和业务写入放在一起；放不进的，先写审计再执行外部操作，审计写失败则操作失败（G15-4）。

### 9.4 邮箱彻底删除

顺序固定，每一步可重入：

1. 把账号行、别名、转发、自动回复、过滤规则、限额覆盖、原文件夹记录读出来，写一条审计。
2. 经运维代理删除邮件服务器上的邮件目录。控制面对邮件存储目录只有只读挂载，删除必须在邮件核心容器里做。
3. 物理删除第 1 步列出的全部行，以及密码历史和容量用量行。
4. 第 2 步失败时整体失败，账号保持待删除，下次清理任务重试。第 3 步失败时同样重试，第 2 步对不存在的目录返回成功。

## 10. 保留期与清理

| 表 | 保留期 | 依据 |
|---|---|---|
| mail_delivery_log、mail_auth_log | 180 天 | G10-4、G11-3 |
| mail_filter_log | 30 天 | G12-4 |
| mail_admin_audit_log | 365 天 | G15-3 |
| mail_attachment_temp | 24 小时 | A08-4 |
| mail_idempotency | 24 小时 | A09-3、[成员接口设计](06-成员接口设计.md) 6.6 |

| mail_admin_batch | 30 天 | 设计取值 |
| mail_sync_run | 90 天 | 设计取值 |

清理任务每天运行一次，按时间分批删除，每批不超过 1 万行，避免长事务。暂存附件和幂等记录另有一小时一次的清理。

## 11. 容量估算

按上限 3000 用户、每用户每天 50 封估：

| 表 | 每天行数 | 保留期内行数 | 估算大小 |
|---|---|---|---|
| mail_delivery_log | 约 25 万 | 约 4500 万 | 约 12 GB |
| mail_auth_log | 约 6 万 | 约 1100 万 | 约 1.5 GB |
| mail_filter_log | 约 15 万 | 约 450 万 | 约 1 GB |

日行数是估算值，入站被拒收的连接每个收件人一行，出站重试每次一行，都没有计入日均 50 封的口径，实际会更高。M5 压测时用实测值修正这张表。如果单表超过预期，再引入按月分区，本期不做。

## 12. 迁移

- 迁移脚本放在 service-mail 的 internal/dbmigrate/migrations，命名和版本表沿用平台现有做法。
- 第一个版本就是 schema.sql 的内容，拆成 up 和 down 两个脚本。
- 之后的变更只增加表和列，保持对上一版本兼容（O06-2）；每个版本都带 down 脚本（O06-3）。
- 视图的变化也走迁移脚本，不手工改库。
- 启动时先跑迁移再监听端口。`-check-config` 模式不跑迁移（O05-3）。
