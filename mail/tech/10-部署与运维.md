## 1. 部署形态

| 项 | 设计 |
|---|---|
| 节点 | 一台公网服务器，单节点。不做高可用（PRD 非目标） |
| 运行方式 | Docker Compose。邮件核心、Rspamd、Redis、控制面、证书客户端各是一个容器，在同一个编排文件里 |
| 数据库 | 用平台现有的 MySQL 实例，另建 ppb_mail 库和 3 个专用账号，见 [数据模型](08-数据模型.md) 第 8 节 |
| 控制面的位置 | 和邮件组件同机、同一个容器网络，这样它能直接读到日志目录、密钥目录和运维代理的套接字 |
| 与平台的连接 | 控制面用两个网络：邮件节点的私有网络，以及到平台内网的连接。网关、IAM、IM、MySQL 都在平台内网一侧 |
| 邮件协议端口 | 不经过网关，直接由 Postfix 和 Dovecot 对公网监听 |

网络上有两个硬要求，部署前先确认：

- 邮件节点到平台内网（网关、IAM、IM、MySQL）有内网路由或加密隧道。控制面的端口不暴露在公网上。
- 出站 25 端口可用。不少云厂商默认封禁出站 25，要先申请解封。

**服务器规格**是设计取值，需要按实际情况调整：

| 项 | 建议起点 | 依据 |
|---|---|---|
| CPU | 4 核 | Postfix、Dovecot、Rspamd 在 3000 用户规模下占用都不高 |
| 内存 | 8 GB | 开启病毒扫描时再加 2 GB，病毒库引擎很吃内存 |
| 系统盘 | 40 GB | 系统、镜像、日志 |
| 邮件数据盘 | 500 GB 起步 | 按 3000 用户、人均 500 MB 到 1 GB 估。配额上限是 5 GB，但不会人人都用满。用量到 80% 告警后扩容 |

## 2. 目录与数据卷

| 数据卷 | 容器内路径 | 内容 | 读写方 |
|---|---|---|---|
| vmail | /var/vmail | 邮件存储，Maildir++ 格式 | Dovecot 读写；控制面只读，用来统计用量 |
| queue | /var/spool/postfix | Postfix 队列 | Postfix；运维代理代控制面执行队列命令 |
| sieve | /var/mail-sieve | 用户脚本，按域名和账号名分层 | 控制面写；Dovecot 读 |
| secrets | /etc/mail-secrets | 子目录 dkim（DKIM 私钥）、tls（证书和私钥）、master（主账号口令）、db（数据库口令） | 控制面写 dkim 和 db；证书客户端写 tls；其余组件只读自己需要的那一个子目录 |
| logs | /var/log/mail | Postfix 和 Dovecot 的日志文件 | Postfix、Dovecot 写；控制面读 |
| mailops | /run/mailops | 运维代理的 Unix 套接字 | 运维代理创建；控制面连接 |
| mail-config | /run/mail-config | 控制面渲染出来的 Postfix 和 Dovecot 数据库连接配置 | 控制面写；邮件核心只读 |
| rspamd-local | /etc/rspamd/local.d | 控制面渲染的 Rspamd 本地覆盖配置和白名单映射。官方镜像读的本地覆盖目录是 local.d，没有 local 这个目录（M1 核对 T10-2） | 控制面写；Rspamd 只读 |
| service-data | /var/lib/service-mail | 暂存附件 | 控制面 |
| rspamd-data | /var/lib/rspamd | Rspamd 的贝叶斯数据 | Rspamd |
| redis-data | /var/lib/redis | Rspamd 的缓存 | Redis |

四个数据卷必须放在持久化的磁盘上：vmail、secrets、service-data、rspamd-data。queue 和日志丢了可以重建。

目录权限：

- vmail 和 sieve 的属主是邮件存储的虚拟用户，系统里统一用 5000。
- 私钥文件权限 0400，只允许读取它的那个服务的运行用户访问。
- 运维代理的套接字只允许控制面的用户组连接。

## 3. 编排文件

位置：ppb-mail/deploy/compose/docker-compose.yml 和同目录的 .env.example。镜像版本全部写死，不用 latest。

| 服务 | 镜像 | 对外端口 | 依赖 | 健康检查 |
|---|---|---|---|---|
| service-mail | 本仓构建 | 平台内网 9118、9108 | 数据库迁移任务完成 | GET /ping |
| migrate | 与 service-mail 相同 | 无 | 数据库 | 一次性任务，退出码 0 算成功 |
| mailcore | 本仓构建，deploy/images/mailcore | 25、465、587、143、993；POP3 开启时加 110、995 | service-mail 健康，证书文件存在 | 运维代理的 status 命令 |
| rspamd | 官方镜像 | 无 | redis | 控制接口的探活 |
| redis | 官方镜像 | 无 | 无 | redis-cli ping |
| acme | 官方镜像或社区镜像 | 80 | 无 | 进程存活 |
| clamav | 官方镜像，可选 | 无 | 无 | clamd 探活 |

启动顺序：

1. migrate 跑迁移。
2. service-mail 启动。监听端口之前先渲染 mail-config 下的文件、创建运维代理要用的目录、把部署配置里的对外主机名和公网地址写进登记表。
3. mailcore 启动。入口脚本先等证书文件出现，最多等 10 分钟，超时退出。
4. rspamd、redis 随 mailcore 一起就绪。

控制面的 /ping 在渲染完成后才可用，所以 mailcore 以 /ping 作为依赖条件就足够，不用另加标记文件。

端口 80 只给证书验证用。证书客户端监听 80，完成验证后把证书放到约定路径。

## 4. 配置

### 4.1 配置文件

位置：service-mail/env/mail-prod.template.yaml。键名和平台其他服务对齐。

```yaml
server:
  rpc_port: 9108          # gRPC
  http_port: 9118         # HTTP
  http_bind: 0.0.0.0      # 容器内监听；来源由编排的网络限制

database:
  mysql:
    dsn: ""               # 空 = 读环境变量 MAIL_DB_DSN

log:
  level: info

mail:
  public_hostname: ""     # 对外主机名，小写
  public_ip: ""           # 公网地址
  imap_addr: "mailcore:993"            # 容器网络内部，隐式 TLS
  imap_tls_server_name: ""             # 校验证书用的主机名，等于对外主机名
  imap_insecure_skip_verify: false     # 只允许开发环境为 true
  imap_master_user: ""                 # Dovecot 主账号的用户名
  submit_addr: "mailcore:10028"        # 内部可信提交端口
  mailops_socket: "/run/mailops/agent.sock"
  vmail_dir: "/var/vmail"
  sieve_dir: "/var/mail-sieve"
  mail_log_dir: "/var/log/mail"
  dkim_dir: "/etc/mail-secrets/dkim"
  tls_dir: "/etc/mail-secrets/tls"
  rspamd_controller_addr: "rspamd:11334"
  rspamd_local_dir: "/etc/rspamd/local.d"
  policy_listen: "0.0.0.0:11433"       # Postfix 策略服务
  temp_attachment_dir: "/var/lib/service-mail/attachments"
  public_dns_servers: ["公共递归地址 1", "公共递归地址 2"]

iam:
  grpc_addr: ""           # IAM 的 gRPC 地址
  issuer: ""              # 成员登录态的签发者
  jwt_secret_env: "MAIL_JWT_SECRET"

im:
  grpc_addr: ""           # IM 的 gRPC 地址

alert:
  webhook_url: ""         # 空 = 不外发告警，只记日志
```

平台里服务之间调用用的凭据怎么取，照 service-file 的 iam_outbound.go 和 im_outbound.go 的做法，键名在 M1 核对后补进这里。

### 4.2 秘密

全部经环境变量注入，不进配置文件，不进镜像（X06-1、X06-2）。

| 环境变量 | 用途 | 使用方 |
|---|---|---|
| MAIL_DB_DSN | 控制面的数据库连接串 | service-mail |
| MAIL_DB_READER_PASSWORD | 只读账号的口令，渲染进 Postfix 和 Dovecot 的数据库配置 | service-mail 渲染，mailcore 使用 |
| MAIL_DB_DICT_PASSWORD | 配额字典账号的口令 | 同上 |
| MAIL_IMAP_MASTER_PASSWORD | Dovecot 主账号的口令 | service-mail 明文使用；启动时算出哈希交给 Dovecot |
| MAIL_RSPAMD_CONTROLLER_PASSWORD | Rspamd 控制接口的口令 | service-mail、rspamd |
| MAIL_HANDLE_SECRET | 邮件标识的签名密钥 | service-mail |
| MAIL_JWT_SECRET | 成员登录态的校验密钥，与平台共用 | service-mail |

### 4.3 启动前配置检查

`service-mail -config <文件> -check-config`，与正常启动用同一份加载和校验代码（O05-1）。检查项在平台通用的几项之外，本域增加：

| 检查 | 失败时的提示 |
|---|---|
| rpc_port、http_port 在 1 到 65535 | 端口非法 |
| dsn 或 MAIL_DB_DSN 至少有一个 | 数据库连接串缺失 |
| public_hostname 是合法域名，public_ip 是合法地址 | 对外主机名或公网地址缺失或格式非法 |
| 第 4.2 节的 7 个环境变量都非空 | 缺少的变量名。不回显任何取值 |
| iam.grpc_addr、im.grpc_addr 非空 | 内部依赖地址缺失 |
| 路径类的键都是绝对路径 | 路径非法 |
| policy_listen 不等于任何邮件协议端口 | 策略服务端口冲突 |
| 运行环境是 prod 时，imap_insecure_skip_verify 必须为假 | 生产环境不允许跳过证书校验 |

检查模式不连接数据库、不跑迁移、不监听端口、不生成任何密钥（O05-3）。通过退出码 0，失败非零。

部署脚本 `deploy/scripts/start.sh` 的顺序固定：渲染环境文件 → 用 service-mail 的镜像执行一次 -check-config → 执行迁移 → 启动其余服务（O05-4）。

## 5. 控制面启动时渲染的文件

| 文件 | 内容 | 读取方 |
|---|---|---|
| mail-config/postfix-*.cf | Postfix 各类映射的数据库查询参数：主机、库、账号、口令、查询语句 | Postfix |
| mail-config/dovecot-sql.conf.ext | Dovecot 查用户和密码的参数 | Dovecot |
| mail-config/dovecot-dict-sql.conf.ext | Dovecot 读写容量用量表的参数 | Dovecot |
| secrets/master/users | 主账号的口令哈希 | Dovecot |
| rspamd-local/dkim_signing.conf | 每个域用哪个选择器、私钥在哪里 | Rspamd |
| rspamd-local/whitelist.inc | 白名单映射 | Rspamd |
| rspamd-local/actions.conf | 垃圾阈值和灰名单开关 | Rspamd |
| mailcore 的清理任务 | 回收站和垃圾邮件的保留期 | 容器里的定时任务 |

数据库连接信息变化后需要重建 mailcore 容器（O01-2），因为 Postfix 和 Dovecot 只在启动时读这些文件。

## 6. 首次上线步骤

按顺序做，每一步有明确的完成标志。

1. **准备服务器**。按第 7 节放行端口。确认出站 25 端口可用：从服务器上连一个外部邮件服务器的 25 端口。
2. **准备数据库**。在平台 MySQL 上建 ppb_mail 库和 3 个账号，账号来源限制为邮件节点的内网地址。
3. **登记 DNS 的地址记录**。主机名的 A 或 AAAA 记录、PTR 反向解析。PTR 由服务器提供商的面板设置。等这两条生效再做下一步，因为申请证书要用到。
4. **填写配置和秘密**，执行 -check-config。
5. **只启动 migrate、service-mail、acme**。等 acme 把证书放到约定路径。看到证书文件后，再启动其余服务。
6. **启动全部服务**。确认 /healthz 返回 200，管理端的系统状态页各组件正常。
7. **添加第一个域**，在 DNS 服务商处配置 MX、SPF、DKIM、DMARC 四条记录，在管理端执行 DNS 校验，等到全部通过。
8. **配置第一个邮箱**，用标准客户端做收发验证：
   - 给外部邮箱发一封，对方收到，检查邮件头里 DKIM、SPF、DMARC 都是通过。
   - 从外部邮箱回一封，客户端收到。
   - 做负向检查，每一项都要看到预期的拒绝：
     - 未认证的连接向外部地址投递，被拒绝。这是开放中继检查，可以另外用网上的公开检测工具再查一次。
     - 认证用户用别人的地址作发件人，被拒绝。
     - 收件人不存在，被拒绝。
     - 停用的邮箱登录、收信、发信都被拒绝。
     - 超过单封大小上限的邮件，被拒绝。
     - 从公网连第 7 节以外的端口，连不上。
     - 从另一个容器连内部提交端口，被拒绝。
9. **小范围试运行**一到两周，再对全员开通。

| 143、993 | 公网 | IMAP |

## 8. DNS 记录

每个域需要四条记录，加上全局的两条。下面用文档专用的保留域名和地址举例，不是真实值。

| 类型 | 名称 | 值 | 何时配 |
|---|---|---|---|
| A 或 AAAA | mail.example.com | 192.0.2.10 | 上线前，全局一次 |
| PTR | 192.0.2.10 | mail.example.com | 上线前，由服务器提供商处设置 |
| MX | example.com | 10 mail.example.com | 添加域后 |
| TXT（SPF） | example.com | v=spf1 mx -all | 添加域后 |
| TXT（DKIM） | s202611._domainkey.example.com | v=DKIM1; k=rsa; p=<公钥> | 添加域后，轮换时新增 |
| TXT（DMARC） | _dmarc.example.com | v=DMARC1; p=none; rua=mailto:postmaster@example.com | 添加域后 |

- 四条记录的值在管理端的域详情页可以直接复制。
- SPF 用 mx，这样所有域指向同一台主机时不必每条都写地址。
- DMARC 初期用 p=none 并接收汇总报告，观察一段时间没有问题再改成 p=quarantine。这是对自己域的出站邮件而言；入站校验按对方域的策略执行。
- 可选项，对应 FP-C01：`_imaps._tcp` 和 `_submissions._tcp` 两条 SRV 记录，以及 autoconfig、autodiscover 两个子域。

## 9. 证书

- 用 ACME 客户端在服务器上自动申请和续期，验证方式是 HTTP-01，所以需要 80 端口（D05-2）。
- 证书域名是对外主机名。启用了 FP-C01 的自动配置文件时，把 autoconfig 和 autodiscover 两个子域加进同一张证书。
- 证书和私钥放在 secrets/tls 下，文件名固定为 fullchain.pem 和 privkey.pem。Postfix 和 Dovecot 共用这一张（D05-1）。
- 续期后各组件自动重新加载：控制面每 10 分钟读一次证书文件，发现内容变化就经运维代理重载 Postfix 和 Dovecot。
- 自签证书只能用于本地开发。线上没有正式证书时，mailcore 不启动（O01-6）。
- 80 端口开不了时，改用 DNS-01 验证。那需要在证书客户端里配置 DNS 服务商的接口凭据，属于部署时的变量，见第 15 节。

## 10. 备份与恢复

### 10.1 备份什么、放在哪

| 内容 | 位置 | 说明 |
|---|---|---|
| 邮件存储 | 数据卷 vmail | 整个目录 |
| ppb_mail 数据库 | 平台 MySQL | 用只读一致性快照导出一个 SQL 文件，随备份一起存 |
| DKIM 私钥目录 | secrets/dkim | 丢了就无法给之前的邮件验签，也无法解密历史备份之外的用途 |
| TLS 证书和私钥 | secrets/tls | 丢了可以重新申请，备份它是为了省一步 |

三点约束：

- **备份必须加密**，并且**保留 14 天**（O02-2）。
- **备份密钥与备份分开保管**（O02-2）。备份密码不放在这台服务器上。
- **备份要放到服务器之外**。O02-4 要求在一台新服务器上恢复，备份和服务器在同一块盘上做不到这一点。目的地用对象存储或另一台机器。

不在备份里的：Postfix 队列、Redis、日志。队列里的邮件是已接收但还没投出的出站邮件，整机损坏时这部分会丢。量很小（正常情况下队列接近空），这是已接受的取舍。

### 10.2 工具与计划

工具选 restic：自带加密、去重和保留策略，支持对象存储和 SFTP。选型在 M5 核对。

- 每天一次，服务器时间凌晨 3 点。
- 保留策略：保留最近 14 个每日备份。
- 每次备份后检查退出码。失败触发告警（O02-6）。
- 备份脚本在 ppb-mail/deploy/scripts/backup.sh，恢复脚本是 restore.sh。两个脚本都不把密码写在命令行里。

数据库和邮件存储不是同一瞬间拍的快照。恢复后执行一次用量重算，见 10.3。

### 10.3 恢复

**单个邮箱**（O02-3，5 GB 以内的邮箱 1 小时内完成）：

1. 从最近的备份里取出这个邮箱的目录，放到一个临时目录。
2. 用“不覆盖已有文件”的方式合并回现网的邮箱目录。合并必须在邮件核心容器里执行，或者以虚拟用户的身份执行，保证属主正确。
3. 让 Dovecot 重新计算这个邮箱的用量。
4. 用标准客户端或 IMAP 确认邮件都在。

**全量恢复**（O02-4，8 小时内恢复服务）：

1. 准备一台新服务器，按第 6 节的第 1、2 步准备。
2. 从备份恢复 secrets 数据卷，这样 DKIM 私钥和证书都是原来的，不用重新申请，DNS 也不用改。
3. 启动控制面，导入数据库备份。导入之后跑一次迁移，让表结构跟上当前版本。
4. 恢复 vmail 数据卷。
5. 让 Dovecot 重算全部邮箱的用量。
6. 把主机名的 A 记录指向新服务器。PTR 记录如果变了也要改。
7. 按第 6 节的第 8 步做收发验证。

**演练**：每季度一次，保留记录（O02-5）。演练至少做一次单邮箱恢复，全量恢复至少半年做一次。

## 11. 监控与告警

### 11.1 指标

控制面在 /metrics 上以 Prometheus 文本格式提供指标（O03-2），用平台现有的指标处理器。采集器抓取它做仪表盘。本域的指标：

| 指标 | 类型 | 含义 |
|---|---|---|
| mail_queue_messages | 度量 | 三类队列的长度 |
| mail_delivery_total | 计数 | 按方向和投递状态累计 |
| mail_auth_total | 计数 | 按协议和结果累计 |
| mail_spam_action_total | 计数 | 按处置结果累计 |
| mail_component_up | 度量 | 各组件是否存活，1 或 0 |
| mail_mailstore_bytes | 度量 | 邮件存储已用和总量 |
| mail_database_bytes | 度量 | 数据库用量 |
| mail_certificate_days_left | 度量 | 证书剩余天数 |
| mail_http_request_duration_seconds | 直方图 | HTTP 接口耗时，带路径模板 |
| mail_http_request_total | 计数 | 按路径模板和状态码累计 |
| mail_outbound_policy_total | 计数 | 策略服务的判定结果：放行、拒绝、超限 |

队列长度、组件状态、磁盘、证书这些每 30 秒采集一次的数据，指标直接读系统状态页用的那份缓存，不重复采集。

### 11.2 告警

控制面自己每 30 秒评估一次下列条件，满足并持续指定时间后，向配置的通知地址发一次 HTTP 请求。这样告警不依赖外部是否部署了监控系统。平台已经有监控栈的，也可以直接抓 /metrics 配同样的规则。

| 告警 | 条件 | 持续时间 |
|---|---|---|
| 投递积压 | 延迟重试队列超过 100 封 | 10 分钟 |
| 磁盘 | 邮件存储或数据库所在磁盘用量超过 80% | 立即 |
| 证书 | 剩余不足 15 天 | 立即 |
| 组件不存活 | Postfix、Dovecot、Rspamd、Redis、数据库任一不正常 | 1 分钟 |
| 认证攻击 | 同一来源地址 1 小时内认证失败超过 50 次 | 立即 |
| 备份失败 | 最近 26 小时内没有一次成功的备份，或备份脚本报错 | 立即 |
| 策略服务异常 | 策略端口监听不正常 | 立即 |
| 对账失败 | 账号对账连续 3 次失败 | 立即 |
| 日志采集停滞 | 采集器 5 分钟没有读到新的日志行，而系统里明显有流量 | 5 分钟 |

规则（O03-3 里没有的几条是本设计补充的）：

- 同一条告警 1 小时内不重复发送。
- 条件消除后发一条恢复通知。
- 通知的内容是：告警名、级别、当前值、阈值、时间、建议动作。
- 通知地址是配置项 alert.webhook_url。它接什么由部署时决定，见第 15 节。地址为空时告警只写服务日志和审计表。

## 12. 日志

| 日志 | 去向 | 保留 |
|---|---|---|
| 控制面服务日志 | 标准输出，由容器运行时收集，开启轮转 | 14 天 |
| Postfix、Dovecot 日志 | logs 数据卷下的文件，按大小轮转 | 7 天（O04-4） |
| 投递、登录、评分记录 | 数据库里的三张日志表 | 180 天、180 天、30 天 |
| 管理操作审计 | 数据库 | 365 天 |

- 服务日志里不出现秘密和完整的数据库连接串（X06-4）。写日志前统一过一个脱敏函数。
- 用主账号访问邮箱时，服务日志记录接口名和邮箱地址，不记录邮件内容。

## 13. 升级与回滚

| 步骤 | 做法 |
|---|---|
| 升级前 | 做一次备份（O06-1）。记下当前各组件的版本组合 |
| 测试环境 | 先在测试环境把新版本组合跑一遍第 6 节第 8 步的收发验证，重点确认配置格式兼容 |
| 生产升级 | 逐个组件替换镜像。顺序是 Redis、Rspamd、控制面、邮件核心。控制面先升级是因为它带迁移 |
| 记录 | 把版本组合记进运维记录（O06-4） |
| 回滚 | 回退到上一版本的镜像，执行迁移的回滚脚本（O06-3）。上一版本的镜像至少保留到下一次升级 |

控制面的迁移只增加表和列，所以旧版本的控制面在新的表结构上还能运行，回滚窗口内不影响收发（O06-2）。

## 14. 运维手册

手册在 M5 交付（O07-1），放在 ppb-mail/deploy/docs/runbook.md。内容按规则要求分六部分：上线前检查清单、日常巡检项、常见故障处置、备份恢复步骤、升级步骤、紧急联系人。

上线前检查清单的条目（O07-2、O07-4）：

- [ ] 每个域的 MX 记录已生效。
- [ ] SPF、DKIM、DMARC 记录已生效，管理端的 DNS 校验全部通过。
- [ ] PTR 反向解析已生效。
- [ ] 第 7 节的端口已放行，没有多放的。
- [ ] 从服务器出站连 25 端口可达。
- [ ] 服务器地址不在常见的实时黑名单里。
- [ ] 证书有效，剩余天数大于 30。
- [ ] 用标准客户端与外部邮箱双向收发成功，发出去的邮件三项校验都通过。
- [ ] 未认证的连接向外部地址投递被拒绝。
- [ ] 备份已配置，并且手工恢复过一个邮箱。
- [ ] 告警能送达。

每一条都要实际执行并留下执行记录。

常见故障的处置要点，先写在这里，M5 时并入手册：

| 故障 | 判断 | 处置 |
|---|---|---|
| 队列积压 | 系统状态页的延迟重试队列持续增长 | 看队列里的失败原因。多数是某一个目标域出问题，不影响其他域。必要时对选中的邮件执行重发 |
| 磁盘满 | 告警，或 Dovecot 报写入失败 | 清理已删除和垃圾邮件文件夹；找出用量最大的邮箱让用户清理；扩容数据盘 |
| 证书过期 | 告警 | 看 acme 容器的日志，常见原因是 80 端口不通或 DNS 验证失败。手动触发一次续期 |
| 被列入黑名单 | 发往某几家服务商的邮件被退回 | 查退信原因里的黑名单名称，到对应网站申请移除，同时排查是否有账号被盗用来发信 |
| 单个用户无法登录 | 登录日志里这个地址连续失败 | 依次看：邮箱状态、临时密码是否过期、客户端的服务器地址和端口、密码是否输错 |
| 正常邮件被判为垃圾 | 评分记录里能看到命中的规则 | 把发件人或发件域加入白名单 |
| 被盗号群发 | 认证攻击告警或出站量突增 | 关闭这个邮箱的外发权限，重置密码，删除队列里它发的邮件 |

## 15. 实现时要核对的事项

- [ ] Postfix、Dovecot、Rspamd、Redis 的镜像版本，以及邮件核心的基础镜像。
- [ ] 证书客户端选哪一个，续期后怎样把文件放到约定路径；DNS-01 验证需要哪些凭据。
- [ ] 备份工具的选型，以及备份目的地的类型和访问方式。
- [ ] 告警通知地址接的是什么系统，请求格式是什么。
- [ ] 平台服务之间调用用的凭据在配置里怎么取。
- [ ] 控制面的容器怎样同时接入邮件节点私有网络和平台内网。
- [ ] 邮件节点到平台内网的路由或隧道方案。
- [ ] 日志采集的“停滞”判定在低流量时段怎样避免误报。
