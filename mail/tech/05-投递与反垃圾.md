# 投递与反垃圾

> v0.2 草案；目标态设计，未实施。规则来源：[域名与收发](../pr/03-域名与收发.md)。本文列出必须落地的配置要点，具体配置文件在实施时按所选镜像的版本编写，并用真实邮件验证。

[需求基线](../PRD.md) · [域导航](../README.md)

## 1. 打包方式

Postfix 和 Dovecot 装在同一个镜像里，由进程管理器托管，在同一个容器里运行。原因：

- Postfix 的认证要经本地套接字转给 Dovecot。同容器不需要对齐两个容器里的用户标识。
- 投递用 LMTP，走容器内部的回环地址。
- 清理任务、运维代理都在这一侧，放在同一个镜像里最简单。

Rspamd 和 Redis 各用官方镜像。镜像版本在 M1 核对后写进本文。

## 2. Postfix

### 2.1 地址与域

| 配置项 | 取值 | 说明 |
|---|---|---|
| 接收的域 | 查域视图 | 见 [账号与认证](04-账号与认证.md) 第 4 节 |
| 有效邮箱 | 查邮箱视图 | 用于在收件人阶段判断地址是否存在 |
| 别名与转发 | 查别名视图 | 返回目标地址列表 |
| 发件地址归属 | 查发件地址视图 | 认证用户能用哪些地址作为 From |
| 收件人策略 | 查收件人策略视图 | 停用的邮箱返回“邮箱已停用” |
| 投递方式 | LMTP 到 Dovecot | 不使用本地投递 |
| 对外主机名 | 系统登记的主机名 | HELO 和退信用到 |

数据库映射用 MySQL 驱动，只读账号。

### 2.2 认证与中继

| 配置项 | 取值 |
|---|---|
| 认证类型 | 交给 Dovecot |
| 未加密连接上认证 | 禁止 |
| 认证机制 | PLAIN 和 LOGIN |
| 中继控制 | 本机或可信网络放行；已认证放行；其余如果不是发往本系统的域则拒绝 |

### 2.3 发件人伪造防护

开启“认证用户的 From 必须属于其登录账号”的检查，数据来自发件地址视图。不匹配时返回 554。

### 2.4 出站限额

| 配置项 | 取值 | 说明 |
|---|---|---|
| 限额检查 | 在收件人阶段调用控制面的策略服务 | 只对认证用户有意义 |
| 策略服务不可达时 | 放行 | 限额是防护措施，不能让它拖垮全员发信。不可达时控制面告警 |
| 策略服务超时 | 10 秒 | 超时按不可达处理 |

策略协议的细节见 [管理端设计](07-管理端设计.md) 第 3 节。

### 2.5 TLS

| 配置项 | 25 端口 | 587 端口 | 465 端口 |
|---|---|---|---|
| 加密 | 支持 STARTTLS，不强制 | 强制 STARTTLS | 隐式 TLS |

出站连接支持 STARTTLS，对方支持就加密。最低版本 1.2。证书从挂载目录读取，续期后由进程管理器重新加载。

### 2.6 过滤接口

Postfix 把每封邮件交给 Rspamd 过滤。过滤服务故障时按通过处理，并在投递日志里体现。

Dovecot 在投递时自己发出的邮件也要经过这道过滤，这样自动回复和过滤规则里的转发才会被签名（S05-1）。这类邮件不从 SMTP 进来，要单独开启对非 SMTP 投入的邮件调用过滤接口。

### 2.7 限制与队列

| 配置项 | 建议值 |
|---|---|
| 单封大小上限 | 50 MB |
| 每封收件人上限 | 200 |
| 最长排队时间 | 3 天 |
| 重试间隔 | 默认，从 5 分钟逐步加到约 1 小时 |
| 同一客户端的连接频率 | 每分钟 30 次 |
| 同一客户端的认证频率 | 每分钟 20 次 |
| 同一客户端的发信频率 | 每分钟 50 封 |

### 2.8 内部可信提交端口

控制面通过一个只在私有网络监听的端口提交邮件，这个端口：

- 不做认证，不做 TLS。
- 只允许控制面所在容器的地址访问，其他来源一律拒绝。
- 告诉过滤服务这是本系统发出的邮件，需要做 DKIM 签名。
- 发件人归属的校验由控制面在提交前完成。

### 2.9 日志

Postfix 把日志写到共享日志目录下的文件，不走系统日志。控制面从这个文件读取投递记录。

## 3. Dovecot

### 3.1 存储与投递

| 配置项 | 取值 |
|---|---|
| 邮件格式 | Maildir++ |
| 每个邮箱的目录 | 按域名和账号名分层 |
| 系统用户 | 统一用一个虚拟用户读写所有邮箱 |
| LMTP 监听 | 容器内部回环地址的 24 端口 |
| 认证套接字 | 容器内部，供 Postfix 使用 |

### 3.2 认证

| 配置项 | 取值 |
|---|---|
| 密码来源 | 密码视图 |
| 用户信息来源 | 用户视图，含目录、系统用户和组、配额 |
| 主账号 | 启用，只允许控制面所在网段使用 |
| 明文认证 | 禁止，除非连接已加密 |
| 认证失败惩罚 | 开启 |
| 认证日志 | 记录成功和失败，含来源地址和失败原因。管理端显示的最近登录时间和来源由控制面从登录日志得到 |

### 3.3 IMAP 与 POP3

| 配置项 | 取值 |
|---|---|
| IMAP | 143 端口支持 STARTTLS，993 端口隐式 TLS |
| POP3 | 默认关闭，由全局设置控制 |
| 协议扩展 | 保持默认，包含空闲推送、增量同步、移动、特殊用途文件夹 |

### 3.4 标准文件夹

每个邮箱自动创建收件箱、已发送、草稿、已删除、垃圾邮件五个标准文件夹，并标记特殊用途。

- 自动创建用 Dovecot 的邮箱自动创建配置，不靠脚本。邮箱第一次被访问时创建。
- 标准文件夹不能删除或重命名（S15-3）。用 Dovecot 的全局访问控制列表把这两个权限从这五个文件夹上拿掉。这样标准客户端和 HTTP 接口都删不掉它们。
- 五个文件夹在 Dovecot 内部的名字固定为 INBOX、Sent、Drafts、Trash、Junk。

### 3.5 配额

| 配置项 | 取值 |
|---|---|
| 配额来源 | 每个邮箱的配额值，由用户视图给出 |
| 用量记录 | 写在 ppb_mail 库的一张表里，由 Dovecot 维护 |
| 超限行为 | 拒收新邮件，返回 552 |
| 预警 | 控制面每天检查一次用量表，达到 90% 且 7 天内没提醒过的，发一封提醒（M11-4）。见 [管理端设计](07-管理端设计.md) 8.6 |

### 3.6 投递时的脚本

邮件入箱前，Dovecot 依次执行：

1. 全局脚本：邮件头标记为垃圾的，放进垃圾邮件文件夹。
2. 用户脚本：由控制面根据用户的过滤规则和自动回复生成。

脚本存放在独立的 Sieve 目录，生成和写入流程见 [成员接口设计](06-成员接口设计.md) 第 8 节。

### 3.7 自动清理

容器里每天运行一次清理，把已删除文件夹和垃圾邮件文件夹里超过保留期的邮件删除。保留期读全局设置，由控制面渲染进清理脚本。

### 3.8 日志

Dovecot 把日志写到共享日志目录下的文件。

## 4. Rspamd

| 配置项 | 取值 | 说明 |
|---|---|---|
| 过滤接口 | milter，监听私有网络 | Postfix 调用 |
| 控制接口 | 私有网络，凭密码访问 | 控制面用来查询历史记录和重载映射 |
| 拒收线 | 15 分 | 可配置 |
| 标记线 | 6 分 | 可配置 |
| 灰名单线 | 4 分，可关闭 | 可配置。评分过了这条线、又不到拒收线的来信都会被暂时拒收（实测 7.5 分、8.8 分的也是，不只是 4 到 6 分）。关闭的办法是给 Rspamd 写一份 `greylist.conf`（一行 `enabled = false;`）并让它重读配置；把灰名单线写成空值关不掉，反而让「加头」的来信全被灰名单 |
| 垃圾标记方式 | 在邮件头加标记 | Dovecot 据此投到垃圾邮件文件夹 |
| 历史记录 | 存在 Redis | 控制面定期读取并入库 |
| 入站校验 | SPF、DKIM、DMARC | 默认开启 |
| DMARC 拒绝策略 | 发件域策略为拒绝且校验失败时拒收 | |
| 出站签名 | 本系统域发出的邮件用发件域的密钥签名 | 密钥在密钥目录，按域名和选择器存放 |
| 白名单 | 由控制面渲染为文件映射 | 映射文件改了（先写临时文件再改名）马上生效，不用调控制接口（实测） |
| 病毒扫描 | 可选，连接 ClamAV | 由全局设置控制 |
| 转发改写 | **已核对：Rspamd 没有这个模块，现状是不改写** | 原设计是转发到外部地址的邮件改写信封发件人。实测转发出去的邮件保持原发件人、不带本系统的签名；不改写的话，收件方按原发件域做校验会不通过，转发邮件容易被判为垃圾或拒收。要不要另加改写的组件，见 [PRD](../PRD.md) 第 11 节第 8 项 |
| 签名配置、白名单、阈值 | 由控制面渲染 | 见 [管理端设计](07-管理端设计.md) 第 9 到 11 节 |

说明：

- 发件人归属的强制校验在 Postfix 一侧完成。Rspamd 的“认证用户名必须与发件人匹配”检查要放宽，否则别名地址发出的邮件不会被签名。
- 垃圾阈值、灰名单开关做成全局设置项，由控制面渲染进配置并重载。阈值可以经控制接口在线改；`actions.conf`、`dkim_signing.conf`、`greylist.conf` 改了之后要给 Rspamd 的主进程发 HUP 才生效，控制面做不了这一步（控制接口没有「重读配置」的路径），是运维动作。
- 垃圾邮件的标记头是 `X-Spam: Yes`；Dovecot 的全局脚本用 `sieve_before` 挂，在用户脚本之前执行。

## 5. 黑名单与白名单的生效路径

| 名单 | 生效位置 | 效果 |
|---|---|---|
| 黑名单 | Postfix 的发件人检查，数据来自黑白名单视图 | 入站邮件发件人命中时拒收 |
| 白名单 | Rspamd 的映射文件 | 入站邮件发件人命中时跳过垃圾评分 |

两者都在 1 分钟内生效。

## 6. 退信

退信由 Postfix 生成。控制面不做额外处理，但把退信作为一条投递记录入库，方向为出站、收件人为原发件人、状态为退信。

## 7. 实现时要核对的事项

2026-11-25 到 26 由邮件核心那一轮在真实的 Postfix 3.7.11、Dovecot 2.3.19.1、Rspamd 4.3.0 上逐项核对，逐条的结论和证据在 ppb-mail 仓的 `docs/verification/M1-技术核对.md`。这里只写和本文有关的结论：

- [x] 镜像里 Postfix 和 Dovecot 的版本：Postfix 3.7.11、Dovecot 2.3.19.1。JSON 格式的队列输出可用（一行一个对象，没有方向字段，也没有重试次数）；策略服务不可达时放行的配置项存在；主账号能登录，但用户查询要多返回一列 `acl_user` 才能打开邮箱（访问控制插件的原因，已修）。
- [x] Postfix 日志直接写文件可用（`maillog_file`），用 `postfix logrotate` 轮转，旧文件是「原文件名加时间戳」。
- [x] Dovecot 把配额用量写入 MySQL 可用。**但正式编排下有一个上线前必须修的问题**：配额字典进程不是 root，按约定的权限读不了它的配置文件，投递会失败（核对文档第 5 节）。
- [x] Rspamd 对 DMARC 拒绝策略可以配；映射文件改了就生效；**没有转发改写的模块**（见第 4 节的表）。
- [x] 禁止删除和重命名标准文件夹的全局访问控制列表可用。
- [x] 垃圾邮件标记头的名字是 `X-Spam: Yes`。
- [x] 内部可信提交端口在容器网络下按来源地址限制到控制面一个地址，别的地址第一条命令就被拒。
- [ ] 自动回复的 DKIM 签名验证不过（核对脚本 F8.1b），原因在查；查清之前不能当成自动回复的签名有效。
