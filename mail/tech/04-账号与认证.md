# 账号与认证

[需求基线](../PRD.md) · [域导航](../README.md)

## 1. 账号模型

| 概念 | 说明 |
|---|---|
| 邮箱账号 | 与一个 IAM 用户一一对应。有主地址、密码、状态、配额、外发权限 |
| 主地址 | 账号名加域。一个邮箱只有一个 |
| 别名 | 另一个地址，来信投到同一个邮箱，也能作为发件地址 |
| 邮域 | 邮箱账号属于一个域。别名可以属于别的域 |
| 邮箱密码 | 只用于登录邮件协议，与 IAM 登录凭证无关 |

一个 IAM 用户最多一个邮箱账号。这是硬约束，由数据库唯一索引保证。

## 2. 开通与同步

### 2.1 手动开通

管理员在管理端提交：用户、域、账号名、初始密码。控制面校验用户存在且状态正常、账号名合规且未被占用，然后写入账号记录，再用主账号经 IMAP 登录一次这个新邮箱，让 Dovecot 在此时创建邮件目录和标准文件夹。完整的步骤见 [管理端设计](07-管理端设计.md) 8.1。

### 2.2 自动开通范围

全局设置里的“自动开通范围”决定谁自动获得邮箱：

| 取值 | 自动开通的对象 |
|---|---|
| 指定组织的成员（默认） | 设置里列出的组织的全体成员 |
| 手动开通 | 不自动开通 |
| 全部 IAM 用户 | 所有状态正常的 IAM 用户 |

### 2.3 对账

对账任务默认每 10 分钟跑一次，流程：

1. 取期望集合。按自动开通范围，从 IM 取指定组织的成员，或从 IAM 取全部用户。**「指定组织的成员」在当前平台用不了**，见 2.4。
2. 取现有集合。从本地数据库取全部未彻底删除的邮箱账号。
3. 查这些账号对应用户在 IAM 的状态。
4. 计算差异并执行：

| 情况 | 动作 |
|---|---|
| 在自动开通范围内，但没有邮箱 | 创建邮箱账号 |
| IAM 用户停用 | 邮箱转停用 |
| IAM 用户恢复，且管理员没有单独停用这个邮箱 | 邮箱恢复正常 |
| IAM 用户注销 | 邮箱转待删除，开始计算保留期 |
| 其他 | 不处理 |

5. 把本次的开始时间、耗时、各类数量和错误写入同步记录。

对账可重复执行。单条失败不影响其他条目，失败的在下次对账时重试。

### 2.4 需要的 IAM 和 IM 能力

| 需求 | 现有契约 | 说明 |
|---|---|---|
| 查单个用户的状态 | IAM 的 InspectAccount | **已核对（2026-11-26）。** ResolveUser 已退役（一律回 InvalidArgument），只剩 InspectAccount 一条路；它是供给面的接口，要内部凭据加管理员的 IAM 断言（出站连接挂平台的断言拦截器，ctx 里带管理员的身份）。后台任务没有管理员身份，不能用它 |
| 分页取全部用户 | IAM 的 ListUsers | **已落地（2026-11-26，ppb-iam 的分支上，没有合并）。** 按用户标识游标分页，每页最多 1000，只回用户标识、状态、更新时间，只认内部凭据；注销的用户（状态 3）也返回。翻页不是快照 |
| 取指定组织的成员 | IM 的 ListMembers | **已核对（2026-11-26）：用不了。** 它是 IM 的管理接口，要 chat 域的 member.read 和管理员身份，对账是后台任务，调它会被拒。聊天产品转向 C 端之后组织管理面也退役了。所以「按组织开通」和「指定组织的成员」这个自动开通范围在当前平台没有可用的数据来源，默认值（组织列表为空）等于不自动开通。要不要保留这两个功能，见 [PRD](../PRD.md) 第 11 节 |
| 成员标识换用户标识 | IM 的 ResolveMemberIds | 已核对：入参是成员标识的十进制串，应答按入参序给用户标识。名字相近的 ResolveMembersByIds 方向是反的（按用户标识查） |

新增的 IAM 接口按供给类接口的先例做服务身份校验。动手前先读 contracts-iam 里现有供给类 RPC 的鉴权方式。

## 3. 邮箱密码

### 3.1 生成与存储

- 密码由控制面校验和哈希后写入账号记录。邮件组件只读哈希。
- 哈希格式：首选 Argon2id。镜像里的 Dovecot 不支持时用 SHA512-crypt，迭代不少于 20 万次。M1 时在镜像里运行 `doveadm pw -l` 确认支持列表，并把结果写回本文。
- 临时密码带过期时间。过期后登录视图里不再有这个账号，登录即失败。

### 3.2 密码的几种来源

| 场景 | 流程 |
|---|---|
| 管理员开通时设置初始密码 | 管理员输入，或系统生成临时密码并只显示一次 |
| 管理员重置密码 | 系统生成 12 位以上随机临时密码，只显示一次，7 天有效 |
| 用户修改密码 | HTTP 接口，需要提供当前密码，校验密码策略和历史 |
| 自动开通的邮箱 | 没有可用密码。用户通过 HTTP 接口设置初始密码后，才能用标准客户端登录 |

自动开通的邮箱要靠成员界面来设置初始密码。成员界面上线之前，管理员可以用重置密码给这类邮箱生成临时密码，用户拿到后就能登录标准客户端。

### 3.3 设置初始密码的鉴权

自动开通的邮箱设置初始密码时没有“当前密码”可校验，只能依靠成员登录态。为防止登录态被盗用后被人抢先设置邮箱密码：

- 要求成员登录态是近期认证过的，具体复用 IAM 的重新认证机制，M3 时核对现成接口。
- 设置成功后，给该用户在 IAM 的登录邮箱发一封通知。

## 4. 邮件组件如何取得账号数据

Postfix 和 Dovecot 不调用控制面，而是用只读账号直接查数据库视图。控制面只写表，视图由数据库维护。

| 视图 | 使用方 | 用途 |
|---|---|---|
| 域视图 | Postfix | 判断一个域是否由本系统接收 |
| 邮箱视图 | Postfix | 判断一个地址是否是有效邮箱 |
| 别名视图 | Postfix | 把别名和转发解析成目标地址 |
| 发件地址视图 | Postfix | 认证用户允许使用哪些地址作为 From |
| 收件人策略视图 | Postfix | 停用和待删除的邮箱收到信时拒绝，并给出提示 |
| 黑名单视图 | Postfix | 发件人黑名单。白名单不经过数据库，由控制面渲染成 Rspamd 的映射文件 |
| 容量用量表 | Dovecot 配额插件 | 每个邮箱的已用量。Dovecot 用一个专用账号读写这一张表 |
| 用户视图 | Dovecot | 地址对应的存储目录、系统用户和组、配额 |
| 密码视图 | Dovecot | 地址对应的密码哈希，只含状态正常且临时密码未过期的账号 |

要点：

- 邮箱视图只包含状态正常的邮箱。停用、待删除的邮箱从邮箱视图移除，由收件人策略视图返回“邮箱已停用”的拒绝信息。
- 发件地址视图里，每个登录账号对应它的主地址和全部别名。Postfix 用它防止伪造发件人。
- 别名视图的返回值是逗号分隔的目标地址。转发且保留副本时，返回值是邮箱主地址加转发地址。
- 给 Postfix 和 Dovecot 的数据库账号只有这些视图的只读权限。
- 所在域停用时，域里的邮箱从所有视图里消失，域本身也从域视图里消失。所以停用一个域等于停用它下面全部邮箱的登录、收信和发信（D01-2）。
- 别名自己所在的域停用时，这个别名不再解析，也不能再作发件地址。
- 临时密码过期的账号仍然在邮箱视图里，能收信；不在密码视图里，不能登录。

## 5. 控制面访问邮箱的方式

控制面通过 IMAP 访问邮箱，用 Dovecot 的主账号机制：

- Dovecot 配置一个主账号，用户名和真实用户之间用星号分隔，主账号口令正确即可登录任何邮箱。
- 主账号只允许从控制面所在的网段连接。
- 主账号口令在部署时生成，保存在密钥目录：一份明文给控制面用，一份哈希给 Dovecot 用。文件权限只允许各自的服务读取。
- 控制面每次用主账号访问邮箱都在服务日志里记录：哪个接口、哪个邮箱、什么操作。

这部分能力只能被成员接口调用，不能被管理接口调用，见 [管理端](../pr/06-管理端.md) 的 FP-G18。

## 6. 认证流程

### 6.1 SMTP 提交认证

1. 客户端在 TLS 连接上提交邮箱地址和密码。
2. Postfix 把认证请求通过本地套接字转给 Dovecot。
3. Dovecot 查密码视图，比对哈希。
4. 成功和失败都写认证日志。

Postfix 和 Dovecot 在同一个容器镜像里，套接字在容器内部，不存在跨容器的用户标识对齐问题。

### 6.2 IMAP 登录

客户端直接连 Dovecot 认证。流程同上，不经 Postfix。

### 6.3 生效时间

账号、别名、密码、状态的修改写入数据库后即被视图反映，邮件组件不做额外缓存。规则里写的“1 分钟内生效”留有余量。

有一个例外要知道：已经用标准客户端登录的会话，不会因为邮箱被停用而立刻断开。Dovecot 只在登录时查一次账号，之后要到下次登录才会被拒。需要立刻切断某个账号时，除了停用邮箱，还要经运维代理重载 Dovecot，让现有连接全部重新登录。这个操作记在运维手册里。

## 7. 实现时要核对的事项

- [ ] 镜像里 Dovecot 支持的密码哈希格式。
- [ ] Dovecot 主账号的配置方式，以及限制来源网段的配置项。控制面的容器在 Dovecot 看来是容器网络里的地址，限制条件要按它来写。
- [ ] 容器内部用对外主机名校验证书的做法能否走通：控制面连的是容器名加端口，证书签给的是对外主机名。
- [ ] 停用邮箱后让现有会话立刻失效的办法：重载 Dovecot 是否足够，有没有更细粒度的做法。
- [ ] Postfix 各类映射的查询模板写法，特别是收件人策略视图返回自定义拒绝信息的方式。
- [ ] Dovecot 用户视图需要返回的全部字段。
- [ ] IAM 现有供给类 RPC 的鉴权方式，作为新增内部清单接口的参照。
- [ ] IM 的 ListMembers 请求里组织标识的取值。
