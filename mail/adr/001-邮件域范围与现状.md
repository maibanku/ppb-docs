# ADR-001 邮件域范围与现状

状态：范围已拍板，2026-11-24。设计细节待评审。本稿记录决定和仍然开放的事项。

[域导航](../README.md)

## 1. 背景

邮件域此前没有独立文档。2026-11-24 核对后的现状：

- 旧的邮箱收发域（server-mail）已于 2026-10-10 移除。它是一个站内邮箱：成员之间互发，经中继向外部外发，不能接收外部来信。工作区里没有它的服务源码，只留下表结构、配置和契约字段等残留。
- 运行中的只有 IAM 的验证码邮件，共三类。它的投递有缺口：没有超时、投递记录分不清是否真发、记录与实发内容不一致。
- 关于邮件域的说法有三种并存：外部独立部署、已移除、冻结归档。

## 2. 决定

### 2.1 此前已有的决定

| 事项 | 结论 | 时间与出处 |
|---|---|---|
| 邮箱收发移除 | 删除契约、服务模块和网关路由 | 2026-10-10，ppb-base 提交 4cbee90 |
| 邮件域落点 | 个人邮件配置迁到用户偏好；邮箱账号表与旧邮件日志冻结只读至退役归档 | 2026-10-28，[IAM 架构决策](../../iam/adr/架构决策.md) ADR 第 3 条 |

### 2.2 2026-11-24 拍板

| 事项 | 结论 |
|---|---|
| 是否重建邮箱 | 重建，作为完整的邮箱系统 |
| 收发范围 | 自建公网收发，不接第三方邮件服务 |
| 服务器核心 | 成熟组件 Postfix、Dovecot、Rspamd，加自研控制面 |
| 成员收发方式 | 标准邮件客户端和 HTTP 接口都支持 |
| 使用对象 | 企业全员，数百到数千人 |
| 本阶段客户端 | 只做后端和管理端，不做成员界面 |
| 部署条件 | 已有公网服务器、固定 IP 和域名 |

## 3. 邮箱收发域去向的选项回顾

| 方案 | 优势 | 代价 | 结论 |
|---|---|---|---|
| A 维持下线并清理残留 | 工作量小，风险低 | 员工没有企业邮箱 | 不采用 |
| B 按原设计重启站内邮箱 | 能内网互发 | 不能收外部来信；要先解决四项设计债；实际上满足不了需求 | 不采用 |
| C 完整互联网邮箱，自建 | 数据自主，与平台账号打通，HTTP 接口可控 | 运维和信誉管理的责任在自己；周期以月计 | 采用 |
| D 完整互联网邮箱，接第三方 | 无运维负担 | 有费用；数据不在自己手里；成员的收发方式受服务商限制 | 不采用 |

建档时给过的建议是 A，有邮箱需求时优先评估 D。决定是 C。理由是部署条件已经具备，并且希望邮件数据留在自己手里。自建的两个主要风险写在这里，供实施时盯住：

- **送达信誉。** 新服务器的地址没有信誉积累。上线初期的 SPF、DKIM、DMARC 配置和 PTR 反向解析必须一次做对，否则发出去的邮件容易进垃圾箱。验收里为此单列了 MAC-25 和上线前检查清单。
- **运维责任。** 备份、监控、升级、故障处置都要自己做。这是 M5 的主要内容。

## 4. 旧残留怎么处理

重建之后，旧残留分成三类：

| 残留 | 处置 | 什么时候 |
|---|---|---|
| ppb-base/deploy/route-manifest.yaml 里的 mail 条目 | 改成启用，指向新的仓库和契约 | M1 |
| ppb-base/deploy/scripts/start-all.sh 里的 mail 相关行 | 改造成启动新的控制面，加配置门禁。MAIL_DB_DSN 这个环境变量名沿用 | M1 |
| ppb-base/deploy/config/mail.yaml | 删除。它指向已经不存在的模块 | M5 |
| ppb-file 的 MailAddr 死配置 | 删除。它指向旧端口 9103，新服务不用这个端口 | M5 |
| ppb-file 的上传场景 mail-attachment 和引用类型 refType=2 | 新设计里邮件附件不经文件服务，这两个取值仍然用不到，下线。下线前确认没有历史数据依赖 | M5，待确认 |
| orgcompat.proto、common.proto 里的邮箱字段和注释 | 本期不恢复它们的含义。契约变更单独一个批次，先确认有没有调用方 | 待定 |
| ppb-base/deploy/sql/ppb_mail 和 ppb_user 下的旧表 | 保持归档，不删除。新系统用的是新建的 ppb_mail 库，不能和旧表混在一起，上线前确认旧库已归档或改名 | 上线前 |
| ppb-docs/infra/config-structure-design.md、ppb-base/deploy/README.md、P8-SWITCH.md 第 8 节、ppb-chat/docs/README.md | 改成统一的口径 | M5 |
| ppb-chat/chat-desktop 的旧截图 email-code.png | 删除 | M5 |

一个要小心的地方：新系统的库名也叫 ppb_mail，和旧表的归档目录同名。如果旧表还留在某个环境里，迁移脚本会撞上它们。上线前检查清单里要有“确认旧表已归档”这一条。

## 5. 文档口径

关于邮件域，统一成一句话：

> 旧站内邮箱已于 2026-10-10 下线。新的自建邮箱系统按 ppb-docs/mail 的文档建设，目前是设计阶段，尚未上线。系统通知邮件由 IAM 承担。

第 4 节列的几处文档在 M5 改成这个说法。
