# ADR-005 与平台集成

状态：设计决定，2026-11-24，待评审。涉及其他仓库的改动都要在各自的仓库里走正常流程。

[域导航](../README.md)

## 1. 代码放在哪里

**决定：新建仓库 ppb-mail，和 ppb-file、ppb-iam 平级。不放回 ppb-base。**

- 结构遵循 [后端服务内部目录规范](../../architecture/05-后端服务内部目录规范.md)。参照的对象是 ppb-file：服务、契约、管理端插件、部署物料各占一个目录。
- HTTP 契约的 JSON 放在 contracts-mail/api。这是 file 和 camera 已经采用的最新做法，一个契约只有一个归属地。
- 工作区里已经有一个空的 ppb-mail/ui 目录，不是本设计创建的。建仓前先确认它的用途。

## 2. 端口

| 用途 | 端口 | 说明 |
|---|---|---|
| 控制面的 gRPC | 9108 | 接在平台的端口序列之后：IM 9102、File 9104、Camera 9106、IAM 9107 |
| 控制面的 HTTP | 9118 | 同上 |
| 控制面的可信提交 | 10028 | Postfix 在私有网络里另开的一个端口 |
| 出站限额的策略服务 | 11433 | Postfix 访问控制面的文本行协议 |

旧的 mail 服务用过 9103 和 9113，本设计不复用。原因是旧端口还在残留配置里被引用：ppb-file 里有一个指向 127.0.0.1:9103 的死配置。复用的话，这个死配置会意外地连上新服务。

## 3. 部署形态

**决定：控制面和邮件组件一起，用 Docker Compose 部署在邮件节点上。**

平台的现有服务是以宿主机进程的方式启动的，由 start-all 脚本管理。邮件的控制面不这么做，有三个原因：

- 它要读邮件节点上的日志目录和密钥目录，要连运维代理的套接字，要在容器网络里访问 Dovecot。和邮件组件在同一个编排里最直接。
- 邮件节点是一台独立的公网服务器，和平台现有的内网服务器不是同一台。
- 配置门禁的做法不变：启动前先用控制面的镜像执行 -check-config。

后果：控制面的容器同时接入两个网络，邮件节点的私有网络和平台内网。这个网络怎么打通是部署时的事，见 [部署与运维](../tech/10-部署与运维.md) 1。本地开发时可以不打包镜像，用同一个二进制作为本机进程启动，配置门禁的做法不变。

**控制面只支持 MySQL，不支持 SQLite。** 平台的一些服务在开发环境可以用 SQLite，邮件的不行，因为 Postfix 和 Dovecot 要通过数据库视图读账号。开发环境也要有一个 MySQL。

## 4. 网关

- 网关继续做透明代理，不解析邮件。成员接口和管理接口都以契约 JSON 的方式登记路由，做法同 file。
- 邮件协议的端口不经过网关，由 Postfix 和 Dovecot 直接对公网监听。
- 网关里要加一条流式直转的车道，走四个路径：附件上传、附件下载、原邮件下载、投递日志导出。做法照已有的文件传输车道。
- ppb-base/deploy/route-manifest.yaml 里的 mail 条目从停用改成启用。

## 5. 身份

- 成员接口用平台的成员登录态。登录态里的主体是成员标识，控制面经 IM 把它换成用户标识，再找邮箱。
- 成员网页客户端在浏览器里走 OIDC 授权码加 PKCE，访问令牌放内存、刷新令牌放 sessionStorage。平台里还没有浏览器持有成员凭据的先例，这是本决策新开的口子，需要登记 OIDC 客户端并把网页的源加进 IAM 的跨源白名单。
- 管理接口用平台的管理端登录态。网关做权限前判，控制面向 IAM 复检。
- 服务之间调用 IAM 和 IM 的方式，照 service-file 里的出站配置做。

## 6. 管理端

- 新建插件 mail-manage-web，基于 base-manage-web，本地开发端口 8274。原定 8270，但衣橱的 Go 后端已经占了它；成员网页客户端用 8273。
- 接入平台管理门户，和 chat、camera、file、iam 的插件并列。
- 管理端的请求走 IAM 的业务桥：浏览器带 Cookie 请求 IAM，业务桥换成带签名的断言头再按路径前缀转给业务服务。业务桥现在只认 file 和 camera 两个前缀，其余都转给 IM，所以要加一条 mail 的前转。这是 ppb-iam 的改动。
- IAM 验证码邮件的“推送记录”页留在原处。它属于 IAM 的功能，不在邮件插件里重复。

## 7. 错误码与权限点

- 错误码用平台给邮件域预留的 MAIL 前缀。
- 权限点用 mail. 开头的 19 个，见 [管理端](../pr/06-管理端.md) 的 FP-G16。它们在 IAM 里的登记方式在 M4 核对。
