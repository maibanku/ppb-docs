# ADR-002 邮件服务器核心选型

状态：方向已拍板，2026-11-24。组件版本和镜像基线在 M1 核对后补记。

[域导航](../README.md)

## 1. 要决定什么

邮件的收、发、存，用现成的软件还是自己写；如果用现成的，选哪几个，自己写的部分做什么。

## 2. 选项

| 方案 | 优势 | 代价 | 结论 |
|---|---|---|---|
| 自研邮件协议栈 | 完全可控，只有一种技术栈 | SMTP、IMAP、POP3、MIME 和各种客户端的怪癖，兼容性要靠多年积累；安全面巨大，任何疏漏都是被人中继或入侵的入口 | 不采用 |
| 成熟组件加自研控制面 | 协议兼容和安全性由成熟项目保证；自己只写业务部分 | 要运维多个组件；集成点不少：数据库视图、日志文件、策略协议、运维代理 | 采用 |
| 一体化邮件套件 | 开箱即用，自带管理界面和反垃圾 | 自带一套账号体系和管理台，和平台统一身份对接要绕；界面风格与平台管理端不一致；体量大，升级节奏不由自己掌握 | 不采用 |
| 第三方企业邮箱或邮件服务商 | 没有运维负担 | 有费用；数据不在自己手里；成员的收发方式受服务商约束 | 不采用，用户已排除 |

## 3. 决定

| 部分 | 选择 |
|---|---|
| 收发和投递 | Postfix |
| 邮箱存储和 IMAP、POP3 | Dovecot |
| 垃圾评分、入站校验、出站签名 | Rspamd，配 Redis |
| 病毒扫描 | ClamAV，可选 |
| 业务逻辑 | 自研的 service-mail，叫控制面 |
| 容器里的运维操作 | 自研的小程序 mailops，只做白名单命令 |

几条配套的决定：

- **Postfix 和 Dovecot 放在同一个镜像里。** Postfix 的认证要转给 Dovecot，投递走 Dovecot 的本地投递接口。放在一个容器里，这些都在容器内部，不存在跨容器对齐系统用户的问题。
- **邮件组件取账号数据用数据库视图，不调用控制面。** Postfix 和 Dovecot 自带的就是数据库查询。让它们反过来调控制面的接口，要多写一层桥接，还多一个故障点。控制面只写表。
- **控制面不解析邮件协议。** HTTP 接口的读操作是控制面作为 IMAP 客户端去访问 Dovecot；发送是控制面作为提交者把邮件交给 Postfix。
- **需要进容器执行的操作经运维代理，不挂 Docker 套接字。** 控制面一旦能访问 Docker 套接字，就等于能控制宿主机上的所有容器。
- **日志靠读文件采集。** Postfix 和 Dovecot 把日志写进共享目录，控制面读。另一种做法是让它们把日志直接发到 syslog 服务器再转进来，链路更长，出问题更难查。

## 4. HTTP 接口怎么读写邮件

这是本决策里最大的子选择。

| 方案 | 优势 | 代价 | 结论 |
|---|---|---|---|
| 控制面直接读写邮件目录里的文件 | 最快，没有网络往返 | 绕过 Dovecot 的索引和锁，两边同时写会损坏邮箱；文件夹、标记、配额的规则都要自己重新实现一遍 | 不采用 |
| 控制面作为 IMAP 客户端访问 Dovecot | 永远和标准客户端看到同一份数据；锁、索引、配额都由 Dovecot 负责 | 每个请求多一到几次本机网络往返；每个请求要登录一次 | 采用 |

后果，实施时要接受或者验证：

- 读接口的性能上限取决于 IMAP 的往返次数。NFR-M04 给了指标，M3 要实测。
- 每个请求都登录一次 Dovecot。本机登录的开销很小，但会在 Dovecot 的日志里留下大量主账号登录，采集器要把它们排除在登录日志之外。
- 控制面停了不影响已经用标准客户端登录的用户，因为标准客户端不经过控制面（NFR-M05）。

## 5. 不在本期范围

- 多节点和高可用。单节点，靠备份恢复保证可用性。
- 邮件归档和取证。
- 成员用的网页或桌面邮箱界面。

## 6. 实施前要核对的

这些结论建立在成熟组件的常规能力上。具体版本的行为要在 M1 逐项核对，清单在各技术设计的末尾：[投递与反垃圾](../tech/05-投递与反垃圾.md)、[账号与认证](../tech/04-账号与认证.md)、[管理端设计](../tech/07-管理端设计.md)、[部署与运维](../tech/10-部署与运维.md)。核对之后如果某一项不成立，改动记录在本文件的新版本里。

## 7. 依据

- Postfix、Dovecot、Rspamd 都是各自领域长期维护的主流开源软件。
- 平台现有的部署方式是 Docker Compose，邮件组件都有官方镜像或者可以在 Debian 基础镜像上安装。
- 规模要求：3000 用户以内，单节点，见 [PRD](../PRD.md) 第 3 节、第 8 节。
