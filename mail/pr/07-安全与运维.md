## 1. 安全（FP-X）

### FP-X01 全链路 TLS（M2）

| 编号 | 规则 |
|---|---|
| X01-1 | 对外端口：25 支持 STARTTLS 但不强制；465 和 587 强制 TLS；143 支持 STARTTLS，993 为隐式 TLS；POP3 开启时 110 支持 STARTTLS，995 为隐式 TLS |
| X01-2 | 所有 TLS 连接最低版本 1.2，禁用已知不安全的加密套件 |
| X01-3 | 证书自动续期，续期后各组件自动重新加载 |
| X01-4 | 组件之间的内部连接走容器私有网络，这些端口不对公网开放 |
| X01-5 | HTTP 接口经网关以 HTTPS 提供 |

### FP-X02 开放中继防护（M2）

| 编号 | 规则 |
|---|---|
| X02-1 | 未认证的连接只能向本系统的域投递。向其他域转发必须先认证 |
| X02-2 | 上线前实测：未认证连接向外部地址投递必须被拒绝 |
| X02-3 | 控制面使用的内部提交端口只在私有网络监听，只接受控制面的连接 |
| X02-4 | 控制面在提交前校验发件地址属于当前用户，见 FP-S14 |

### FP-X03 登录失败防护（M2）

| 编号 | 规则 |
|---|---|
| X03-1 | Dovecot 对认证失败做惩罚：同一来源对同一账号连续失败后，逐次加长响应延迟 |
| X03-2 | Postfix 限制同一客户端的连接频率和认证尝试频率 |
| X03-3 | 每次登录成功和失败都写入登录日志 |
| X03-4 | 密码策略见 FP-M05 |

### FP-X04 入站连接防护（M5，可选）

| 编号 | 规则 |
|---|---|
| X04-1 | 开启后对入站连接做协议合规检测，并查询实时垃圾来源黑名单 |
| X04-2 | 使用外部黑名单前须确认该服务的使用授权 |
| X04-3 | 被误判的来源地址可以加到放行列表 |

### FP-X05 密码安全存储（M2）

| 编号 | 规则 |
|---|---|
| X05-1 | 邮箱密码只保存哈希。哈希格式必须是 Dovecot 能验证的慢哈希：首选 Argon2id；镜像里的 Dovecot 不支持时用 SHA512-crypt，迭代次数不少于 20 万 |
| X05-2 | 实现前在镜像里核对 Dovecot 实际支持的哈希格式，并把结果写进技术设计 |
| X05-3 | 任何人都不能查看密码明文。重置只能生成新密码 |
| X05-4 | Dovecot 通过只读视图读取哈希。Postfix 的认证交给 Dovecot，不直接读库 |

### FP-X06 秘密管理（M1）

| 编号 | 规则 |
|---|---|
| X06-1 | 以下秘密只通过环境变量或挂载的密钥文件注入，不写入镜像、代码仓库和配置模板：数据库密码、控制面访问邮箱的主账号口令、Rspamd 控制接口密码、DKIM 私钥、TLS 私钥、服务间凭据 |
| X06-2 | 配置模板里只放占位符 |
| X06-3 | 启动前检查必需的秘密是否存在且可读，缺失则拒绝启动。错误信息不回显秘密 |
| X06-4 | 日志不打印秘密和完整的数据库连接串 |

### FP-X07 HTTP 接口安全（M3）

| 编号 | 规则 |
|---|---|
| X07-1 | 身份校验和越权防护见 FP-A18 |
| X07-2 | 每用户请求限速：读接口每分钟 300 次，写接口每分钟 60 次，附件上传每分钟 30 次。超限返回 429 并带重试等待时间 |
| X07-3 | 请求体大小上限：JSON 请求 1 MB；附件上传按 FP-A08 的限制 |
| X07-4 | 附件下载不提供可公开访问的链接 |
| X07-5 | 所有输入都校验长度、字符集和格式；数据库访问用参数化语句；生成的过滤脚本要转义 |
| X07-6 | 管理接口每个请求都复检权限并记审计 |

## 2. 运维（FP-O）

### FP-O01 部署编排（M1 骨架，M2 完整）

| 编号 | 规则 |
|---|---|
| O01-1 | 提供容器编排文件，包含邮件核心（Postfix 与 Dovecot 同在一个容器）、Rspamd、Redis 和控制面服务；病毒扫描组件可选 |
| O01-2 | Postfix 和 Dovecot 连接数据库用的配置文件由控制面在启动时根据配置渲染。数据库连接信息变化后需要重建容器 |
| O01-3 | 镜像版本固定。镜像里各组件的版本在 M1 核对后写进技术设计 |
| O01-4 | 数据卷分开：邮件存储、邮件队列、密钥与证书、日志 |
| O01-5 | 只有 Postfix 和 Dovecot 暴露公网端口。Rspamd、Redis、控制面和各内部端口只在私有网络可达 |
| O01-6 | 首次启动时初始化数据库；正式证书和 DKIM 私钥由挂载或域名管理页提供，不自签顶替 |

### FP-O02 备份与恢复（M5）

| 编号 | 规则 |
|---|---|
| O02-1 | 每日备份一次，内容：邮件存储、ppb_mail 数据库、DKIM 私钥目录、TLS 证书和私钥 |
| O02-2 | 备份加密保存，保留 14 天。备份密钥与备份分开保管 |
| O02-3 | 单个邮箱恢复：把备份里该邮箱的邮件合并回现网邮箱，不覆盖现有邮件。5 GB 以内的邮箱 1 小时内完成 |
| O02-4 | 全量恢复：在一台新服务器上用最近一次备份恢复，再切回 DNS。8 小时内恢复服务 |
| O02-5 | 每季度做一次恢复演练并保留记录 |
| O02-6 | 备份失败时告警 |

### FP-O03 监控告警（M5）

| 编号 | 规则 |
|---|---|
| O03-1 | 采集指标：三类队列长度、每小时收发数量、拒收率、认证失败次数、磁盘用量、各组件是否存活、证书剩余天数、HTTP 接口耗时 |
| O03-2 | 控制面提供健康检查接口和指标接口，指标用 Prometheus 文本格式 |
| O03-3 | 告警条件：延迟重试的邮件超过 100 封并持续 10 分钟；磁盘用量超过 80%；证书剩余不足 15 天；任一组件不存活；同一来源地址每小时认证失败超过 50 次；备份失败 |
| O03-4 | 告警的接收通道接平台现有的监控方式 |

### FP-O04 日志采集（M2）

| 编号 | 规则 |
|---|---|
| O04-1 | Postfix 和 Dovecot 把日志写到共享目录里的文件，控制面实时读取、解析并入库 |
| O04-2 | 垃圾评分记录从 Rspamd 的历史库读取后入库 |
| O04-3 | 采集服务重启后从上次读到的位置继续，不重复入库，也不遗漏 |
| O04-4 | 原始日志文件按大小轮转，保留 7 天 |

### FP-O05 启动前配置检查（M1）

| 编号 | 规则 |
|---|---|
| O05-1 | 控制面提供 `-check-config` 参数，与正常启动使用同一份配置加载和校验代码 |
| O05-2 | 检查项：配置文件存在且可读；YAML 没有未知字段；环境名称合法；数据库连接串存在且格式正确；必需的秘密存在且可读；内部依赖地址已配置 |
| O05-3 | 检查通过退出码为 0，失败为非零。检查模式不连接数据库、不跑迁移、不监听端口、不生成任何密钥 |
| O05-4 | 部署脚本先用同一个二进制和同一份配置执行检查，通过后才启动。做法与平台现有服务一致 |

### FP-O06 升级与回滚（M5）

| 编号 | 规则 |
|---|---|
| O06-1 | 邮件组件升级的顺序：备份、测试环境验证、生产升级。配置格式的兼容性先在测试环境确认 |
| O06-2 | 控制面的数据库迁移只增加表和列，保持对上一版本兼容 |
| O06-3 | 保留上一版本的镜像。回滚时回退镜像，并执行迁移的回滚脚本 |
| O06-4 | 每次升级记录各组件的版本组合 |

### FP-O07 运维手册（M5）

| 编号 | 规则 |
|---|---|
| O07-1 | 手册内容：上线前检查清单、日常巡检项、常见故障处置、备份恢复步骤、升级步骤、紧急联系人 |
| O07-2 | 上线前检查清单包括：DNS 各项记录已生效、端口和防火墙已放行、反向解析已配置、出站 25 端口可达、服务器地址不在常见实时黑名单里 |
| O07-3 | 常见故障覆盖：队列积压、磁盘满、证书过期、服务器地址被列入黑名单、单个用户无法登录、正常邮件被判为垃圾 |
| O07-4 | 上线前检查清单必须逐项实际执行并保留执行记录 |
