# 系统通知邮件

> v0.1；注册、找回密码、换绑邮箱三类验证码邮件的需求细则。状态口径见 [域导航](../README.md)。“数值待定案”指代码注释明确标注的待决取值。标“缺口”的条目怎么修，见 [缺口修复设计](../tech/11-通知邮件缺口修复设计.md)。2026-11-25 这些缺口已经在分支上修复（ppb-iam 和 ppb-chat 的 `fix/notify-mail-gaps`），还没有合并，所以下面写的是「已修复，待合并」。

[需求基线](../PRD.md) · [投递设计](../tech/01-系统通知邮件投递设计.md) · [缺口修复设计](../tech/11-通知邮件缺口修复设计.md)

## MAIL-01 发码触发与用途

| 编号 | 规则 | 状态 |
|---|---|---|
| 01-1 | 注册发码：`POST /iam/api/v1/register/code {email}`。邮箱规范化（去空白、转小写）后校验外形，非法即拒 | 现役 |
| 01-2 | 找回密码发码：`POST /iam/api/v1/password/forgot {email}`。仅当邮箱归属存在且用户状态正常时发码；未注册、已停用、已注销、已换绑退役的旧值一律不发码，对外仍返回成功 | 现役 |
| 01-3 | 换绑邮箱发码：`POST /iam/api/v1/identity/change-email/start {new_email, current_password}`，须已登录并通过当前密码校验 | 现役 |
| 01-4 | 换绑确认：`POST /iam/api/v1/identity/change-email/confirm {code}`，码单次消费，旧邮箱标识退役但保留唯一占用，新标识写入已验证，并记审计 | 现役 |
| 01-5 | 每个用途的验证码摘要在各自的域内计算，跨用途不可互用；换绑码的摘要额外编入用户维度，防止跨用户消费 | 现役 |
| 01-6 | 换绑码绑定发起时的用户：其他用户即使拿到码也不能消费 | 现役 |
| 01-7 | 换绑的进行态（用户到新邮箱的对应关系）当前存于服务进程内存，服务重启或多实例部署时丢失 | 缺口，多实例前须外置 |

## MAIL-02 验证码规则

| 编号 | 规则 | 状态 |
|---|---|---|
| 02-1 | 验证码为 6 位数字，用密码学安全随机源生成 | 现役 |
| 02-2 | 有效期 10 分钟 | 现役，数值待定案 |
| 02-3 | 同一挑战最多 5 次错误尝试，超过即作废 | 现役，数值待定案 |
| 02-4 | 限流：同一投递目标在 1 小时内未消费的挑战达到 3 条即拒绝，按用途分别计数 | 现役，数值待定案 |
| 02-5 | 注册发码超限返回 429 `IAM-4290`；内部 RPC 返回 `IAM-1002` | 现役 |
| 02-6 | 找回密码的超限不对外暴露，返回与成功相同的响应，避免泄露账号是否存在 | 现役 |
| 02-7 | 挑战单次消费，并发下只允许一次成功 | 现役 |
| 02-8 | 挑战只存 HMAC-SHA256 摘要，由服务端密钥、用途、目标、码计算；明文码不落库、不进审计 | 现役 |
| 02-9 | 验证码生成算法存在取模偏差，低位码出现概率比高位码高约 6% | 已修复，待合并：改成拒绝采样，提交 e77fa4f |
| 02-10 | 是否增加按来源（IP、设备）维度的发码限流或人机校验，防止邮箱被刷 | 待决策 |

数值说明：`account_register.go` 的常量注释写明“数值时限属 ADR-005 P0 待决项，暂取保守值”，对应 [IAM 架构决策](../../iam/adr/架构决策.md) ADR-005。上表的 10 分钟、5 次、3 条是现行实现值，不是定案值。

## MAIL-03 投递通道与装配

| 编号 | 规则 | 状态 |
|---|---|---|
| 03-1 | 生产通道为 SMTP：587 端口，PLAIN 认证，服务器宣告 STARTTLS 即自动升级 | 现役 |
| 03-2 | 非 TLS 且非回环地址的链路上不发送认证凭据；25 端口只有回环地址可明文投递；465 隐式 TLS 不支持 | 现役 |
| 03-3 | 装配顺序：SMTP 四项配置齐全且口令已注入，则装配真投递；否则开发态开关开启时装配日志投递；否则不装配 | 现役 |
| 03-4 | 显式配置了生产投递时优先按生产走，即使开发态开关同时开启 | 现役 |
| 03-5 | 通道未装配时发码即失败，返回 503 `IAM-3001`，不静默丢码 | 现役 |
| 03-6 | 邮件通道未配置不阻止服务启动，只输出告警 | 现役 |
| 03-7 | 日志投递会把验证码明文写进服务日志，只允许在开发环境使用 | 现役 |
| 03-8 | 生产环境若装配结果为日志投递，启动时应拒绝或明确告警 | 已定为拒绝启动。已修复，待合并：提交 9c98c79 |

## MAIL-04 投递时效与可靠性

| 编号 | 规则 | 状态 |
|---|---|---|
| 04-1 | 单次投递有总时长上限，连接、认证、投递各阶段都受其约束；超时按投递失败处理并释放连接。建议 5 秒，沿用 ppb-chat/docs/README.md ADR-009 的口径 | 已修复，待合并：提交 cd293c7，总时长从拨号前算起 |
| 04-2 | 投递失败如实返回：注册发码返回 503 `IAM-3001`，内部 RPC 返回 Unavailable | 现役 |

| 04-4 | 发码请求不因中继慢或挂起而长时间占用连接和协程。可选做法：先落挑战即返回，后台投递；或至少受 04-1 约束 | 待决策 |
| 04-5 | 投递失败是否重试，重试次数与间隔 | 待决策，现状不重试 |
| 04-6 | 每次投递新建完整 SMTP 会话，不复用连接 | 现役，已知取舍 |
| 04-7 | 中继异步退信（投递后被对端退回）无人接收，是否定义退信地址与处理策略 | 待决策 |

## MAIL-05 邮件内容

| 编号 | 规则 | 状态 |
|---|---|---|
| 05-1 | 纯文本邮件。主题为“【PPB】”加用途词加“验证码”，用途词为注册、找回密码、换绑邮箱；未知用途回退“验证码” | 现役 |
| 05-2 | 正文包含验证码、有效分钟数和一句安全提示 | 现役 |
| 05-3 | 中文主题按 MIME 编码词编码；正文声明 UTF-8 字符集；行尾用 CRLF | 现役 |
| 05-4 | 收件人或发件人含换行符即拒发，防止邮件头注入 | 现役 |
| 05-5 | 投递记录里的主题和发件人必须与实际发出的邮件一致，模板只能有一个来源 | 缺口，现状实发模板和记录模板是两套 |
| 05-6 | 是否提供 HTML 版式、多语言文案 | 待决策，首版不做 |
| 05-7 | 发件域名的 SPF、DKIM、DMARC 由中继服务方保障，应用不做校验；若改为自建发信域需补充校验需求 | 待决策 |
