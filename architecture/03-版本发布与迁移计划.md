## 远程依赖策略

~~~go
// 某业务只接入 IAM，以下为示例依赖。
require (
    github.com/maibanku/ppb-base/go-framework v0.1.0
    github.com/maibanku/ppb-base/platform-sdk/iam v0.1.0
)
~~~

需要文件再增加 File SDK，需要 RabbitMQ 再增加对应驱动。SDK 自己声明必要的契约依赖。根基础模块不导入所有可选适配，不能通过全局初始化器创建全部服务客户端。

snapshot-1.0.0 可作为开发分支。消费方更新该分支时，Go 将提交解析为固定版本；分支后续推进不会使其他服务自动升级。可复现快照使用新标签，例如 platform-sdk/iam/v0.1.0-snapshot.1，后续增加 snapshot.2。发布后保持标签不可变。

私有源码模块由开发机和 CI 通过受控 Git 身份读取，配置精确 GOPRIVATE 范围。包仓库凭据通过 CI 或构建 Secret 提供，不能进入源码、镜像层、URL 或日志。私有源码权限与最终镜像拉取权限分别配置。

Go 会统一解析共享传递依赖的版本，升级一个 SDK 可能改变共同 gRPC 运行库的最终版本。每次升级核对 go list -m all、go mod graph、构建和关键回归。

## 分阶段迁移

| 阶段 | 主要工作 | 阶段交付 |
|---|---|---|
| P0 事实基线 | 确认仓库、工作区、分支、Go/npm/Rust/Swift 工具版本、接口、身份和数据状态 | 每仓 HEAD、检查命令、结果与已有缺口 |
| P1 基础提取 | 提取实际使用的轻量包、gRPC、数据库、MQ 和 Outbox 适配，迁入现有测试 | 公共模块可独立测试和发布 |
| P2 契约与 SDK | 保持 protobuf package／字段／方法兼容，拆领域协议；统一 IAM 和 File 客户端错误处理 | 可远程获取的协议及 SDK 版本，业务消费验证 |
| P3 网关 | 迁入 ppb-gateway/service-gateway，镜像只构建本仓，路由改明确清单输入 | HTTP／OIDC／WS／文件代理回归 |
| P4 前端包 | 底座库与演示双产物、业务插件版本包、门户消费升级 | npm 安装、类型检查、构建和菜单权限验证 |
| P5 IAM | 迁入 ppb-iam，搬迁前端、SQL、测试和配置；保留认证与管理桥行为 | 原账号、客户端、会话和权限链回归 |
| P6 Camera | 迁入 ppb-camera/service-camera，消费远程模块 | 模板、主体、额度和未开通分析状态回归 |
| P7 IM 与 File | 分批迁入 Chat 和 File，迁移实时、任务、SQL和管理端 | 登录、收发、文件、回调和故障回归 |
| P8 集成收尾 | 更新部署清单、路由、文档和旧路径；独立检出验证 | 已验证版本组合与回退记录 |

P3 到 P7 的具体先后可根据现有分支和依赖可用性调整，并在进度中说明。共同前提是先有可下载且验证过的公共模块。跨仓发布顺序采用兼容提供方、消费方、集成切换。

## 迁移约束

- 在隔离分支或 worktree 实施。保留他人工作区修改，避免通过 reset、clean 或强推处理未知状态。
- 优先保留迁移历史。路径过滤在临时副本完成，原仓和目标仓主分支保持可追溯；记录来源提交、目标提交和文件映射。
- 迁移阶段先保持外部 API、protobuf package／字段编号、错误语义、Cookie 和 OIDC 地址兼容。进一步清理按独立变更验收。
- go_package、buf 输出、工具模块、生成器版本和所有消费方 import 一起核对。公共 descriptor 只有一份，避免新旧生成代码同时注册同名协议。
- 用户 ID、成员 ID、雪花节点配置、数据库、签名密钥、会话和生产凭据不因仓库改名重建。旧字段处理以当前源码和专项迁移证据为依据。
- 数据迁移脚本只随服务迁移，目录调整不自动执行生产 DDL、初始化种子或清空数据。
- 库提取若发现 SDK 回执错误等已有缺陷，用独立可解释提交修复，保存复现和结果，避免与搬文件混成无法回滚的大提交。
- Wardrobe 本轮保持工程位置。统一身份和文件平台接入需单独业务验收。

## 网关路由交付

各服务发布自己的 HTTP 路由清单，集成流程记录服务、清单版本和校验摘要，汇总生成 gateway-routes.yaml。已启用服务缺清单、未知上游、方法与路径归属冲突均应使构建或启动失败。

网关镜像构建不检出其他业务源码。服务地址由环境注入，默认端口取 [调用规范](02-模块边界与服务调用.md)。当前实现启动时读取路由，更新配置按滚动重启或已验证的加载机制生效，不假定存在热更新。

新增业务前缀能由配置承接。已有精确路由仍逐条核对，尤其 /api/v1/user 兼容面、/iam 管理静态前缀和 IAM API／OIDC 路径。

## 前端交付

- base-manage-web 作为私有版本包发布，库和应用输出目录分别配置。
- 业务 manage-web 导出插件，独立入口与平台门户复用同一页面实现。
- 平台门户使用锁定版本的远程包，不读取相邻仓源码。清理 Vite alias、file:、tsconfig paths、相对跨仓 imports 及工作区隐式链接。
- 核对构建产物中的类型声明、CSS、资源路径和 Vue 共享运行时。
- IAM 前端代码归 IAM，平台门户归 ppb-base。静态托管位置按环境选择，保持公开 URL、代理优先级、OIDC 回调和 Cookie 兼容。

## 构建、CI 与回退

每个服务从自己的仓库构建，CI 至少有一次单仓检出且关闭工作区的检查。

~~~bash
# 在相应 Go 模块目录执行
GOWORK=off go mod download
GOWORK=off go build ./...
GOWORK=off go test ./...
~~~

使用临时空模块缓存验证真正的远程依赖读取，不能只凭本机缓存成功判定。凭据、网络或工具链失败必须单独记录，不能改回本地 replace 后宣称通过。

CI 枚举所有实际 go.mod 运行检查。根目录 go test ./... 不覆盖所有嵌套模块。生成、协议兼容、SDK业务错误、网关依赖和前端发布入口使用相关门禁。

新旧版本并存期间保留匹配的旧镜像、路由、前端和依赖清单。先新增可运行目标，再切环境引用；旧源码删除在目标独立构建和相关回归完成后进行。回退采用已记录的上一组兼容制品，数据库若涉及另行变更按专项恢复方案执行。
