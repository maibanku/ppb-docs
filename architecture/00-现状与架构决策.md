## 新确定的目录与发布决策

1. 新建 ppb-iam、ppb-gateway、ppb-file，IAM、网关和文件服务各自发镜像。
2. IAM 后端目录为 service-iam，网关为 service-gateway。Chat、Camera、File 迁移目标分别为 service-im、service-camera、service-file。
3. 共同基础代码放 ppb-base/go-framework，目录名由两个单词组成。
4. SDK 和契约按实际领域拆 Go 子模块。轻量基础包可以共用一个版本，gRPC、RabbitMQ、Redis、GORM 等较重适配按需独立。
5. platform-manage-web 保留在 ppb-base。网关通过静态制品或 Web 上游提供入口，源码归属与实际托管位置分别维护。
6. base-manage-web 发布公共包，同时提供独立演示入口。完整的跨应用业务装配放 platform-manage-web。
7. 所有服务，包括 IAM 和网关，正式构建从远程版本获取公共模块，验证时关闭 Go 工作区。
8. 外层 ppb 是本地仓库父目录。go.work 可选，模板与正式依赖分别管理。

## 数据和接口边界

- IAM 持有统一账号、认证凭据、会话、公共资料、平台授权。
- Chat 持有组织成员、好友、群、消息和聊天授权。
- File 持有存储、文件元数据、引用和生命周期。业务服务持有资源用途及业务访问规则。
- Camera 和 Wardrobe 持有各自业务主体、任务、偏好和权益。相机游客拍摄与衣橱本地流程继续按产品定义运行。
- 数字主键在线面按现有契约处理，user_id、member_id、OIDC subject 各自保留原语义。目录改造不隐含更换 ID、用户身份、协议包名、字段编号或数据库模型。
