# 跨仓改造验收标准

本文件列出目标验收，全部初始状态为待执行。历史报告中的成功结果只作为基线参考。每项结果需写入 [实施进度](implementation/PROGRESS.md)，包含仓库、分支、SHA、命令、日期和实际输出摘要。

## 工程与依赖

| 编号 | 验收条件 | 所需证据 |
|---|---|---|
| ARC-01 | 目标仓库与路径符合迁移映射，历史来源可追溯 | 原／目标 SHA、文件迁移列表 |
| ARC-02 | 各模块的 module、imports、go_package 和标签路径一致 | 模块清单、生成结果和发布标签 |
| ARC-03 | 单独检出 IAM、网关、Chat、File、Camera 可构建 | 关闭 GOWORK，空依赖缓存的下载和构建结果 |
| ARC-04 | 只使用 IAM 的示例模块不依赖 File SDK、RabbitMQ 驱动及业务实现 | 该示例的 go.mod、模块图及相关包依赖检查 |
| ARC-05 | 增加 File／MQ 按需引入，各 SDK 和协议可独立发版 | 组合构建和版本清单 |
| ARC-06 | 正式依赖没有本地目录 replace、相邻源码或绝对开发路径 | Go／npm／Vite／tsconfig／Docker 配置扫描 |
| ARC-07 | 框架不反向依赖业务协议和服务，网关主程序保持透明代理边界 | 实际包依赖图，单独检查生产二进制入口 |
| ARC-08 | 嵌套模块均被 CI 覆盖，生成器及工具版本可复现 | 每模块检查清单、生成漂移与协议兼容结果 |

必要的兼容模块及临时替换要列明作用、owner 和退出条件。以实际包导入和模块关系判断依赖，不能因多模块仓中目录存在就判定为二进制已引入。

## 网关与跨服务通信

| 编号 | 验收条件 | 所需证据 |
|---|---|---|
| ARC-09 | 方法、路径模板、前缀及兼容路由 owner 保持正确 | 迁移前后路由 diff；未知路径及方法请求 |
| ARC-10 | 缺少必需清单、歧义或未知 upstream 时明确拒绝 | 生成与启动负控 |
| ARC-11 | 原业务凭据按约定传递，外部伪造内部身份不能生效 | 无凭据、错误凭据、伪造头、错误应用／主体负控 |
| ARC-12 | WS 升级、收发、重连和跨节点投递保留行为 | 真实消息 ack／push、节点记录 |
| ARC-13 | 文件上传、下载、大文件和分片行为经迁移回归 | 小文件、分片、大文件、取消、无权访问结果 |
| ARC-14 | 普通接口、WS、文件超时及断连行为明确 | 不可达、响应头超时、取消和代理错误记录 |

当前普通代理共用 IM 响应头超时，WS 单独使用零响应头超时。按服务拆超时如需实施，应独立记录行为变化。文件代理流式传输不能由单次小文件成功推断。

## IAM、文件与业务数据

| 编号 | 验收条件 | 所需证据 |
|---|---|---|
| ARC-15 | 原账号、issuer、client_id、subject、回调和 Cookie 兼容 | 原客户端登录与已有会话验证 |
| ARC-16 | 停用、撤权、注销、错误成员和跨应用权限保持正确 | 正负权限矩阵与版本回源失败记录 |
| ARC-17 | user_id 与 member_id、历史附件引用、缓存及待发队列保持语义 | 数据抽查和客户端回归，无清库 |
| ARC-18 | SDK 同时检查 RPC error、业务错误和必要回执 | IAM 无效／不可用区别；File 业务失败、零／错误 ID 回归 |
| ARC-19 | File 写入成功但 IM 提交失败等窗口被验证和记录 | 故障注入；幂等、确认／补偿／对账状态 |
| ARC-20 | File 引用和下载权按当前业务范围校验 | 其他用户／会话／应用访问拒绝，未确认引用权限检查 |
| ARC-21 | 数据库迁移与生产切换范围明确 | 实际 schema 基线、dry run、恢复方案或无 DDL 声明 |

ARC-19 的完整可靠引用协议若属于后续业务阶段，可以单独标记未完成，但必须报告存量风险及本次是否改变该行为，不能将其填为通过。已知 WS 主动撤销、真实媒体和存储环境问题按现状报告。

## 完成判定

每项使用通过、失败、未执行或待后续阶段四种状态。发现环境阻塞应说明具体原因、影响范围和可继续完成的检查。文档、骨架、编译或历史记录都不能替代实际功能结果。

阶段完成时提交当前可验证代码和证据，后续阶段保持明确。生产发布和破坏性数据库操作由用户启动指令及环境授权决定，本次文档提交不执行这些动作。
