# PPB 跨仓架构与目录改造

更新日期为 2026-11-18。本文档记录已讨论确定的目标结构，工程迁移尚未执行。首次交付范围是文档和 Claude Code 实施交接。

PPB 的公共 Go 代码、协议、SDK 和后台底座由 ppb-base 发布。IAM、网关、文件和产品后端由各自仓库维护，通过版本化依赖构建，通过网络接口交互。

## 阅读顺序

1. [现状与架构决策](00-现状与架构决策.md)，确认源码快照、既有业务边界和历史文档冲突。
2. [完整目标目录](01-目标目录结构.md)，确认仓库、Go Module、前端工程和部署配置的归属。
3. [模块边界与服务调用](02-模块边界与服务调用.md)，确认依赖方向、鉴权、文件引用、日志和 MQ 的接入方式。
4. [版本发布与迁移计划](03-版本发布与迁移计划.md)，按提供方到消费方的顺序实施。
5. [验收标准](04-验收标准.md)，逐项保存真实结果。
6. [Claude Code 执行提示词](implementation/CLAUDE_CODE_PROMPT.md)，作为后续本地实施入口。
7. [实施进度](implementation/PROGRESS.md)，记录各仓 SHA、命令结果、阻塞和下一步。
8. [后端服务内部目录规范](05-后端服务内部目录规范.md)，查 IAM、IM、File、Camera、Gateway、Wardrobe 的目标文件落点、迁移批次和验收门禁。它补充的是分仓后的服务内部布局；下方的仓库存在状态为原方案的历史快照。

| 仓库 | 目标职责 | 本次核对的存在状态 |
|---|---|---|
| ppb-base | go-framework、contracts、platform-sdk、公共后台底座、平台门户、集成配置 | 已存在，仍承载旧服务目录 |
| ppb-iam | service-iam、iam-web、iam-manage-web | 待创建 |

| ppb-camera | service-camera、iOS 和管理端 | 已存在，后端待迁入 |

目标共八个仓库。通用框架目录采用至少两个单词组成的 go-framework。框架放在 ppb-base 内，后续按模块发版即可。

## 文档适用范围

- 本目录决定本次仓库归属、目录名、依赖发布和构建部署方式。
- 产品功能与权限语义继续以对应产品 PRD、接口和实际源码为依据。
- 旧文档中的 server-*、server-pkg、同仓 IAM 和相邻源码引用属于历史路径，需要按迁移映射逐批更新。
- 用户已要求单一 ID 和移除冗余删除时间。数据库现状须核对 [2026-11-14 变更记录](../database/2026-11-14-id-only/README.md)及当前源码，不能由旧 DDL 推断生产执行状态。
- 新旧标识、会话撤销、附件一致性和真实媒体链路需要分别验收，目录迁移不能作为这些能力已完成的证据。
