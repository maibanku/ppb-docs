## 现有路径迁移映射

| 当前 | 目标 |
|---|---|
| ppb-base/server-iam | ppb-iam/service-iam |
| ppb-base/iam-web | ppb-iam/iam-web |
| ppb-base/iam-manage-web | ppb-iam/iam-manage-web |
| ppb-base/server-gateway | ppb-gateway/service-gateway |
| ppb-base/server-im | ppb-chat/service-im |
| ppb-base/server-camera | ppb-camera/service-camera |
| ppb-base/server-file | ppb-file/service-file |
| ppb-base/file-manage-web | ppb-file/file-manage-web |
| ppb-base/server-pkg | 按依赖分别进入 go-framework、contracts、platform-sdk 或所属业务 |
| ppb-base/idl | 逐批进入 contracts 的领域模块 |
| ppb-base/platform-manage-web | 保留位置，替换跨仓源码别名 |
| ppb-wardrobe/wardrobe-manage-web/server | 保留位置，IAM／File 接入另行评估 |

IAM、IM、Camera、File 的数据库脚本随所属服务迁移。环境级编排保留在 ppb-base/deploy，脚本引用服务制品和版本，避免依赖相邻服务源码。

## 兼容协议的处理

当前 user.proto 同时由 IAM 和 IM 承接不同方法。先在 user-compat 中保持现有 protobuf package、完整 RPC 方法名及字段编号，逐个记录方法的真实 owner。拆分明确后再移除兼容模块。

refaccess.proto 作为 File 定义的访问裁决回调契约，放入 contracts/file，由 Chat 等业务实现。contracts/common 第一阶段可保留历史类型以维持兼容；通用类型与聊天类型的进一步拆分单独验证，避免注册重复 descriptor。

## 可选扩展

Kafka 驱动、通知 SDK、通知契约或审计服务只在具体需求出现后创建。日志采集和 MQ Broker 首期采用独立基础设施制品及部署配置。
