## 1. 背景与结论

用户拥有不少衣物，但日常选搭耗时；传统电子衣橱录入负担大，单纯生成好看图片又未必能用真实衣物穿出来。本产品将“照片拆分—单品入库—AI 组合—局部替换—实际穿着反馈”串联，帮助用户用已有衣物快速决定今天穿什么。

产品主张：**把已有的衣服，穿出新可能。**

本需求以会话中用户最后确认的方向为准：

1. 设计简单简约，操作键尽量少，容易上手。
2. 参考 WOO 的立体穿搭展示方向与人物为中心的体验，保留原创品牌和界面。
3. 手机端保留“穿搭、衣橱”两个一级入口，每个核心页面只有一个主要行动按钮。
4. 支持整张穿搭照片拆分为上衣、裤子、鞋、包等独立单品；允许单独整理后由 AI 重新组装。
5. 手机能够本地运行，同时可选择使用云端能力。
6. Web 支持衣物整理和管理，个人工作台与运营权限明确隔离。

早期奶白/墨绿、四入口、周计划大屏等探索，作为后续参考；最终视觉基线为黑白灰、少量蓝色强调、立体人物居中、底部单品选择。本文不将生成效果图当作已实现的交互或算法效果。

## 2. 目标用户与场景

### 2.1 首批用户

已有一定数量衣物、需要日常通勤搭配、愿意尝试 AI 但不愿复杂录入的个人用户。初期设计不限制性别；样例人物不代表目标用户仅限某一性别。

| 场景 | 用户需求 | 产品响应 |
| --- | --- | --- |
| 出门前 | 快速决定穿什么 | 一套直接可用的搭配，支持换一套 |
| 喜欢部分组合 | 保留裤子，只换外套 | 锁定保留项，点击单品局部替换 |
| 整理旧照片 | 一张照片里有多件衣物 | 自动拆分候选，确认后分别入库 |
| 新买衣物 | 快速添加与分类 | 拍照或选图，自动建议类别，允许改正 |
| 无网络 | 继续查看、整理和搭配 | 本地数据库与图片可用，云端功能有明确状态 |
| 桌面集中整理 | 更高效确认大量单品 | Web 原图与拆分结果并排，支持批量编辑 |
| 记录穿着 | 记住穿过什么及感受 | 一次确认记录，反馈自愿填写 |

### 2.2 产品目标

- 降低从图片到可用衣橱的录入成本。
- 提高推荐的实际可穿性和用户采纳率。
- 让用户在没有账号、没有网络时仍能使用基础衣橱。
- 通过明确反馈逐渐改善推荐，不用一次测试给用户固定贴标签。
- 控制 AI 成本，不以每次交互都生成真人图片为前提。

### 2.3 非目标

首版不承诺真实尺码/合身测量、服装物理仿真、精确三维重建；不建设公共社区、电商交易、发型写真、无限生成或自研基础模型。完整三维展示列入技术验证与后续版本，不阻塞衣橱闭环。

## 4. 信息架构与设计规范

### 4.1 手机端

一级导航仅“穿搭、衣橱”；日历、账户、同步、设置放在相应二级页面。设置可由衣橱页的更多菜单进入，不增加第三个一级标签。

| 页面 | 主要内容 | 唯一主要动作 | 次要操作 |
| --- | --- | --- | --- |
| 穿搭首页 | 当前搭配、人物或二维组合、单品缩略图 | AI 搭一套 | 点单品替换；保存/记录入口 |
| 衣橱 | 分类与单品网格 | 右上角添加 | 点单品查看详情，更多菜单 |
| 换一件 | 当前效果与替代单品底部面板 | 保存搭配 | 切换类别、返回 |
| 照片拆分 | 原图、候选单品、待确认标记 | 确认入库 | 调整抠图、修改类别、取消勾选 |
| 搭配详情 | 单品清单、日期、反馈 | 就穿这套 | 收藏、分享导出 |
| 穿着记录 | 日期与已穿搭配 | 按场景显示 | 更正日期、撤销记录 |

交互规则：

- “AI 搭一套”生成推荐；“保存搭配”写入收藏；“就穿这套”写入穿着记录，三者语义严格区分。
- 已有当前搭配时，主按钮可变为“就穿这套”，“换一套”使用次要文本动作。
- 点击单品可换搭；长按可作为快捷方式，但必须存在可发现的普通点击入口。
- 不把相机、相册、上传、抠图、分类分别做成五个一级按钮；添加后在流程中逐步选择。
- 每页最多一个高强调主按钮；避免同时展示多个同等权重的操作。
- 点击区域建议不小于 44×44 逻辑单位；支持字体放大、屏幕阅读器，状态不只依赖颜色。
- 操作完成用轻提示反馈；只在删除重要数据或上传授权等必要场景确认。
- 图片加载、空状态、处理中、离线、失败均有清晰说明和可继续使用的动作。

### 4.2 视觉与形象展示

- 白/浅灰背景，深色文字，少量蓝色表示选中状态。
- 人物位于穿搭页面中心；单品缩略图位于下方，减少浮动按钮和侧边工具。
- 支持不同体型、肤色与性别表达，不使用自动外貌打分。
- 未创建形象时直接使用二维拼搭图，不强制上传人像。
- 展示模式区分：二维拼搭、AI 二维试穿图、多视角图片、真正三维模型。
- 仅三维资产存在且交互已实现时显示旋转手势；二维图不显示虚假的旋转入口。
- 三维资产不可用、设备性能不足或用户开启减少动态效果时降级为静态图。
- 视觉概念图中的人物、天气和数值均为示例，不构成验收证据。

### 4.3 Web 个人整理端

最小布局：左侧原图，右侧拆分结果；主动作“确认入库”，次动作“调整拆分”。可查看上衣、裤子、鞋、包等分类，批量修正名称与标签，并选择已入库单品发起 AI 搭配。

桌面个人端与手机共享数据结构。Web 不自动读取手机本地文件：跨设备需主动同步，或导出文件包再导入。默认私有，不因生成分享图而公开整个衣橱。

### 4.4 Web 运营后台

独立入口与角色认证，管理用户服务、模型任务、质量反馈、成本、配置与版本。运营人员默认只看到状态与脱敏元数据，不默认浏览个人衣橱。

## 5. 核心用户流程

### 5.1 首次启动

启动 → 简短说明 → 直接进入本地衣橱 → 添加一张图片 → 确认单品 → 生成或手动创建第一套搭配。

登录为建议采用的产品方案，不设为基础操作前置门槛；仅在跨设备同步、账号额度或相应高级服务需要时提示。拒绝登录后保持原操作上下文并继续本地功能。基础功能不要求填写身材、性别、生日或上传人像。

### 5.2 单图拆分入库

1. 用户拍摄或选择单品图/整套穿搭图。
2. 本地保存原图，允许裁切与旋转；读取照片权限按需请求。
3. 根据设备能力、网络与授权选择本地或云端拆分。
4. 输出候选单品，每项含裁切/蒙版、类别建议、置信信息、来源原图。
5. 用户检查、改类别、调整边缘、取消误识别项；低置信与遮挡项标记待确认。
6. 点击“确认入库”，仅保存勾选且已处理完必需确认的项。
7. 返回衣橱，显示新增数量，可立即搭配。

约束：

- 原始像素抠图与 AI 补全为不同产物。补全结果必须标记，保留原图与来源。
- 被外套挡住的上衣不能宣称完整还原；允许用户补拍或保留局部图。
- 一双鞋默认记为一个单品；多个同类物件允许分别确认。
- 类别至少支持外套、上衣、裤子、裙装/连衣裙、鞋、包、配饰、其他；无法识别归入待确认。
- 材质、品牌、尺码、价格不得仅凭图片自动当作事实填写。
- 相似单品提示合并，但不自动删除；重复确认和网络重试不得生成重复衣物。
- 全部识别失败时可手动裁切添加；未确认候选不参与正式推荐。

### 5.3 AI 组合与局部替换

1. 默认使用已确认、可穿的衣物。
2. 用户可选择简短场景，或输入“保留这条裤子，换得休闲一点”。
3. 系统先过滤在洗、已收纳、已归档及不满足约束的单品，再产生组合。
4. 首屏呈现一套主推荐；其他候选通过“换一套”逐次展示。
5. 用户点击单品选择替换，保留/锁定项不得改变。
6. 保存搭配或确认实际穿着，可自愿反馈“喜欢、太正式、有点热”。

若缺少鞋等必要类别，说明缺项，允许保存不完整组合，但不得虚构用户拥有该物品。外部购衣建议如后续加入，应与已有衣物明确区分。天气需用户选择城市或授权定位；不可用时支持手动选择温度/场景，不阻断搭配。

### 5.4 本地到云端

本地数据持续可用 → 用户选择云端增强/同步 → 说明上传范围 → 登录（若该服务需要）→ 确认本次图片或选定衣物 → 上传 → 查询任务 → 下载结果并保存本地。

授权云端处理一张图不等于授权同步全部衣橱；登录不等于开启同步。撤销授权后不再发起新上传，已运行任务提供取消或删除结果的入口并说明处理状态。

| FR-12 | 隐私授权 | 仅本地模式无照片/衣橱内容外传；拒绝上传仍可使用本地功能 |
| FR-13 | 效果预览 | AI 生成图有标识；不宣称尺码保证，失败不影响原搭配保存 |
| FR-14 | 额度与扣费 | 如启用额度，先展示预计消耗；失败释放预占，幂等重试不重复扣减 |

### 6.1 关键异常状态

| 异常 | 页面表现 | 恢复方式 |
| --- | --- | --- |
| 无衣物 | 说明“先添加几件常穿的衣服” | 添加图片或体验明确标记的示例衣橱 |
| 类别不齐 | 告知缺少类别 | 保存部分组合或继续添加 |
| 无照片权限 | 说明当前操作需要的权限 | 系统选图器/手动授权；不循环弹窗 |
| 拆分不确定 | 单品标记待确认 | 调整区域、改类别或补拍 |
| 模型下载失败 | 本地 AI 尚不可用 | 手动裁切/规则搭配，用户选择是否重试 |
| 无网络 | 保留原图和操作进度 | 用户选择恢复联网后重试；不未授权自动上传 |
| 存储空间不足 | 不丢弃已保存数据 | 清理派生缓存，提示释放空间 |
| 云端超时 | 明确任务状态，避免重复提交 | 查询原任务或使用同一幂等键重试 |
| 同步冲突 | 显示本机/远端版本摘要 | 选择版本或保留副本 |
| 删除任务中衣物 | 当前结果提示失效 | 重新选取单品；历史穿搭保留快照 |

## 7. 本地优先与云端架构要求

本节为逻辑约束，不锁定框架、供应商或模型。具体选型需结合平台、预算和实机验证决定。

### 7.1 能力矩阵

| 功能 | 本地基线 | 云端增强 | 无云端时的保障 |
| --- | --- | --- | --- |
| 衣橱浏览与编辑 | 数据库、原图/缩略图、本地分类 | 备份与同步 | 完整可用 |
| 单品裁切 | 手动裁切，支持设备可用的轻量抠图 | 复杂背景处理 | 手工修正入库 |
| 整图多衣物拆分 | 端侧模型能力待验证 | 多目标识别、分割、可选补全 | 逐项手工裁切 |
| 穿搭组合 | 类别、颜色、场景基础规则 | 语义理解、个性化排序 | 输出规则建议，不标作云端 AI 结果 |
| 人物预览 | 本地二维拼搭与已下载图 | 生成试穿图 | 二维可用 |
| 三维形象 | 渲染已下载且兼容的三维资产 | 可选资产生成 | 静态图 |
| 记录和偏好 | 本地保存 | 用户授权后跨设备共享 | 本地独立可用 |

### 7.2 逻辑组件

- App：页面层、本地数据仓库、图片处理、推荐规则、端侧模型适配器、同步队列。
- Web 个人端：图片/文件包导入、拆分确认、衣物整理、搭配工作台。
- 云端：身份与权限、衣橱同步 API、对象存储、AI 任务编排、模型适配、额度账本、可观测性。
- 运营后台：配置、任务监控、质量反馈、成本、审计；不能绕过用户数据权限。

客户端只通过自有服务访问商业模型；模型供应商密钥不下发至 App/Web。AI 输出需服务端结构校验与归属校验，再写入用户数据。

### 7.3 数据与同步约束

- 本地写入优先，断网记录变更；每个对象具有稳定 UUID、版本和更新时间。
- 同步队列需支持幂等、重试、删除墓碑；不能用“最后写入直接覆盖”处理所有冲突。
- 冲突的衣物编辑保留两版信息；穿着记录以稳定记录 ID 合并。
- 游客绑定账号时先提供合并预览，不覆盖已有云端衣橱；相似衣物由用户决定合并。
- 退出账号后停止同步，用户可保留或删除本机副本；切换账号不泄露前一账号数据。
- 本地项目与已登录账号的数据命名空间隔离。
- 导出包包含版本清单、图片与关系；导入做校验并报告失败项。卸载本地应用可能丢失未备份内容，设置页清楚提示并提供导出。
- Web 浏览器本地缓存不视作永久备份。MVP 手机跨设备数据仅经主动同步或文件包迁移。

### 7.4 AI 任务生命周期

草稿 → 待授权 → 待上传 → 排队 → 处理中 → 待确认/成功；任一阶段按能力转为失败或取消。

- 任务记录 operation_id、幂等键、输入资源 ID、模型/提示词版本、执行位置、耗时与成本。
- 不确定的识别结果进入待确认，不自动升级为已入库单品。
- 客户端超时后先查询既有任务，不能立即创建第二个付费任务。
- 同一任务回调重复到达仅入账一次；失败释放额度预占。若供应商已产生费用，由产品策略处理，不能重复扣用户额度。
- 手工调整必须保留，重跑 AI 时先生成新候选，不覆盖用户已确认结果。

## 8. 核心数据模型

| 对象 | 必要字段/关系 | 规则 |
| --- | --- | --- |
| LocalProfile/Account | local_profile_id、可选 account_id、偏好、授权版本 | 无账号也有本地身份 |
| ImageAsset | asset_id、原图/蒙版/补全/缩略图类型、位置、来源、hash | 补全与原图分开存储 |
| Garment | garment_id、owner、类别、颜色、状态、asset_ids、来源图、确认状态、版本 | 推荐只引用已确认有效对象 |
| ExtractionCandidate | candidate_id、task_id、区域/蒙版、标签置信度、人工修正 | 确认后创建或关联 Garment |
| Outfit | outfit_id、单品 ID、锁定项、场景、生成来源、预览资源 | 记录组合，不依赖单一生成图片 |
| WearLog | log_id、日期时区、outfit_id、当时快照、反馈 | 历史可追溯，不随单品删除丢失 |
| PreferenceFeedback | 对象、喜欢/不喜欢原因、显式或推断来源、时间 | 明确反馈优先，支持重置 |
| AITask | 类型、状态、执行位置、版本、幂等键、成本、错误 | 可观察、可取消、可追踪 |
| SyncChange | entity_id、版本、操作、墓碑、同步状态 | 防止删除后旧设备复活数据 |
| CreditLedger | 预占/扣减/释放、task_id、交易 ID | 可选收费能力，账本幂等 |
| AuditLog | 操作者、角色、动作、资源、时间 | 运营访问图片需留痕 |

图片与敏感字段不写入普通业务日志；反馈统计避免上传原始私人照片。

## 9. Web 管理权限

| 角色 | 可做事项 | 默认不可做事项 |
| --- | --- | --- |
| 个人用户 | 整理自己的图与衣物、生成搭配、导出删除 | 查看其他用户衣橱 |
| 客服 | 查看授权范围内的任务状态与错误 | 任意浏览人像原图 |
| 运营 | 查看聚合使用与质量、管理内容配置 | 访问模型密钥、越权修改个人衣物 |
| AI 管理员 | 模型路由、提示词版本、评估、回滚 | 默认查看无授权私人照片 |
| 系统管理员 | 角色与服务配置、审计 | 绕过审计直接获取用户资料 |

后台 P0 包含任务检索、失败原因、重试权限、模型版本、耗时/成本、功能开关与回滚；批量修改配置需预览影响范围。用户投诉需查看图片时，采用限时授权及审计。

## 10. AI 质量、性能与验证

以下数值为**拟定验收目标**，不是现有能力或竞品数据。评审时用约定设备与网络条件校准，不通过则降级或缩减支持范围。

| 项目 | 初始目标/验证方法 |
| --- | --- |
| 本地启动 | 约定基准手机、500 件衣物，冷启动到可操作 P95 ≤ 3 秒 |
| 本地交互 | 分类筛选等常用操作 P95 ≤ 300ms；长任务不阻塞页面 |
| 云端推荐 | 约定测试网络下 P95 ≤ 15 秒；超时提示与任务可查询 |
| 云端拆分 | 约定分辨率测试集 P95 ≤ 60 秒；显示进度与可离开提示 |
| 类别识别 | 标注测试集宏平均 F1 目标 ≥ 0.90；单独统计遮挡/小物件 |
| 抠图质量 | 至少 200 张授权测试图，人工评审可直接用比例目标 ≥ 80% |
| 推荐可靠性 | 不存在/越权/不可穿单品引用为 0；锁定项违反为 0 |
| 本地隐私 | 仅本地模式网络检查中照片与衣橱内容外传为 0 |
| 数据完整性 | 断网、杀进程、重试、冲突、重复回调测试无已确认数据丢失 |
| 端侧 AI | 单独测试模型包大小、峰值内存、耗时、温升与电量；未达标关闭该能力 |
| 三维体验 | 低端设备与可访问性验证通过后开放；不通过提供静态预览 |

测试集应覆盖单品平铺、真人穿搭、镜面自拍、复杂背景、不同肤色体型、遮挡、包带、鞋对、多人照片。多人照片默认让用户选择目标人物，不自动混合两人的服饰。

AI 模型更新需在固定评估集回归，检查类别、抠图、服装细节、推荐约束与成本后灰度发布。质量下降可回退模型/提示词版本。截图效果好看不能替代功能测试。

## 11. 产品指标与实验

北极星指标：**每周采用推荐并确认实际穿着的去重用户数**。游客以本地安装标识或本地统计计算；是否上报分析需遵守用户分析设置，不为指标强制注册。

| 指标 | 定义 |
| --- | --- |
| 首次搭配激活率 | 首次进入后 24 小时内保存首套真实衣物搭配的用户 / 新用户 |
| 入库完成率 | 确认至少一件单品的导入流程 / 已开始导入流程 |
| 首次价值时间 | 首次启动至保存首套真实衣物搭配的时间 |
| 推荐采纳率 | 推荐展示后被确认穿着的推荐会话 / 有效推荐会话 |
| 拆分修正率 | 用户修改类别/蒙版的候选 / 被确认候选 |
| 四周留存 | 首次激活用户在第 4 周再次完成核心行为的比例 |
| 单次采纳成本 | 统计周期 AI 总成本 / 同期被采纳的推荐次数 |
| 故障率 | 失败任务 / 已执行任务；按设备与模型版本分组 |

埋点建议：import_started、extraction_completed、garment_confirmed、outfit_generated、item_replaced、outfit_saved、outfit_worn、cloud_consent_changed、sync_failed。事件用随机/内部 ID，不包含原图、姓名、自由文本或供应商密钥。

先获取内测基线，再设增长目标。验证二维组合与人物预览是否真正提升采纳/留存，避免只优化生成图片数量和分享点击。

## 12. 商业化与账户策略

建议基础衣橱、手动搭配、本地记录保持可用；高级规划订阅、云端试穿按额度进行实验。定价、免费额度、支付渠道待成本与用户访谈确认。

- 登录仅在所需服务触发，不能阻断游客衣橱。
- 登录、购买、同步、人像上传分别说明，不合并为默认勾选。
- 发起收费生成前显示所需额度与余额；余额不足不扣费且保留当前搭配。
- 支付恢复、退款、账号切换及账本对账列入商业化上线前验收。
- App 上架地区、隐私材料、支付与生成内容标识等按发布时适用要求专项核查；本文不替代政策检查。
