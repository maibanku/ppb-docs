# 验收总则与发布门槛

版本 v1.0 · 2026-10-26。

[验收目录](./README.md) · [需求追踪矩阵](./需求追踪矩阵.md)

## 1. 范围与依据

以总 PRD 的 P0 为 MVP 必测范围。P1/P2 或支付等条件功能如在本次开放，必须执行对应验收；如未开放，记录开关、用户入口和不适用理由。未实现的 P0 不得标记为不适用。

本目录定义预期行为和测试方法，不宣称软件已经存在或测试通过。测试方案中的样本量和评估口径是本次细化建议，需在执行前冻结；性能/质量阈值继承总 PRD 初始目标，不得测完后为通过而下调。

## 2. 开始执行前冻结

- App 构建号、代码提交、Web/服务端版本、数据库版本。
- 模型、提示词、端侧模型包、功能开关与额度策略版本。
- 首发平台、最低系统、低/中/高性能设备和 Web 浏览器名单。
- 网络条件（带宽、延迟、丢包）、图片格式/分辨率/大小、测试集清单与授权。
- 两个独立测试用户、游客空间、运营角色、测试账本和模拟供应商。
- 支持的输入格式/文件大小上限、数据删除和备份处理时限，在发布前填明。未冻结时相关用例阻塞。
- 数据样本：空库、500 件衣物库、有效/在洗/归档/待确认对象、单人/多人/遮挡/损坏图片、同步冲突和历史快照。
- 负责人、执行日期、测试环境；所有证据来自测试账号，不将私人生产图提交至公开仓库。

## 3. 状态与证据

| 状态 | 使用条件 |
| --- | --- |
| 未执行 | 尚未开始 |
| 通过 | 全部预期满足，环境与证据齐全 |
| 失败 | 至少一项预期未满足，关联缺陷 |
| 阻塞 | 缺少构建、权限、环境、接口或测试数据，无法作出结论 |
| 不适用 | 本版本不开放的 P1/P2/条件功能，有范围依据 |

截图用于证明界面；持久化、权限、幂等与成本须有对象差异、接口/网络、日志或账本证据。录屏必须能看到从操作到结果。日志脱敏且禁止包含供应商密钥、令牌、原始私人图片和完整自由文本。

每个执行结果需有用例编号、构建、环境、步骤、实际结果、证据、缺陷、执行人和日期。修复后保留原失败记录并追加复测，不用覆盖原记录隐藏缺陷。

## 4. 缺陷等级

| 等级 | 示例 | 发布处理 |
| --- | --- | --- |
| S0 严重 | 越权读取、未授权照片上传、已确认数据不可恢复丢失、重复扣费 | 阻止发布 |
| S1 高 | 无法导入/拆分确认/搭配/保存、离线无法使用、核心流程持续崩溃 | 阻止发布 |
| S2 中 | 有绕行方案的非核心功能问题、局部状态不准确 | 记录影响与修复计划；不得据此把失败 P0 写为通过 |
| S3 低 | 不影响操作的轻微样式或文字问题 | 可记录遗留项并指定负责人 |

安全隔离、数据完整性、账本幂等和隐私授权不得以用户体验豁免绕过。严重度用于排期，不代替用例通过判定。

## 5. 性能与 AI 评估方法

- P95 使用排序样本的第 ceil(0.95×n) 项；记录样本数量、失败数、超时数和原始测量。
- 每项性能测试至少 100 次；冷启动必须进程未运行；首次安装/模型下载单独记录，不混入已就绪口径。
- 云端端到端耗时从授权后提交到可展示结果，包含上传、排队、执行与下载；网络条件必须固定。
- 超时和失败单列统计，不能只展示成功请求的漂亮分位数。记录成功样本 P95 与全量失败率，阻断错误单独评估。
- 类别宏平均 F1 为各约定类别 F1 的算术平均，逐类列出 precision/recall/F1；预先冻结标签。
- 抠图可用标准：目标完整、无明显背景残留、边缘不需人工修正；至少两名评审独立打分，分歧复核。
- 真人预览如启用，另记录服装颜色/图案/轮廓与人物一致性；不得以画面好看替代衣物一致性。
- 端侧性能需记录耗时、峰值内存、模型包大小、温升和电量；阈值未冻结不得宣称全机型支持。

## 6. 发布门槛

1. 本次所有适用 P0 用例 100% 通过；相关冻结指标达标，核心功能无未执行或阻塞项。
2. 无未关闭 S0/S1；其他遗留问题列出影响、负责人、计划并经产品/研发/测试签署。
3. 不适用项有范围说明及关闭入口证据；不因未开发将 P0 改为不适用。
4. 断网、杀进程、重复请求/回调、同步冲突、账号切换、导出恢复、未授权上传和越权读取测试通过。
5. 有可安装/部署产物、版本清单、配置说明、升级/迁移/回退与恢复演练证据。
6. 运营具备任务观测、异常告警定位和模型/配置回退能力。
7. 上架前完成目标地区/平台届时要求的专项检查，具体依据和负责人另行记录，不凭本需求文档推断已合规。

## 7. 建议执行顺序

游客离线冒烟 → 衣物拆分 → 推荐换搭 → 记录 → 云端任务 → 同步/恢复 → Web → 后台权限 → AI/性能 → 发布演练。失败后针对相关变更和依赖回归，不用重复通过的无关测试替代问题修复。

## 8. 自动化边界

适合自动化：ID 归属校验、幂等、账本、数据关系、同步冲突、权限接口、规则推荐与核心冒烟。

需人工结合：抠图质量、视觉一致性、屏幕阅读器与大字体、首次上手体验、三维表现。自动化截图相似不代表完整验收。
