## 阅读和维护规则

- 需求编号为 REQ-模块-序号，验收编号为 TC-模块-序号；编号稳定，删除需求时保留废弃说明，不挪用旧编号。
- 每个需求包含规则、输入、操作/异常、输出与对应验收，当前实现状态统一为待开发。
- P0：首版；P1：增强；P2：探索。真人试穿、完整三维、跨图片高级批量和周计划不因拆分而提前为首版必做。
- 基础多选编辑属于现有 Web 整理；跨图片自动批处理属于后续高级能力。
- 本地基础操作与规则搭配必须可用；完整端侧 AI 与设备覆盖以实机验证为准。
- 需求总纲、详细需求、验收发生冲突时暂停相关实现并通过变更记录明确决策，不由开发或测试自行扩大范围。
- 架构与具体框架/模型选型仍待技术评审，不在本文声称供应商能力已接入。

## 分工建议

产品维护范围与优先级；设计维护页面状态；客户端负责本地体验与数据；服务端负责同步与权限；AI 负责拆分/推荐及评估；测试负责证据与结论。以上是角色分工，不代表已分配具体人员。
