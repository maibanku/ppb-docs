# 3D 形象、真人预览与形象管理

[需求目录](./README.md) · [验收](../ac/09-形象管理与真人预览.md) · [技术设计](../tech/形象与试穿技术设计.md)

## 1. 当前缺口与本次决策

原文仅规定 W09 真人预览 P1、W12 可旋转三维 P2，没有体型参数、形象管理、衣物资产映射、结果失效和双端编辑规则。本次拆分 W12：**参数化模板形象与管理页调整为 P1；照片重建真实数字人、完整衣物建模与布料仿真保持 P2。** 此为需求变更，不表示功能已实现，也不改变原有 P0 衣橱闭环。

展示舞台仍在“穿搭”页；“衣柜”保持分类单品网格，在单品详情可进入“查看搭配效果”；不把整个衣柜网格改成人物页。三个底部入口不变。

| 展示模式 | 核心用途 | 允许交互 | 局限与回退 |
| --- | --- | --- | --- |
| 二维拼搭 | 快速挑选真实单品 | 同类替换、锁定、随机 | P0，始终可用 |
| 3D 形象 | 查看轮廓、颜色与组合关系 | 真正旋转、缩放、模板发型/体型调整 | P1，模板服装只能称款式示意 |
| 真人效果 | 在本人照片上查看选定衣物 | 查看已生成图、放大、按需重新生成 | P1，二维图片，不支持自由旋转 |

无形象/无兼容资产时回到二维。仅当功能开启且资源满足条件才显示相应模式。首次不强迫选择形象或填写身材。

## 2. 页面设计

- 穿搭页顶部放轻量“拼搭 / 3D / 真人”分段控件；主舞台保持白底、右侧部位栏、左侧当前部位缩略图、下方三项快捷操作和低胶囊导航。模式切换不更改 outfit、选中品类或锁定项。
- “我的 → 我的形象”为正式入口；穿搭页人物旁的编辑图标为快捷入口，指向同页。二级页隐藏主 Tab，顶部返回和保存，中间实时 3D 预览，底部“外观 / 身材 / 穿搭”三个面板，每次只展开一个。
- 外观：模板、发型缩略图、发色；更多里选择肤色。身材：身高、体重两项优先可见，展开才显示胸腰臀围、肩宽、内侧腿长与视觉比例。穿搭：场景、松紧偏好、裤长偏好、配色偏好；每项给简短文字而非裸数值。
- 草稿改动实时本地预览，不发起云端生成；保存才提交新版本。返回时有改动提示保存/放弃，支持重置当前分组并撤销。日常使用无需每次进入管理页。
- 真人模式首次仅显示“添加本人照片”；材料齐全后主动作“生成效果”，先展示本次上传对象与额度；生成中可离开页面。再次进入可恢复任务。
- Web 个人端增加“我的形象”：左预览、右参数、底部保存；数据来源仅为主动同步/导入。运营后台另设公共模板资产管理，不能用管理员身份替用户修改身体数据。

## 3. 参数字典与影响范围

以下数值为首轮成人模板支持范围草案，发布前需按资产实测冻结；不代表健康标准。超出模板支持范围仍允许保存用户真实数值，但不直接套到网格，明确“此模板暂不支持”，可选其他模板或二维。非法值拒绝保存；空值不是 0。

| 参数字段 | 单位/取值 | 来源及生效范围 |
| --- | --- | --- |
| height_cm | cm；模板暂拟 140–210 | 用户输入，步长 1；调整形象尺度，影响比例建议 |
| weight_kg | kg；模板暂拟 35–180 | 用户输入，步长 0.5；仅作粗略体型条件，不推算真实三围 |
| chest_cm / waist_cm / hip_cm | cm；各自可空；正数 | 用户自填测量，可单项填写；优先于粗略估计，缺失保留未知 |
| shoulder_cm / inseam_cm | cm；正数，可空 | 自填；肩宽/内侧腿长，附测量示意 |
| body_fullness / shoulder_ratio / leg_ratio | 0–1；模板内归一化 | 视觉滑杆，仅“形象调整”，不得回写为测量值 |
| hair_style_id / hair_color | 目录 ID / 调色板值 | 只更换 3D 头发；不得静默修改本人照片 |
| skin_tone_id / template_id | 目录 ID | 可选模板外观，不推断用户族群 |
| fit_preference | fitted / regular / relaxed | 合身/常规/宽松，参与排序，不直接改变原衣尺码 |
| trouser_length_preference | cropped / regular / full | 九分/常规/盖鞋，参与建议；无长度数据不能断言实际裤长 |
| formality_level / warmth_preference | 1–5，偏好枚举 | 正式程度、怕冷/中性/怕热；用于组合排序，非商品实测数值 |
| preferred_colors / excluded_tags | 色组 / 标签集合 | 显式偏好；不喜欢的约束可编辑、重置 |

体型估计单独记录 estimated_shape，不把推断作为事实。照片不自动估重、估身高；以后加入测量须另行验证。真实测量、视觉形象、穿搭偏好分别保存。真实照片按自身像素/姿态生成；单改身高体重不能声称照片已准确变成该体型。对当前真人底图不生效的参数明确提示；新发型仅在将来独立“生成新形象照”中处理，首轮不纳入。

## 4. 逐项需求

所有需求状态：待开发。每项与同号 TC-AVA 用例一一对应。

### REQ-AVA-01 多模式舞台与真实能力（P1；真实性约束所有版本适用）
输入同一套 outfit。切换模式保留单品 ID、selected_category、locked_item_ids 和草稿；只有真实网格可旋转。无资产/功能未开显示二维和原因，不出现空白旋转舞台。验收 TC-AVA-01。

### REQ-AVA-02 形象管理与草稿保存（P1）
两个 App 入口同页。局部修改即时预览，保存递增版本；放弃恢复已保存值，重置可撤销。首次允许跳过，杀进程后恢复持久草稿并提示。保存失败保留本地草稿。验收 TC-AVA-02。

### REQ-AVA-03 发型、发色及模板兼容（P1）
仅列出当前模板支持且已授权的发型，兼容头部锚点和帽子规则。缺资源可下载或保留旧发型；离线使用已下载资产。切发型不改 garment 或本人照片，模板切换显示不兼容字段并经确认重置。验收 TC-AVA-03。

### REQ-AVA-04 身体数据与视觉调整分离（P1）
所有参数可不填；检查单位、有限正数、小数精度及模板支持域。身高体重相同可有不同形象；三围不强行估计，视觉滑杆不覆盖测量。超支持域保留测量并提供降级。验收 TC-AVA-04。

### REQ-AVA-05 穿搭参数与推荐解释（P1）
按参数字典参与排序；显式排除、锁定、选中品类约束先执行。换宽松偏好不篡改衣物尺寸；无实测数据只给风格建议。相互冲突时说明哪项未满足，保留原组合。验收 TC-AVA-05。

### REQ-AVA-06 照片衣物到 3D 的映射（P1 模板；P2 精确资产）
Garment 的原图/蒙版、3D 模板映射、真实衣物网格是不同资产。映射记录来源和置信；模板明确“款式示意”，支持列表按类/版型/模板版本限制。无对应资产的衣物仍在清单中可见，不用其他款暗中替换；可整体回二维。验收 TC-AVA-06。

### REQ-AVA-07 真人底图与授权（P1）
用户明确选择本人或已获授权的单人照片，做多人、遮挡、全身完整度提示；仅支持经验证的输入，不把坏图直接收费送生成。云端授权列出底图、单品图和必要参数；仅本地模式不上传。原图保留，输出带 AI 标识。验收 TC-AVA-07。

### REQ-AVA-08 按需生成与失败恢复（P1）
随机换一件仅更新组合，真人旧图立即标“待更新”，不自动付费生成；用户点生成才新建任务。服务端冻结衣物、底图、形象/偏好和渲染配置版本。取消、超时查询、重试、额度预占遵循原任务规则；失败可保存组合。验收 TC-AVA-08。

### REQ-AVA-09 版本、过期与历史（P1）
底图、有效衣物版本或模式相关参数变化时，缓存键变化。晚到结果只绑定原快照，不覆盖当前组合；过期结果可查看来源，不显示成当前效果。修改发型只使 3D 快照失效，不声称真人已更新；历史衣物组合保留快照，私人形象资源删除规则见 REQ-AVA-11。验收 TC-AVA-09。

### REQ-AVA-10 Web 编辑与公共资产后台（P1）
个人端只编辑本人已同步/导入形象；版本冲突返回两版并由用户选，不静默覆盖。资产管理员可上传、校验、预览、灰度发布和回滚公共模板/发型/服装映射；无商业使用授权或不兼容资产不得发布。用户身体数据不进入公共目录。验收 TC-AVA-10。

### REQ-AVA-11 数据隔离、导出与删除（P1；上传/权限底线 P0）
头像照片、测量、视觉参数独立同步选项，授权不由登录/其他衣物授权代替。导出含版本和引用；删本人底图/形象时可选清理派生图，明确本机/云端范围、备份处理期限和执行状态。撤销后禁止新上传；删除墓碑阻止晚到任务与旧设备恢复照片。历史可保留非敏感搭配清单，对被删私人人像显示占位，不以快照为由保留已请求删除人像。验收 TC-AVA-11。

### REQ-AVA-12 质量、资源与降级（P1）
发布冻结支持模板、设备、OS/浏览器、版型和模型类别。3D 性能、极值变形、穿模、发型/帽子/包带遮挡和真人保真分别评估；不支持的类别不承诺整套试穿。发热/内存压力释放网格并降级二维，读屏可完成等效换搭。验收 TC-AVA-12。

## 5. 开发交付顺序

1. P0 继续完成二维、数据归属、授权和真实能力标识。
2. P1a 验证一个通用骨架、体型变形、至少 3 个发型、上衣/下装/鞋模板链路；完成管理页及离线保存，未映射衣物走二维。
3. P1b 在授权、成本与保真评估通过后开放真人效果，先公布已验证的品类，包和配饰不能默认承诺支持。
4. P2 再验证照片到专属网格、单品真实三维、布料仿真及合身测量。每阶段单独开关与发布验收。

接口、数据、缓存、资产流水线与拟定性能门槛见技术文档。以上为产品与工程方案，未实现、未测试。
