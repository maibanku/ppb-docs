# 文件平台 PRD
> v0.1，拟实施基线。

## 目标与边界
支持多业务统一存储，避免业务保存永久物理URL或各自实现大文件上传。业务附件、用户个人文件、平台治理分开授权；不以全平台上传者清单代替业务权限。

|主体|负责|边界|
|---|---|---|
|文件服务|文件身份、真实元数据、上传、存储、签名访问、引用保护、容量记账、GC|不判断聊天成员或作品公开规则|
|业务服务|文件用途、排序、业务映射、用户权益、访问裁决、业务回收站与发布|不保存桶凭据，不直接删除共享内容|
|媒体Worker|探测、封面、转码、播放包、失败重试|不自行公开内容，不决定作品是否发布|
|IAM|身份、应用客户端、平台权限|IAM登录不自动赋予业务资源权限|

## 首期需求
- F-01 独立用户工作台、平台管理台及可嵌入上传组件；同一上传队列内可暂停、续传、取消、重试。
- F-02 多应用接入、可信服务身份、应用隔离、每应用上传政策。
- F-03 稳定文件业务键、真实元数据、批量查询、重命名；文件内容不可变。
- F-04 单次直传与原生Multipart、断点续传、完成幂等、过期Abort。
- F-05 通用引用准备/提交/释放、业务outbox、乱序防护与对账。
- F-06 下载/预览/播放凭证；私有源站、Range、凭证轮换与撤销边界。
- F-07 回收站恢复、容量预留/提交/释放、GC及缺失告警。
- F-08 媒体任务：视频探测、封面、可播放MP4；HLS/DASH为P1。
- F-09 管理配置、使用量、任务、异常、审计；内容查看单独授权。
- F-10 版本化迁移、旧接口适配、灰度与回滚。

## 首版范围与目标
P0：IAM接入、应用隔离、个人工作台、管理台、直传/Multipart、引用保护、下载、回收站、真实元数据与容量账本；视频原片上传与MP4 Range下载属于P0。视频探测/封面/转码作为可开关Worker子阶段P0.1；未开启时不伪报可播放。
P1：多清晰度流媒体/CDN、存储迁移、成本分析；目录/标签/搜索按独立工作台需求推进。
P2：外链分享、协作ACL、在线编辑另立设计；首版不提供匿名公共链接。

初始目标（待实测）：小文件直接PUT，超过64MiB建议Multipart；16–64MiB分片、移动端3–4并发。默认业务单文件上限按政策配置，不把10GiB写成全应用硬限制。file_console初始政策建议10GiB，必须先配置大于文件上限的容量池；chat/avatar等沿用更小限制。以1/10GiB和弱网中断验证，不能把测试目标当成果。

## 业务规则
文件上传成功、媒体处理成功、业务发布成功相互独立。引用未解绑时用户工作台不能彻底删除业务附件。业务回收站内仍持有保护引用；真正清除后才释放。个人文件回收站默认30天且继续计费；无引用上传保护默认72小时，引用准备态必须对账后才能释放。逻辑计费用量与物理去重字节分开显示。

## 数据与安全
业务映射存稳定file_biz_key和用途，可存经服务确认的展示快照；不保存签名URL或存储路径。不跨库JOIN。跨应用复用必须走受控复制授权，不能凭知道文件键绑定。客户端不能传任意主体或应用绕过身份上下文。
