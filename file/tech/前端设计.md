# 独立前端设计
> 拟实施；工程名为规划。

## 工程与部署
- file-web：Vue3+TypeScript+Vite，个人文件工作台，独立构建/路由/部署。
- file-manage-web：平台治理台，复用base-manage-web通用壳和权限组件，但独立入口、会话和构建产物。
- 上传SDK/组件：轻量版本化包，提供会话、分片、恢复、进度、取消、错误码；不依赖整个后台工程。
- file-console-bff：可先作为独立模块与server-file同进程部署；以受限服务身份调用核心服务，保存个人目录等业务元数据时用独立schema；不能从浏览器直接访问内部API。

## 用户工作台
|路由|页面内容|交互与状态|
|---|---|---|
|/files|个人文件列表，文件类型筛选，搜索，排序，容量|默认仅file_console；游标分页；只返回授权项|
|/uploads|上传队列，速度，进度，暂停/继续/取消/重试|暂停停止新分片并中断在途请求；已落分片保留；刷新恢复需重新选择同文件并核验指纹，浏览器文件句柄能力可选|
|/files/:fileBizKey|真实元数据、预览、下载、重命名、处理产物|未就绪显示处理中；失败原因可恢复；不存在/无权一致提示|
|/recycle-bin|回收、恢复、彻底清除、剩余保留期限|显示仍计费；彻底清除二次确认；业务附件不在此操作|
|/usage|已提交用量、其中回收站、上传预留、总额度|used已包含recycled，不能重复相加|

业务应用上传SDK仅显示队列并回传file_biz_key，由业务应用保存映射。工作台不直接列跨业务附件；可提供业务链接，跳回业务端完成权限判断。

## 平台管理台
总览/应用政策/存储实例/文件元数据/上传会话/引用保护/媒体任务/异常与对账/审计。权限示例：
`file.metadata.read`、`file.storage.manage`、`file.policy.manage`、`file.quota.manage`、`file.lifecycle.manage`、`file.audit.read`、`file.content.inspect`。
接入IAM角色菜单/按钮映射，服务端逐请求验证权限和应用数据范围；有菜单不等于可以操作。下架、恢复、清理、改额度需要原因与审计；下架记录不能通过重命名覆盖。

内容检查使用单独短期授权与理由，记录访问审计；不把运营人员默认变成所有用户文件的下载者。凭据表单只写密钥引用；服务端回显脱敏，不返回密钥。

## 认证与安全
用户端与管理端独立IAM客户端/会话，OIDC code+PKCE及BFF流程遵从IAM技术大纲。Cookie修改请求检查CSRF/Origin；不把IAM ID Token当文件API授权。预签名URL不进持久化状态、日志、埋点或复制链接；页面不可信文件名按文本渲染。
预览活跃内容使用隔离源/安全下载策略，不直接在主站执行HTML/SVG。视频URL到期重新向业务BFF申请；Range支持仍须鉴权，不能关闭签名检查解决拖动问题。

## 设计风格与无障碍
白色背景、紧凑列表、清晰状态；桌面左导航，窄屏底部精简入口。上传队列固定可见但不遮挡主操作。键盘可操作、焦点可见、进度有文字/屏幕阅读器信息；失败重试保留用户输入。
