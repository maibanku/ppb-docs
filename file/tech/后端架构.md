# 后端架构
## 模块与依赖
server-file为独立Go服务：application/policy、upload、resource、reference、access、quota、storage、lifecycle、audit。存储适配local（开发）、MinIO/OSS/S3（按后端能力矩阵启用）。生产大文件走对象存储。HTTP控制API与对象字节通道分离；gRPC仅元数据控制，不传GiB bytes。
file-worker领取数据库任务（租约+CAS）或消费可靠队列，处理校验、迁移、GC；媒体Worker与API分进程。媒体库ppb_media独立迁移，首版可共享基础设施但不反向依赖业务库。

## 信任边界
浏览器只调用业务BFF/个人BFF和对象存储受限URL；/internal/file/v2不经公网路由。业务服务用mTLS或限定audience/scope的服务令牌认证，application_biz_key与客户端绑定。客户端不能自报application_id、user_id、billing主体；BFF根据已验证会话派生，文件服务核验应用允许主体与政策。IAM登录本身不授予任何文件读取权。
内部元数据批量接口仅供受信服务，按调用应用和已绑定引用/上传归属范围过滤；拒绝凭键探测其他应用资源。管理员权限回源IAM/授权端口，管理台服务独立鉴权。

## 授权
业务每次判断ACL→向file申请指定reference_key的download/preview/play授权。文件侧核验service client、应用、引用有效且所属文件、文件就绪、未下架、作用域和TTL，再返回短期URL。不能用上传者直通绕过原业务ACL。
同应用内部签发权也按client scopes和允许业务类型限定；受信业务服务被攻破的风险由最小权限、审计和撤销控制。

## 生命周期与计数
文件内容不可变。file_status=1 verifying / 2 ready / 3 recycled / 4 purge_pending / 5 purged / 6 failed；restriction_status=0 normal / 1 blocked，独立于文件状态。
blob_status=1 staging / 2 available / 3 deleting / 4 deleted / 5 broken。
logical_ref_count为尚未purged逻辑文件行数（包括个人回收站与媒体输出file）；业务引用数量不直接加到blob计数。删除逻辑文件前必须无prepared/active/recycle/processing保护。
GC事务锁定blob，复查真实非purged文件、未完成会话/任务占用和计数，CAS available→deleting后提交；新绑定/上传复用须锁同blob并拒绝deleting。后台删除对象，成功后更新deleted；失败留状态重试。仅SELECT FOR UPDATE但解锁后直接删对象不足以保证正确性。孤儿清理也需相同发布/认领互斥协议，不能靠两次查询替代。
计数按实际状态迁移的行数分blob聚合，不能先去重blob ID再统一减1；有repair任务重算但不以repair掩盖写入错误。

## 容量
file_quota按应用+主体类型(user/workspace/application)+主体键唯一，应用池另行统计/限制。reserved在创建上传时原子预留，完成后reserved→used同事务，失败/取消释放一次；used含回收站，recycled是其子集。实测大小与声明不符拒绝或在政策允许时重新原子核额，不能盲加。
跨服务业务付费权益由业务决定；技术配额是文件服务最后防线，0=禁止新增、NULL=应用默认，不混用无限额度。所有增减写quota_events，按event_key唯一；恢复不重复记账。对账用revision_number CAS或在同主体锁下完成，旧SUM不能覆盖新上传增量。

## 运维
版本化迁移与schema验证；禁止生产启动AutoMigrate。Liveness/readiness分开；指标包含完成率、失败码、吞吐、临时容量、预留积压、prepared老化、GC重试和缺失对象。任务游标分页，不全库全桶载入内存；超时、重试退避、租约续期、死信和人工处置。备份覆盖元数据、对象版本/备份策略及恢复后引用对账。签名URL/凭据/文件内容不进入日志。
