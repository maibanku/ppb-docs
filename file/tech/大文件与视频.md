# 大文件与视频
## 大文件传输
控制API只承载JSON元数据。small direct_put或multipart由政策及存储能力决定，超过64MiB建议multipart；16–64MiB分片、3–8并发为起点；动态选片确保不超后端分片数和最小/最大限制。适配器显式报告MinIO/OSS/S3支持的大小、校验、签名头、ListParts与Abort能力，不能假定各实现完全一致。

init→文件侧CreateMultipartUpload→按需签发part URL→客户端UploadPart→文件侧ListParts恢复→complete由服务端核对并调用CompleteMultipartUpload→Head/可信校验→ready。客户端不得任意传object_key、bucket、backend。单次PUT同样上传到唯一不可变对象键，不覆盖已有资源；URL未到期可被重放覆盖的风险通过版本固定、条件写/复制到不可写正式键及状态确认处理，不能只在DB置done就认为字节不可变。
ListParts分页，DB分片表是缓存；最终以存储侧结果为准。续签只能签原会话对象，重新验证主体、状态、政策、容量。分片URLs10分钟、会话24小时起步，可按应用政策延长；旧URL到期后已上传分片仍可恢复。
完成CAS ongoing→completing，使用lease；完成对象但DB提交失败由recover任务查询对象和会话恢复，不立即释放容量或删内容。完成重试返回同file_biz_key；completing返回202状态；取消与完成串行，已done取消409。超期Abort完成前再次核验状态，失败保留任务重试。
原生Multipart未完成部分和单次直传临时对象都纳入临时用量与生命周期；DB状态及对象存储Abort规则双兜底。

## 校验与去重
不强制上传前整文件SHA-256。声明大小用于预留，真实大小由后端核对；声明MIME不作权威；探测与校验未完成状态为verifying。记录checksum_algorithm、checksum_type(full_object/composite/part)、checksum_value；ETag独立字段，不推定等于MD5/SHA-256。
可信完整hash可后算，未确认不参与hash去重。默认应用内dedup_scope；首期不开放跨用户“凭hash秒传”。后续复用只允许已授权资源，持有局部字节不是普遍可靠的全文件所有权证明。大文件下载不每次全量重哈希。

## 视频
媒体库media_assets（真实媒体属性）/media_jobs（版本化处理任务）/media_outputs（MP4/封面）/media_packages（HLS/DASH逻辑包）。独立Worker资源限制、隔离执行、禁任意外部URL输入，只消费被授权file键；处理幂等键为application+input_file+profile_version+request_key。文件是否ready与媒体是否ready、业务是否published分开。
任务先取得processing引用保护输入；输出新file并创建processing引用；业务接收产物、提交映射引用后释放任务保护；取消/失败输出按保护规则清理，不能删掉已被业务使用的输出。
HLS/DASH多个清单和切片组成一个package，对业务暴露package_biz_key，不给每个切片建立业务可见file。package映射不可变后端位置、对象前缀、对象清单与状态；Worker写完再原子发布清单指针，失败包不公开。GC以包为单元清理；manifest存储在系统生成受控位置，禁止任意key路径。
视频原片及衍生物、播放包各计费一次，实际字节形成容量流水；processing预留输出预算，不足时任务停止/等待，不能绕过配额。HLS包前缀资源需纳入物理使用与缺失巡检。

## 播放
MP4使用Range/206、Content-Range、Accept-Ranges、ETag/Last-Modified与条件请求；授权通过后才访问对象。可用对象存储/CDN实现。
HLS必须保护主清单、子清单、切片、字幕和密钥（如有）；只保护m3u8不充分。CDN签名cookie或边缘授权使用包级范围，私有源站防直连；短期签名泄漏在TTL内可访问，要求即时撤销则引入在线授权及版本检查，不能声称JWT/URL天然即时失效。
起步访问URL5分钟、part URL10分钟，业务可缩短；TTL受应用上限约束。
