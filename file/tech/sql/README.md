# SQL 基线
- [schema.sql](schema.sql)：15张文件核心表，MySQL8.0.16+新库目标态。
- [media.sql](media.sql)：4张可选媒体表，ppb_media库；P0.1探测/MP4、P1播放包。
- [数据模型](../数据模型.md)补充约束与记账语义。

不要在存量ppb_file直接执行这些CREATE TABLE；先由版本迁移脚本盘点差异、回填、验证、灰度。未实际运行MySQL，当前交付不声称可直接投产。开发SQLite必须单独编写迁移和约束行为测试；MySQL JSON/排序规则/锁语义不能原样照搬。

全部实体主键应用侧雪花发号，file服务沿用经确认的唯一节点分配；媒体Worker若发号需分配不同节点/worker标识，部署前防重复。ID通过JSON传字符串。精确身份字段utf8mb4_bin，字段名均两词以上snake_case。
状态数据不能仅按deleted_flag过滤；file软删字段与file_status由同事务维护，purged保留身份墓碑。过程/物理/账本/审计表不强加软删；生命周期状态与归档策略明确。
SQL不声明外键，插入/状态迁移校验逻辑引用、同应用、计费主体、状态；所有余额与流水同事务，released引用不可复活。
同一blob单主位置由锁+事务保证，迁移只能在校验新对象成功后切主。哈希NULL可多行表示未校验，不得用空串占唯一键。哈希确认发生并发去重冲突时锁定并归并位置/逻辑关联，不能丢失已发布对象。
