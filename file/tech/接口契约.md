# 常用接口契约
> v0.1拟实施。完整路径、请求/响应schema、错误状态、安全方案见[OpenAPI](api/openapi.yaml)。共49个操作；新v2不覆盖现有v1/proto。JSON使用snake_case，旧camelCase由兼容层转换。

## 1. 暴露范围与通用约定
- `/api/v2/file`：file_console个人BFF，只对本人及个人应用资源开放。其他业务浏览器应调用自身BFF，其上传代理使用内部契约。
- `/internal/file/v2`：仅可信服务网络+服务身份，client绑定应用与scope；不是客户端可自由调用的公共API。
- `/api/v2/manage/file`：平台管理台，服务端逐操作验证IAM权限和应用数据范围。
- `/internal/media/v1`：可信业务提交媒体作业，P0.1；HLS包操作、包引用和播放签发的完整API为P1评审项，不把file_id套用于包。
- 身份不从URL query的memberBizKey等用户声明取值；主体来自BFF会话/受验证服务上下文。服务令牌不是任意应用用户token；用户uploader可空仅允许授权系统client。
- JSON成功为`{code:"FILE-0000",request_id,data}`；错误为`{code,message,request_id}`且HTTP非2xx。202仅代表受理/处理中。日期RFC3339 UTC；内部雪花ID在JSON中十进制字符串。
- 修改请求必须`Idempotency-Key`（1–128字符）。幂等作用域=认证client+应用+方法+规范化路径+key；上传映射request_key并持久化，完成产物永久关联会话。相同key同payload返回同结果，不同payload409。一般响应缓存至少24h；过期仍由资源状态/版本守卫，不得再次执行余额动作。
- Cookie修改请求另带`X-CSRF-Token`并校验Origin。签名URL是秘密，日志脱敏，禁止存业务表。
- 列表采用limit(1–100,默认20)+cursor，稳定排序create_time/id。游标签名并绑定应用/筛选条件，换条件重新查询。默认只列有效状态，回收站接口单独查询。
- 重命名/政策/下架/额度更新检查revision或policy_version；公开响应提供对应版本。引用路径与body重复键必须一致。
- metadata批量最多100；拒绝与不存在统一unavailable_keys，不泄露跨应用是否存在。

## 3. 创建上传示例
业务服务已从会话与业务政策确认用户、应用和计费主体后：
```http
POST /internal/file/v2/uploads
Authorization: Bearer <service-token>
Idempotency-Key: camera-upload-request-001
Content-Type: application/json

{
  "application_biz_key": "app_camera",
  "uploader_user_id": "9007199254740993",
  "quota_biz_key": "fq_example",
  "original_name": "trip.mov",
  "declared_bytes": 2147483648,
  "declared_mime": "video/quicktime",
  "upload_mode": "multipart"
}
```
```json
{
  "code": "FILE-0000",
  "request_id": "req_example",
  "data": {
    "upload_biz_key": "upl_example",
    "upload_mode": "multipart",
    "upload_status": "ongoing",
    "part_size": 33554432,
    "part_count": 64,
    "expire_time": "2026-10-28T12:00:00Z"
  }
}
```
declared_bytes不能大于应用单文件上限/容量剩余；quota账户必须同应用、主体来源可信。file_console公开init不接受这些主体字段，BFF派生，防止越权。

## 4. 分片与完成
```http
POST /internal/file/v2/uploads/upl_example/part-urls
Authorization: Bearer <service-token>
Idempotency-Key: part-url-batch-001
Content-Type: application/json

{"part_numbers":[1,2,3,4]}
```
返回每片upload_url、required_headers、expire_time。客户端PUT字节到URL并遵守签名头；后端CORS只放行需要的方法/头，允许客户端读取ETag等必要响应头。失败只重传该片。GET /parts按后端分页结果恢复；重新签URL使用新Idempotency-Key，旧key在幂等缓存期内仍返回原URL，不能误以为续期。
```http
POST /internal/file/v2/uploads/upl_example/complete
Authorization: Bearer <service-token>
Idempotency-Key: complete-upload-001
Content-Type: application/json

{"parts":[{"part_number":1,"provider_etag":"example-etag"}]}
```
上例只展示一个分片条目；生产提交完整分片清单，服务端与存储核对。direct_put完成可提交{}。完成200返回Upload（含file_biz_key；可能仍verifying），处理中202返回Upload；轮询GET会话，只有对应File为ready才准备引用。取消202返回task_biz_key，使用内部/管理任务状态查询；个人BFF只暴露本人取消状态并轮询会话，不开放全局任务查询。done后取消409。

## 5. 引用准备与提交
```http
POST /internal/file/v2/references/prepare
Authorization: Bearer <service-token>
Idempotency-Key: prepare-camera-001
Content-Type: application/json

{
  "application_biz_key":"app_camera",
  "reference_key":"camera-work-example-original-001",
  "file_biz_key":"file_7f6b6d51a9bc4fa18d00391025913cc2",
  "reference_type":"camera_work_original",
  "reference_version":1
}
```
文件服务验证同应用、ready、无平台下架、认领权限并转prepared。业务写映射+outbox成功后：
```http
PUT /internal/file/v2/references/camera-work-example-original-001
Authorization: Bearer <service-token>
Idempotency-Key: commit-camera-001
Content-Type: application/json

{
  "application_biz_key":"app_camera",
  "reference_key":"camera-work-example-original-001",
  "file_biz_key":"file_7f6b6d51a9bc4fa18d00391025913cc2",
  "reference_type":"camera_work_original",
  "reference_version":2,
  "target_status":"active"
}
```
业务回收改target_status=recycle并递增版本，恢复active；彻底删除递增版本released。相同reference_key永久关联同file；released终态；release早到必须落墓碑。prepared无业务结论不能自动到期删文件。[一致性详文](业务接入与一致性.md)。

## 6. 访问签发
```http
POST /internal/file/v2/access-grants
Authorization: Bearer <service-token>
Idempotency-Key: access-camera-001
Content-Type: application/json

{
  "application_biz_key":"app_camera",
  "file_biz_key":"file_7f6b6d51a9bc4fa18d00391025913cc2",
  "reference_key":"camera-work-example-original-001",
  "actor_subject":"user:9007199254740993",
  "action_code":"download",
  "ttl_seconds":300
}
```
业务必须先核对该请求用户对作品/消息的权限，actor_subject只用于受信审计不能替代鉴权。文件服务核验service范围、active引用与文件/后端状态后返回access_url、expire_time、required_headers；后端不支持动作/产物未就绪则409/422。续期用新幂等key并重验业务权限。只知道file_biz_key不能获取URL。短期签名到期前可能被持有者重用；即时撤销需在线边缘校验。

## 7. 常用写入规则
- PATCH文件仅改original_name与revision_number，不覆盖字节；换内容需新上传/新键。
- recycle/restore/purge仅file_console个人资源；BFF验证owner及应用。回收同事务维护个人引用recycle和file状态；purge释放该个人引用后检查其他保护，存在其他引用则409且整个请求回滚；返回202不代表对象已经删除。
- 应用政策PUT只允许已在IAM存在的应用；path/body应用键必须一致，policy_version作CAS；首次创建version=1，更新提交当前版本并由服务器递增。
- 后端凭据只提交credential_ref，GET响应仅credential_configured；修改实例不能使存量位置瞬间指向不同物理桶，变桶需新建实例+迁移。
- quota_bytes=null恢复默认，0禁止新增，负数400；余额不由管理请求直接覆盖，额度低于当前用量允许但阻止新增，流水和审计记录原因。
- restriction_status=blocked优先于所有业务签发；恢复normal不自动恢复purged字节或业务发布状态。
- 媒体请求profile_code/version白名单，不接受任意ffmpeg命令/外部URL；相同Idempotency-Key不同输入409。

## 8. 错误码
|HTTP|code示例|含义与客户端行为|
|---|---|---|
|400|FILE-INVALID_ARGUMENT|参数/格式错误，修正输入|
|401|FILE-UNAUTHENTICATED|重新登录或刷新受控服务凭证|
|403|FILE-FORBIDDEN|动作无权；对象存在性敏感时统一404|
|404|FILE-RESOURCE_UNAVAILABLE|不存在或当前范围不可见|
|409|FILE-STATE_CONFLICT / FILE-IDEMPOTENCY_CONFLICT|查询状态/版本；不能盲重试写入|
|410|FILE-EXPIRED / FILE-PURGED|重新上传或业务提示已清除|
|413|FILE-SIZE_EXCEEDED|超政策大小|
|422|FILE-CHECKSUM_MISMATCH / FILE-TYPE_REJECTED|校验失败或真实类型不允许|
|429|FILE-RATE_LIMITED|按Retry-After退避|
|503|FILE-DEPENDENCY_UNAVAILABLE|可重试，保持同幂等键|

quota不足使用409 FILE-QUOTA_EXCEEDED，界面显示容量不足；未结束不释放预留。后端完成返回200但对象verifying不等同业务可发布。
