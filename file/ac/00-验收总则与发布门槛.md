# 验收总则与发布门槛
## 强制用例
|编号|场景|通过条件|
|---|---|---|
|AC-01|file_console工作台与管理台|会话隔离；业务附件不因上传者身份显示/可下载；管理内容查看单独授权|
|AC-02|跨应用伪造主体/文件键|拒绝绑定、元数据探测、URL签发；应用身份来自可信client|
|AC-03|新旧文件键|新键生成、唯一约束、旧键兼容；API不返回不安全大整数|
|AC-04|1/10GiB上传中断/刷新/续签|只补缺片；最终大小校验；完成重试同产物；大文件不整包进API内存|
|AC-05|完成与取消/超期/DB失败竞争|仅一个终态；对象已成但DB失败可恢复；预留不重复释放|
|AC-06|业务commit失败/消息延迟/乱序release|prepared保护；墓碑防复活；未知状态冻结待核对；无业务悬空可用附件|
|AC-07|原片与HLS鉴权|Range正确；m3u8、子清单、切片、字幕/密钥皆受控；源站不能绕过|
|AC-08|回收站第29天恢复|内容仍存在；used不变；恢复后不立即再过期|
|AC-09|两文件同blob同批清除及GC竞争|计数按实际文件数；无负数；新引用不能复用deleting对象|
|AC-10|并发上传+容量对账|used含回收站；reserved最终释放；CAS防旧快照覆盖；零配额拒绝新传|
|AC-11|视频失败/取消/输出被业务引用|重试幂等；输入受保护；不误删被业务绑定输出；就绪不自动发布|
|AC-12|存储迁移与灰度回滚|按存储记录路由；核验后切位置；对象缺失告警；恢复演练有证据|
|AC-13|静态契约与数据库|OpenAPI引用可解析、SQL列命名合规、链接可达本仓、MySQL执行与约束行为通过|
|AC-14|凭证重放与隐私|单次直传完成后旧PUT URL不能修改已发布版本；日志无完整签名/凭据；预览隔离|

## 环境和门槛
P0/P0.1/P1按PRD开关分批，不得将未实施流媒体能力标为通过。MySQL8.0.16+为目标，SQLite仅显式开发适配；对象存储至少MinIO并覆盖实际生产后端。安全与数据正确性用例全部通过，无P0/P1缺陷；性能SLO需记录硬件、网络、并发与p50/p95/错误率，不先宣称已达成。
文档阶段仅验证链接/契约/字段命名；完整SQL需实际数据库执行后才能打运行通过。
