## 1. 质量门禁 G1–G5

| 门禁 | 实现约束与验证 |
|---|---|
| G1 并发安全 | Swift 严格并发检查；UI 主线程；相机会话独立执行上下文；跨域仅传可安全共享的值 |
| G2 性能 | §8 真机预算；记录设备、系统、温度与数据量，未测量不得声称达标 |
| G3 引导稳定 | 时间可注入的状态机；覆盖触发/解除/冷却/升级/低置信边界；稳定场景微抖无反复切换 |
| G4 快门独立 | CameraCore 不依赖 AI、账号或额度；结构检查加超时/无网/弹层下实机拍摄验证 |
| G5 授权边界 | AnalysisUpload 与 FeedbackUpload 分别核验用途授权；拒绝云分析零分析帧上传，拒绝反馈附件零截图上传 |

静态扫描不能证明运行时隐私或快门可用，必须配合抓包、故障注入和真机操作。

## 2. 技术选型与边界

沿用现有设计方向：SwiftUI、AVFoundation、Vision、Core Image、SwiftData、StoreKit 2；服务端 Go + PostgreSQL；后台 React。这是项目选型，具体 SDK、编译器和最低系统组合在 M0 编译验证后锁定，不代表已验证兼容。

- 最低系统暂定 iOS 17，基准机 iPhone 12；最低支持设备单独跑性能验收。
- 预览用系统预览层；HUD 首先验证轻量覆盖层，只有测量表明需要时引入 Metal。不能假设自定义 HUD 与系统预览层可锁定同一提交帧。
- Vision 检测执行设备和耗时以实测为准，不硬编码“必走 NPU”承诺。
- 原片文件 + 每张独立 recipe + SwiftData 索引；Repository 隔离持久化实现。
- Redis 仅用于限流、缓存和调度优化；任务与额度一致性依靠 PostgreSQL 事务。
- 首版采用模块化单体服务，后台独立权限域；不提前拆微服务。

## 4. 帧与生命周期

分析流长边目标 512px，目标 15fps；使用只保留最新帧的有界队列，处理未完成时丢旧帧。检测、滤波、引导在专用上下文运行；原始 sample buffer 不进入 UI。低置信关节可短暂用于视觉平滑，但不能用于达标判定。

拆分两路输出：低频 `GuidanceEvent` 更新文案与触觉；有界 `OverlaySnapshot` 更新轮廓和箭头。不能仅靠状态变化事件驱动连续轮廓。坐标映射必须覆盖前摄镜像、方向、预览裁切和拍摄比例。

离开拍照页/切后台暂停检测与预览，取消当前云任务；返回重建采集与观察状态，不重放旧建议。拍摄时不等待检测。过热依次收起轮廓、降低检测频率、仅保留参考线；系统相机中断或写盘失败应明确展示，不能承诺任何硬件状态都可拍。

## 5. 引导状态机

状态为 idle → candidate → active → cleared/cooldown；同一问题可在 active 中升级文案一次。使用单调时钟注入，不依赖墙钟。

- candidate 连续 1.5s 才激活；active 连续进入解除区 1.0s 才解除。
- 同类冷却 2s；激活 6s 未解除，升级一次文案。
- 优先级：无主体 > 出框 > 大小 > 倾斜 > 头顶裁切 > 逆光 > 姿势。
- 阈值沿用需求大纲 FS-03；大小、角度等按各自方向定义滞回。
- 云结果只提供候选目标；端侧重新校验现场、置信度和优先级后决定是否上屏。
- `guidance_followed` 为激活后 6s 内完成解除驻留；每个 guidanceId 最多一次。超时后达标可显示成功，不计入该指标。
- 稳定性测试以真实场景恒定、±2° 噪声且不跨越真实问题边界为前提，60s 内无重复激活抖动；正常达标、升级与新问题出现分别统计，不混成“总事件≤1”。

## 6. 本地数据与账号边界

```text
PhotoSession: id, startedAt, endedAt?, purposeId?, templateId?
PhotoRecord: id, sessionId, createdAt, dimensions, originalPath,
             selectionState, markerState, recipeVersion, exportState
EditRecipe: photoId, styleId, lutVersion, recipeVersion, adjustments
Template: id, revision, purposeId, assetHashes, poseTemplateId, status
QuotaCache: subjectId, available, reserved, buckets[], fetchedAt, version
UploadConsent: purpose, state, policyVersion, changedAt

Application Support/Photos/{sessionId}/{photoId}/original.heic
Application Support/Photos/{sessionId}/{photoId}/recipe.json
Caches/Thumbs/{photoId}.jpg
```

每张独立目录避免连拍覆盖。原片先写临时文件，完整校验后改名，再写索引；文件与数据库不具备跨资源原子事务，启动恢复扫描补齐孤立文件或标记缺失索引。删除先标记 tombstone，再后台清理文件与索引，失败可重试，不能把文件夹删除和索引更新称为同一原子事务。

照片不按登录账号自动搬迁。本机使用者可访问本机作品；切换账号不会提供本地私密隔离。退出清空 token、账号额度与订单缓存；保留作品和本机偏好。照片排除应用自动云备份范围作为首版设计，实施时验证系统备份设置；界面明确卸载可能丢失底稿，导出到相册属于独立副本。首版不实现应用云同步。

## 7. 云分析接口与确认协议

### 7.1 接口

| 端点 | 契约 |
|---|---|
| `POST /v1/guest-sessions` | 服务端签发匿名身份凭据；频控，不能用任意设备号冒充主体 |
| `POST /v1/analysis` | token + requestId + consentVersion + 单帧 JPEG + purpose/template + pitch/roll；返回 taskId、状态、deadlineAt |
| `GET /v1/analysis/{taskId}` | 返回 pending/ready/committed/released 与终态原因；只允许任务归属主体读取 |
| `POST /v1/analysis/{taskId}/ack` | resultVersion + requestId；原子确认有效结果并核销，重复确认返回同一终态 |
| `POST /v1/analysis/{taskId}/cancel` | 幂等取消；未核销则释放；已核销返回 committed，不虚报取消成功 |
| `GET /v1/quota` | 分桶的 available/reserved/used/expiresAt + version；客户端只读 |
| `POST /v1/auth/sms`、`POST /v1/auth/apple` | 校验凭据，发 token，显式绑定当前匿名主体；防重复绑定 |
| `GET /v1/templates?since=` | revision + 增量 + 下架墓碑；过旧版本要求全量刷新 |
| `POST /v1/feedback` | 文本与单独授权的附件；用途授权与分析不同 |

错误码：401 身份失效；403 权限/授权不满足；409 幂等键对应内容不同或状态冲突；422 输入无效；429 携带 `quota_exhausted` 或 `rate_limited`；5xx 服务失败。UI 按业务 code 展示，不把 401 当余额不足。

JPEG 长边≤1280、质量目标 0.7，去除 EXIF/定位元数据，上传大小上限由接口配置并在客户端预检；无效黑帧不上传。同一 requestId 内容摘要只在服务端计算，避免客户端伪造。日志不存原图、完整请求体或 token。

### 7.2 时限与展示

点击开始的端到端等待预算 3s，含抓帧、编码、上传、推理和结果确认。服务端推理上限目标 2s，客户端为网络与本地处理留余量；弱网预算耗尽即本地建议，云成功时延与本地降级时延分别报告。

服务端有效结果进入 ready，预留最多保留至受理后 30s。客户端只有在仍处于当前取景会话、授权有效、结果校验通过且仍在等待预算内时发送 ack；确认成功后展示。若 ack 已发但回执丢失，显示“结果确认中”，可先用本地指导并查询终态，不自动重发新任务。此时可能已经成功扣次，不能承诺所有客户端超时均免费；未 ack 的任务超时一定释放。已确认结果可在本次建议记录中重新查看，不因页面切换再次扣费。

取消与 ack 竞争由数据库行锁串行决定：先核销则取消返回 committed；先取消则 ack 返回 released。客户端 Task.cancel 只代表本地停止等待，必须另发取消或依赖到期清扫。迟到结果不得覆盖新会话。

| 指标 | 初始目标 | 验证 |

## 9. 任务、额度和购买一致性

### 9.1 状态与事务

```text
created → reserved → running → ready → committed
                   ↘ failed/cancelled/expired → released
ready → cancelled/expired → released
```

`created` 为受理前概念态；数据库创建任务与预留在同一事务提交。failed/cancelled/expired 是释放原因，持久终态统一为 released。committed 与 released 互斥且不可逆；退款另记补偿流水，不篡改历史。

事务约束（模型说明，具体迁移实现后再验证）：

```text
analysis_tasks UNIQUE(subject_id, request_id)
  payload_hash, status, result_version, deadline_at, release_reason
quota_buckets UNIQUE(subject_id, kind, period_key)
  granted, available, reserved, spent, expires_at
  CHECK available >= 0 AND reserved >= 0 AND spent >= 0
reservations UNIQUE(task_id)
  bucket_id, amount, status   # 一次分析1次，单桶预留
quota_events UNIQUE(task_id, event_type)
  event_type = reserve | commit | release
billing_events UNIQUE(provider, transaction_id, event_type)
```

创建时先去重，在同一事务锁定可用桶并检查额度，available−1 / reserved+1；确认时锁任务及预留，reserved−1 / spent+1；释放时 reserved−1，若桶尚未过期则 available+1，已过期则转 expired 不转入新周期。所有路径固定锁顺序，避免死锁。任务状态条件更新保证 commit/release 互斥；仅靠流水唯一键并不足够。

免费桶按 UTC 自然月新建，到期旧桶不可新预留；付费桶独立不受免费更新影响。预留跨月按原桶结算。匿名首次绑定账号时对本期免费额度做一次性事务合并，以双方已用量与预留合计抵扣同一期上限，不简单相加；绑定后匿名旧凭据不能继续领另一份。正在执行的任务先结算或取消后完成绑定。付费订单不得自动跨账号合并。

后台清扫到期未确认任务；任务写入与 outbox 同事务，worker 至少一次投递，通过状态检查防止重复结算。进程重启扫描未终结任务；供应商调用不能保证绝对只发一次，重复成本单独监测，但用户最多扣一次。PG 为事实源，缓存故障不改变余额；日对账核对桶、预留、事件与订单，不让“退款失败”静默遗留。

### 9.2 购买

购买前必须登录。服务端验证交易及所属账号后幂等入账，客户端成功回调不能直接加额度。区分取消、待支付、已付款待核验、已入账、退款/撤销；每种状态都有可查询结果。已处理的消耗型额度通过账号账本恢复展示，不承诺仅靠商店恢复按钮重建所有消耗历史。订阅恢复、重复通知、退款、跨账号交易均列测试。具体商品、定价、有效期和退款后额度处理由负责人在开放购买前确定。

### 9.3 清理与运维

分析帧优先内存短存；如落对象存储，终态即删，扫描遗漏任务，最长24小时为需要实测证明的上限目标。对象生命周期只是兜底；覆盖缓存、对象版本、日志、备份和供应商留存。尚未验证处理方删除能力时，禁止向用户发布“24小时删除”的确定承诺。反馈附件独立保留策略，不复用分析授权。

## 10. 界面与后台实现

相机按[界面设计规范](界面设计规范.md)实现。顶部模式胶囊展开目的/模板，取景器底部放变焦；快门右侧 AI、左侧最近照片；工具栏只放当前支持的功能。按钮最小触控44pt。VoiceOver 与减少动态效果覆盖全部路径。

后台采用独立管理登录：运营编辑模板/策略草稿，授权发布者复核；客服仅看工单授权附件和必要的额度信息；只读看聚合；超管管理权限及补偿审批。申请人不能审批自己的变更。普通运营不能访问分析帧。每次发布存版本、diff、评估报告、审批者、时间；灰度可回滚。预算阈值触发告警和云端熔断，客户端继续本地指导。

## 11. 验证矩阵

| 场景 | 必须成立 |
|---|---|
| 飞行模式/游客 | 拍摄、模板兜底、选片、调色、导出闭环 |
| 授权 unknown/declined/revoked | 零分析帧上传；授权期间撤销停止后续上传，已发任务取消/清理 |
| 同键并发/不同内容 | 同任务同扣次；内容冲突409 |
| 仅剩1次并发两任务 | 至多一个预留成功，余额不负 |
| 供应商失败/worker崩溃/超时 | 未确认预留最终释放，无永久占用 |
| ack与cancel并发、ack回执丢失 | 单一终态，可查询可恢复，无重复核销 |
| 跨月/游客绑定/换账号 | 免费不叠加，旧桶不污染新桶，缓存隔离 |
| IAP重复通知/待核验/退款 | 幂等入账与可追踪处理状态 |
| 写盘中断/删除失败/连拍 | 无文件覆盖，可恢复索引，无虚假保存成功 |
| 模板下架/离线重连 | tombstone优先，版本回退可验证 |

黄金集覆盖弱光、遮挡、镜像、多人、边缘裁切；策略更新需人工评估和回归记录，不能仅凭模型自评分发布。

## 12. CI 与发布

编译与静态检查、领域边界测试、并发结算集成测试、授权抓包、真机性能、无障碍回归分别留报告。权限用途键、隐私清单、第三方 SDK 与实际行为匹配；地区上架材料另行维护，不虚构系统专用备案键。审核和正式运行能力一致。

## 13. 待决策与风险

M0 锁定最低设备、HUD实现、性能基线与模型成本；M2 锁定云供应商及留存约束、匿名风控、商品方案与反馈保留期；发布前核验目标市场规则与账号删除期限。任何阻碍数据承诺或支付一致性的未决项都应阻止对应功能开放，而不是阻止本地相机开发。
