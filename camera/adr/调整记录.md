# 骨架结构调整记录（2026-10-26）

依据：对 ppb-chat 现有骨架（server-camera / server-gateway / camera-ios-app）的代码审查。业务方向确认为**默认本地构图 + 拍后自动自然成片 + 云分析按需授权**，本轮先修骨架结构缺陷，业务实现随 M2。

| 问题 | 本轮决定 |
|---|---|
| 雪花发号钩子未接（BaseModel 无 BeforeCreate 委托，主键不会应用侧发号） | 对齐 server-user：domain 声明包内 `hooks = dombase.NewHooks(6)`，BaseModel.BeforeCreate 委托；单测覆盖零值发号 + 显式 id 保留 |
| 付费额度包唯一键冲突（`(subject_id, kind, period_key)` + 付费包空串 → 同主体第二张必撞） | period_key 语义改为：免费桶=UTC `YYYY-MM`；付费包/订阅=购买批次键（`pb_` 前缀，一次购买一行）；列宽 16→32 |
| 非负/amount 约束未落库 | gorm `check` 标签建表落地：桶四计数非负（chk_bucket_nonneg）、预留/事件 amount=1；AutoMigrate 不向已存在表补 CHECK，旧起步库重建后生效；执行行为由单测覆盖 |
| subjects 表缺失，guest-sessions 与绑定语义无落点 | 新增 `domain/subject.go`：Kind 1 匿名/2 登录，绑定原地升级不换 subject_id；phone_hash/apple_sub 只建普通索引（MySQL 无部分索引），唯一性归绑定事务（M2） |
| migrate DSN 优先级与文档不符（实为 CLI>配置>环境） | 改为 CLI > `CAMERA_DB_DSN` > config db_dsn > 默认 SQLite，与命令注释一致 |
| `Open("")` 时 Dialect 按未解析 DSN 误报 | Open 先 `ResolveDSN` 再建连与判方言 |
| 配置无范围校验 | LoadConfig 尾部 fail-fast：端口 1024-65535、免费额度/deadline/帧上限 > 0 |
| VerifySchema 只查表存在 | 增关键列与命名唯一索引校验（含 outbox 表）；缺表/缺键启动即失败 |
| `/ping` 未挂载、healthz 不查库 | `/ping` 与 `/healthz` 同款信封：自描述字段 + `db`（SELECT 1，失败 status=degraded） |
| 主体身份协议未闭合（proto 宣称网关下传但无约定无提取） | 契约固定：gRPC metadata `x-ppb-subject`，仅信任内网网关注入；server-camera 拦截器装入 typed context，归属类 RPC（GetAnalysis/Ack/Cancel/GetQuota）缺主体 CAM-4010；errcode 增 CAM 段 |
| 网关无 camera upstream | config 增 `ppbchat.camera`（127.0.0.1:9106/3000ms）；grpc_clients 增 Camera 连接；注册 10 条 REST 路由（`/api/v1/camera/*`，含 /auth/sms 两阶段分派）；匿名引导三路由入白名单；JSON 面字段名为 snake_case（新 protoc-gen-go json tag 口径） |
| 云供应商未定（技术大纲 §13 M2 才锁定），Python 推理服务暂不建 | `service/analysis` 留 Provider 接口 + UnsupportedProvider 恒返回 CAM-9050 provider_unsupported，不假造结果；自建推理服务的触发条件与"纯推理、无业务库、仅内网"定位写入包注释 |
| iOS 13 包均为 marker，缺技术大纲 §6 领域类型 | SharedModels 落 6 个 Codable 值类型（PhotoSession/PhotoRecord/EditRecipe/Template/QuotaCache/UploadConsent）+ 约束校验 + 13 个 swift-testing 用例；不建第 14 个包 |
| docs 无数据库专文，表约束散在技术大纲 §9 | 新增 [database.md](../tech/database.md)（权威 DDL/唯一键/CHECK/节点号/双方言），README 补工程位置与链接 |

后续待办（不属本轮）：业务 RPC 实现（仍 CAM-0001 501）、绑定/结算事务（M2）、camera-manager-web API stub 替换、docs V2.4 全面重构（本地成片为默认路径的口径）。

# ADR-1101 需求更新决策（2026-11-01）

日期：2026-11-01。性质：**需求更新裁决，不是发布实现**；本轮只新增/同步文档（产品功能设计、AI 构图交互与模块架构、执行计划、实施现状，及 README/PRD/界面规范/FS-01/06/10/追踪矩阵小范围同步），未创建或修改应用代码、未运行测试。历史 ADR 正文未改动。

| 议题 | 决策 |
|---|---|
| 导航结构 | **四 Tab 固定：拍照 / 灵感 / 作品 / 我的，默认拍照**。「我的」承载 IAM 账号、额度、权限、隐私、存储、反馈、关于；拍照页右上角调整面板保留（模板选择 + 构图辅助开关 + 设置快捷入口）。取代 V2.3「三 Tab + 设置入口」；V2.3 时期「四Tab与主流程冲突→收进设置」的历史裁决随之失效，以本条为准 |
| 灵感页去留 | 保留。ppb-camera 工作树中「删除灵感页、改三 Tab」的未提交在改方向与四 Tab 目标不一致，记为待整合（执行计划 T00），本轮不改代码 |
| Doka 参考 | **仅参考 AI 构图交互功能**（意图表达→取景内辅助→引导对齐→拍摄的能力与信息层级）；不参考布局、导航、配色、控件样式、图标。保留现有沉浸式视觉方向（界面规范仍为视觉唯一权威） |
| 中心点口径 | 默认显示，位置固定为**实际 3:4 参考框几何中心**（非整屏中心）；纯预览开关；不是对焦点、不是主体识别结果、不参与检测判定、不写入原片；调整中心点/网格开关后**真实 toast**。中心点/主体检测/对焦三者正交（架构文档 §5） |
| 构图按钮 | 在现有画面显示轻量指导；未接入分析能力时**明确标注本地提示**，禁止假进度、假达标；建议一次一条；低置信静默 |
| AI 实现顺序 | 三期递进：①本地辅助（参考框/网格/中心点/静态指导卡）→ ②端侧主体/姿态检测 + 稳定引导状态机 → ③真实云分析。云结果落屏前仍须端侧校验 |
| 云分析边界 | 主动触发 + 单帧授权卡；无默认原片上传；失败/超时/取消幂等与额度一致性沿用技术大纲 §7/§9 结算契约（不重开） |
| 快门独立 | 重申 G4：快门不依赖 AI、账号、网络、额度任何一项；任何引导/授权/加载状态不禁用快门 |
| 自动曝光/变焦 | 预留不排期；若实现须主动授权 + 真实反馈 + 恢复入口 + 默认不自动拍摄，四条缺一不可 |
| 首个代码任务 | 限定 **NetworkKit 模板客户端**（纯包内，零 App/Features 改动）；与在改 App/Features 任务不得并发覆盖 |
| 代码归属 | 更正为 ppb-camera（camera-ios-app + camera-manager-web）与 ppb-base（server-camera/server-gateway/base-manage-web）；**不在 ppb-chat**；不重建 React/Postgres 后台（沿用 Vue 底座 + Go/MySQL） |
| 快门/拍摄模式 | 单拍/3秒倒计时/连拍（连拍间隔 400ms 为目标值）；未实现模式不显示空控件；自动拍摄一律不做 |
| 验收红线 | 未实现入口不伪装可用；未接分析明确本地提示；目标指标不是实测值；不声称已真机/已接通云 AI |

执行与验收映射见[执行计划](../implementation/Claude-Code执行计划.md)（T00–T21）；实施基线见[实施现状与验证记录](../implementation/实施现状与验证记录.md)（含未提交工作树冲突记录）。
