# FS-14 · AI 构图分析与实时引导需求

版本：1.0｜日期：2026-11-02｜状态：基于源码的增量需求，未实现验收。

关联：[FS-02](FS-02-AI现场分析.md)、[FS-03](FS-03-机位引导.md)、[FS-12](FS-12-AI选区与拍摄调整.md)、[FS-13](FS-13-半圆变焦控制.md)、[技术设计](../tech/AI构图实现技术设计.md)、[代码分析](../implementation/2026-11-02-ppb-camera代码分析.md)、[专项验收](../ac/AI构图专项验收.md)。

## 1. 目标与已有事实

将“想拍得更好”转换为一条用户可以执行、系统能够检查结果的构图建议。首个目标为后置单人静态全身、半身及简单旅行人像；不把智能识别缺失包装为已完成能力。

源码基线 ppb-camera@b3b7dad：全屏预览、悬浮按钮/Tab、本地 ROI 编辑与读取、曝光和数字变焦已存在实现；读取只生成本地临时图，不进行 AI 分析。端侧姿态、实时引导、云分析及权益包仍需开发。事实与目标分别标记。

## 2. 本轮承接的规则

1. 导航目标沿用 ADR-1101 的四 Tab；当前代码三 Tab 记录为差距，不在本轮反向修改目标。
2. 默认全屏预览无大参考框/遮罩；普通快门保存完整原片，无自动 3:4 裁切。全屏 aspectFill 的边缘可见范围不等于完整照片，不能承诺所见即所得。
3. ROI 只限定分析输入，非拍摄裁切；不把被 ROI 排除的部位判为“照片裁掉”。全身构图必须有足够全身证据，否则说明分析范围不足。
4. 快门不受 AI 加载/失败/低置信/额度控制；相机权限、系统中断和硬件忙属于真实设备限制，需要如实反馈。
5. 基础拍摄、本地作品与端侧构图免登录。登录、分析上传授权、反馈附件和未来同步分别管理。
6. 一次一条建议；未知不算通过；未真实运行检测时不显示识别框、达标反馈或假进度。

## 3. 发布层级与入口

沿用现有 L1/L2/L3 命名，不新增另一套 L0。

| 层 | 能力 | 入口与诚实边界 |
| --- | --- | --- |
| L1 本地辅助 | 网格/中心点、ROI 编辑与快照读取、静态提示 | 当前“构图”进入 ROI；继续明确“未进行AI分析”；读取时会本机拍一张，不是持续视频帧分析 |
| L2 端侧检测 | 人物/姿态、占比、位置、水平、单建议反馈 | 作为 ROI 模式内独立“本地分析”操作；仅能力可用时开放，支持关闭；首次说明只在本机处理 |
| L3 云增强 | 主动单帧场景/背景理解，返回候选构图目标 | 另设“分析现场”动作并先授权；不将“读取选区”自动变成上传，不自动付费重分析 |

后续入口可以随可用性测试调整，但“读取、端侧分析、云分析”三种行为在文案和授权上必须可区分。未实现层保持清楚状态，不提供假的可用按钮。

## 4. 页面流程

全屏相机 → 点构图 → 调整 ROI → 可读取本地快照 → 启动真实 L2 → 选择全身/半身目标 → 单人检测或点击确认主体 → 单条建议 → 条件满足后的反馈 → 用户快门拍照 → 完整原片入库。

L3：用户点击分析现场 → 说明单帧内容/目的/处理方/期限与额度 → 授权/必要登录 → 发起真实任务 → 本地辅助继续 → 在等待预算内验证 ready 结果 → ack 成功 → 展示建议。超时回到当前本地状态；不能把 L1 静态卡写成端侧智能建议。

ROI 移动/缩放、切镜、变焦、退出、Tab/后台切换立即清旧快照与指令。未来增加方向切换时也失效；当前工程只声明竖屏，不能宣称已支持横屏。

## 6. 指令与完成条件

| 问题 | 指令示例 | 检查依据与边界 |
| --- | --- | --- |
| 人物位置 | 把人物放到左侧框内 | 画面目标可验证；不能据此确定摄影者横移方向 |
| 人物大小 | 让人物在画面里小一点 | 人物框占比；不默认自动变焦，不指定后退厘米数 |
| 边缘余量 | 头顶接近画面边缘，留一点空间 | 明确针对可见分析范围；非原片覆盖范围不判照片裁切 |
| 手机倾斜 | 把手机端平 | 重力与设备方向；画面地平线不存在时不编造地平线检测 |
| 背景干扰 | 头部背景较杂，可以换个角度 | 云建议须有证据；无法自动检查时允许确认/忽略，不假判已解决 |
| 足部不可测 | 暂时看不清脚部 | 不累计脚部就绪，不强制要求后退 |

沿用优先级：无主体 > 出框 > 大小 > 倾斜 > 头顶 > 逆光 > 姿势。ROI 范围不足属于前置可测性检查。低置信度强指令静默，必要状态说明不高频弹窗。具体模板阈值沿用 FS-03，修改须记录版本、回放证据与影响范围，不在此次文档中静默改成新数值。

## 7. 异常、数据与无障碍

无网络保留 L2；无 L2 则只显示 L1。检测丢主体暂停移动指令；多人无法关联则重新确认。热降级后 unknown 不能保持“已达标”。云异常结束本地等待，但不得据客户端超时直接退款或把服务端任务改终态。

图像特征默认内存保存，照片仍按本地作品规则管理。上传期限、供应商处置和清理机制上线前冻结；不虚构已满足 24 小时删除。账号切换隔离任务与缓存，登录不上传设备照片。云结果未通过时不 ack；已 ack 后场景改变不自动退款，允许查看已确认建议并按既有政策处理。

提示一次一条，最多一种当前引导标记，避开快门/半圆变焦盘/底部 Tab。读屏按指令变化播报，不逐帧播报；颜色配合形状与文字；支持减少动态效果和透明度。ROI 选择保留等效无障碍操作，中心点仍非对焦点或检测结果。

## 8. 指标、验收与发布

使用现有 analysis_requested/ready/succeeded/degraded/ack_unknown/released 与 guidance_shown/followed 等事件，不新增同义缩写。分析成功只表示已确认云结果，不表示照片满意。普通拍照自动入库不等于用户主动满意，另统计收藏/导出与配对拍摄偏好。

性能沿用 PRD/技术大纲的**目标值**：检测15fps/单帧16ms、建议 HUD p95≤100ms、云点击至建议 p95≤3s（含降级）。本轮没有实测；机型、分辨率、温控和计时范围在预研时冻结。若不可达先正式修订指标，再开放能力，不能直接把降低帧率记为通过。

发布依赖：L1 先保证本地 ROI/原片和迟到治理；L2 必须有映射、真实检测、状态机、回放和真机证据；L3 必须完成授权抓包、ready/ack 一致性、故障注入、服务端与供应商联调。付费还须订单、退款/撤销、恢复与账本补偿验收。

详细用例与需求映射见[专项验收](../ac/AI构图专项验收.md)。当前全部新增智能能力按“未实现/未验证”管理，不能因本文提交而标完成。
