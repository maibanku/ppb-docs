# FS-12 AI 选区与拍摄调整

> 2026-11-02 后续增量见 [FS-15](FS-15-右侧工具列与照片比例.md)：原始模式仍全屏且保存完整原片；仅用户明确选择非原始比例时新增成片框和非破坏派生版本，原片始终保留。ROI仍只作分析输入；中心点在非原始模式按成片框定位。曝光与辅助线新增侧栏入口，共享状态。本文“不修改比例API”仅适用于此前原始模式批次，不阻止FS-15的显式比例功能。

> V1 · 2026-11-02；全局范围见[需求大纲](../PRD.md)，界面基线见[界面设计规范](../tech/界面设计规范.md)。

## 1. 功能描述

1. **默认全屏取景**：实时预览延伸四边铺满屏幕（`resizeAspectFill`），无成片参考大框、无框外遮罩；中心点（如开启）默认落在画布中心，九宫格为独立开关且只作预览参考线、不参与任何裁切。
2. **本地 ROI 选区模式**：点右侧「构图」进入。出现一个初始居中的矩形选区（初始比例沿用 3:4，但**不强制固定比例**，可自由缩放）；框内画面正常显示，框外覆盖半透明中性灰遮罩。可拖动整框移动、拖四角缩放，选区始终约束在可用画布内且有最小尺寸。
3. **读取选区**：从 `captureSource.capturePhoto()` 实拍当前一张相机图像，按选区裁出独立临时图像，仅本机临时展示。**这不是实时 AI，也不是屏幕截图**；不写 PhotoStore、不上传、不做任何 AI 分析。
4. **亮度（曝光补偿）**：真机提供实际曝光补偿滑杆 +「恢复默认」，影响整个相机画面与后续拍摄的照片（非仅 ROI）。

## 2. 覆盖关系（本轮对旧行为的裁决）

| 旧行为（immersive-refine 批次） | 本轮裁决 |
|---|---|
| 取景器常驻 3:4 参考框 + 框外弱化遮罩（`GuideDimmingOverlay` 常驻绘制） | **废除**。默认不画任何参考框与遮罩；仅 ROI 选区模式绘制定位框与灰遮罩。 |
| 快门拍摄后自动按 3:4 参考框 WYSIWYG 裁切（`capture()` 内 `cropToGuide`） | **废除**。普通快门把 `capturePhoto()` 返回的**完整原片**直接落库（回归 FS-05 §1「原片按系统最高质量保存本地」），不做任何自动裁切。 |
| `FinderGuideGeometry` / `CaptureLayout` / `AspectFillCropMapping` / `WYSIWYMCaptureCrop` | **保留原实现与原测试**，不为本轮显示篡改任何原几何方法。`FinderGuideGeometry` 复用为 ROI 初始框几何（3:4、避开控件带）；`AspectFillCropMapping` 复用为 ROI 屏幕→像素映射；`WYSIWYMCaptureCrop` 保留类型与测试但不再位于快门路径。 |
| 中心点固定在 3:4 参考框几何中心 | **改为默认画布中心**；ROI 模式内中心标记跟随选区中心。 |
| 右侧「构图」按钮开关静态指导卡 | **改为进入本地 ROI 选区模式**（静态提示不再由该入口承载）。 |

**全屏与原片比例限制（用户已裁决）**：全屏铺满预览与完整传感器原片比例无法同时保证。用户选择**铺满屏幕、允许预览边缘裁切；完整原片保留**。因此保持 `resizeAspectFill` 铺满、不修改任何比例相关 API；预览边缘（通常为左右）所见范围窄于原片，属已知限制如实记录，不做隐藏补偿。ROI 裁切**只服务本地分析输入**，不能影响普通照片。

## 3. 交互细则（ROI 选区模式）

| # | 用户动作 | 界面效果 | 联动 |
|---|---|---|---|
| 1 | 点右侧「构图」 | 进入 ROI 模式：出现初始居中 3:4 矩形（复用参考框几何，避开控件带），框外半透明中性灰遮罩，框四角出现明确 corner handle（44×44pt 触控区）；中心标记跟随选区中心 | 快门照常可用（互不阻塞） |
| 2 | 框内拖动 | 整框平移，始终约束在可用画布内 | 选区中心标记跟随；**旧读取预览立即失效** |
| 3 | 拖角缩放 | 锚定对角缩放，约束最小尺寸（88×88pt）与画布边界；比例自由 | 同上 |
| 4 | 点「取消」 | 退出 ROI 模式：移除遮罩、选区框与**全部临时预览数据** | 不影响普通拍摄与已存照片 |
| 5 | 点「读取选区」 | 实拍一张（`capturePhoto()`）→ EXIF 归一 → 选区映射裁切 → 小预览卡展示所选内容 + 文案「已提取选区，仅本机临时使用，未进行AI分析」 | 进行中可被新的失效事件打断 |
| 6 | 读取后移动/缩放选区、切换前后摄、退出 ROI 模式 | **旧预览立即失效并丢弃**（generation 递增，迟到结果丢弃） | 不误存、不上传 |
| 7 | 离开拍照 Tab / App 进后台 | 读取任务取消、迟到结果丢弃；离开 Tab 同时退出 ROI 模式（移除遮罩与临时数据） | — |

尊重系统「减弱动效」（过渡改直切）与「减弱透明度」（遮罩/衬底加浓改不透明倾向）。

## 4. 读取选区的诚实边界

- 数据来源是 `captureSource.capturePhoto()` 的**一张真实相机图像**；模拟器为合成源，产物同样明确标注、同样仅临时使用。
- 裁切复用既有 EXIF 方向归一 + `AspectFillCropMapping` 屏幕坐标→像素映射，形成独立临时图像；**不写 PhotoStore、不上传、不生成任何分析结论**。
- **前摄镜像**：预览层默认镜像前摄画面而拍摄原片不镜像，因此前摄路径在映射前对选区做水平翻转。该映射按 AVFoundation 默认镜像行为推导，**未实机验证**，如实标注；若真机表现与假设不符，以真机为准修正映射，不得假装准确。
- 读取流程不占用/不禁用普通快门，也不进入任何 AI/账号/额度状态（G4 同口径）。

## 5. 亮度（曝光补偿）

| 项 | 口径 |
|---|---|
| 能力 | 真机 `AVCameraSource` 曝光补偿（`exposureTargetBias`），为 `AVCameraSource` 具体能力 API，不进入 `CaptureSource` 业务协议 |
| 线程 | 全部在 `sessionQueue` 串行处理；`lockForConfiguration` / `defer unlock` |
| 范围 | 硬件 `min/maxExposureTargetBias` 与合理区间（±3 EV）取交集；不支持或交集为空时如实报「不支持」 |
| 返回值 | 每次设置返回硬件**真实应用值**（读回 `exposureTargetBias`），UI 展示与应用一致 |
| UI | 拍摄调整面板内「亮度」滑杆 + 「恢复默认」（回 0 EV）；滑动合并末次再串行下发，避免旧值覆盖新值；失败文案可见；切镜/重开后读回真实状态 |
| 影响面 | 整个相机画面与后续拍摄照片（曝光补偿作用于设备，非仅 ROI 选区） |
| 模拟器 | 不假装硬件调整：滑杆禁用并显示「模拟器不支持亮度调节」 |
| 不做 | 饱和度/白平衡等未实现项不放假开关；不做任何自动曝光决策（无云 AI） |

## 6. 状态矩阵（读取选区）

| 状态 | 触发 | 表现 |
|---|---|---|
| 待选区 | 进入 ROI 模式 | 初始框 + 遮罩 + 角柄 |
| 读取中 | 点「读取选区」 | 轻量进行指示；快门与构图操作照常 |
| 已提取 | 实拍+裁切成功且未失效 | 小预览卡 + 「已提取选区，仅本机临时使用，未进行AI分析」 |
| 失效 | 移动/缩放/切镜/退出/离开 | 预览卡消失，迟到结果丢弃 |
| 失败 | 拍摄/解码/裁切失败 | 如实报错（可重试），不展示半成品 |

## 7. 文案清单

- 进入 ROI：「已进入选区模式，拖动调整范围」
- 读取成功：「已提取选区，仅本机临时使用，未进行AI分析」
- 读取失败：「读取选区失败，请重试」
- 前摄提示（读取成功时附带）：「前置摄像头镜像映射未实机验证」
- 亮度：「亮度」「恢复默认」「亮度调节失败，请重试」「模拟器不支持亮度调节」

## 8. 无障碍

角柄、读取、取消均为 ≥44×44pt 触控区并带 VoiceOver 标签；选区中心标记为纯装饰隐藏；ROI 手势之外提供等效按钮操作；动效遵循「减弱动效」。

## 9. 验收标准

- [ ] 默认取景无任何参考框/遮罩；九宫格与中心点独立开关，不影响落库照片
- [ ] 普通快门落库为 `capturePhoto()` 完整原片（无自动 3:4 裁切）
- [ ] ROI 移动/缩放受画布与最小尺寸约束（纯逻辑单测覆盖）；退出后无遮罩与临时数据残留
- [ ] 读取选区：失效规则（含迟到结果丢弃）单测覆盖；产物不进 PhotoStore、不上传
- [ ] 曝光补偿 clamp/交集纯逻辑单测覆盖；真机实拍验证（**未实机验证，待办**）
- [ ] 前摄镜像映射实机验证（**未实机验证，待办**）

## 10. 技术要点

- ROI 几何（移动钳制、角点缩放、镜像翻转、最小尺寸）为纯值函数（`ROIGeometry`），App 单测覆盖边界。
- 读取选区使用显式数据模型 + generation 代数：任何失效事件递增代数，结果回填时代数不符即丢弃；任务句柄随 Tab/后台取消。
- 曝光补偿范围/钳制为纯值类型（CameraCore `ExposureBiasRange`），包内单测覆盖；硬件读写只在真机路径执行，测试不伪测硬件。
- Swift 6 并发：跨隔离只传 Sendable 值（`Data`/`Float`/`CGRect`）；临时图像只存活于 MainActor 状态。

## 11. 与AI分析展示的区别（四角框方案）

用户已确定AI分析时采用[FS-14 §9](FS-14-AI构图分析与实时引导.md)的四角断线式圆角框，画面保持实时、无分析灰遮罩。本文灰遮罩与角柄仍仅属于ROI编辑阶段；进入真实分析时隐藏编辑遮罩/角柄，保留同一几何范围的四个圆角角标。此变化不代表L1读取已经接入AI，读取仍仅本地临时提取，不显示假分析进度。取消/失败返回编辑时可恢复编辑外观，照片/比例与原片规则不变。
