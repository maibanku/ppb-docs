## 1. 功能描述

端侧持续检测（无网可用），覆盖五类构图问题：**人物出框 / 人物过大过小 / 头顶裁切 / 地平线倾斜 / 手机倾斜**。引导形式 = 取景器内箭头动画 + 参考线 + 底部一句话建议，用户跟着走位；达标瞬间引导收起 + 成功触觉，然后按优先级放出下一个问题。这是「跟着提示拍到好照片」的核心环节。

## 2. 入口与触发

| 入口 | 触发 | 行为 |
|---|---|---|
| FS-02 分析成功 | 建议落地即进入对应引导模式 | 建议条文字 = 当前 Issue 文案 |
| FS-01 选模板后未分析 | 端侧直接开跑基础引导 | 参考线（人物占位框）常显，问题建议照常出现 |
| 任何时刻 | 快门不打断检测；离开拍照页暂停 | 切后台暂停，返回重新评估现场 |

## 3. 页面布局（HUD 元素，全部叠加在取景器上）

```
┌──────────────────────────────┐
│              ⬤水平仪          │ ← 左上角迷你水平仪（倾斜时白色→橙色）
│                              │
│        ┌ 虚线人形框 ┐         │ ← 人物占位参考框（构图目标：脚贴下沿）
│        │   ▲        │        │
│        │  (箭头动画) │        │ ← 引导箭头：指向建议方向，呼吸动画
│        │            │        │
│        └────────────┘        │
│                              │
│ ┌──────────────────────────┐ │
│ │ ↘ 手机放低一点，让脚靠近   │ │ ← 建议条（同 FS-02 位置）
│ │   下面的参考线。           │ │
│ └──────────────────────────┘ │
```

引导箭头方向语义：上/下=手机高低调高低调低；左/右=平移；弧形=绕主体移动；倾斜图标=端平手机。

## 4. 交互细则（动作 → 效果 → 联动 → 埋点）

| # | 用户动作/系统事件 | 界面效果 | 联动 | 埋点 |
|---|---|---|---|---|
| 1 | 问题触发（驻留 1.5s 通过） | 建议条文字 crossfade（`guidance`）+ 对应 HUD 箭头/参考线出现 + `light` | GuidanceEngine.issueRaised | guidance_shown |
| 2 | 用户持机移动，指标改善但仍未达标 | 箭头随偏差方向实时更新（60fps HUD）；文字不变 | FrameQueue 持续评估 | — |
| 3 | 指标进入滞回区 | 箭头减淡（确认边缘，不撤建议） | 防抖滞回生效 | — |
| 4 | 进入对应解除区并连续驻留1.0s | 箭头/参考线 `celebrate` 收起 → 参考线闪品牌绿一次 → 「构图好了」toast 1.2s + `success`；按优先级放出下一问题（若有） | issueCleared | guidance_followed |
| 5 | 6s 未达成 | 文案升级（coaching）：「还要再低一点，让脚碰到下面的线。」 | GuidanceEngine.coaching | — |
| 6 | 用户离框/主体丢失 | HUD 虚线人形 + 「让被拍的人站进框里」；不放其他建议 | noSubject 优先级最高 | — |
| 7 | 检测置信度低（弱光/侧身） | 人形轮廓虚化，只留参考线，不放姿势/构图强建议 | 降语气 | — |
| 8 | 过热降级（thermal） | 依次：收轮廓留参考线 → 检测降至 10fps → 仅参考线；右上角小图标提示 | CameraCore thermal 事件 | — |
| 9 | 全部达标 | 全部 HUD 收起，进入「可以拍了」空闲态；快门圈微呼吸 | — | — |

## 5. 状态矩阵

| 状态 | 触发 | 表现 |
|---|---|---|
| 空闲 | 无问题 | 参考线极淡常显，无建议条 |
| 引导中 | 有激活 Issue | 建议条+箭头+对应参考线 |
| 无主体 | 检测不到人 | 虚线人形 + 主体提示 |
| 低置信 | 弱光/遮挡/侧身 | 虚化轮廓，静默（宁可不说，P3） |
| 过热 | thermal elevated+ | 分级降级链 |
| 无网 | 断网 | **无任何变化**（本功能纯端侧）——这是设计承诺 |

## 6. 动效与触觉

建议切换 `guidance` crossfade（严禁闪烁）；达标 `celebrate` + `success`；升级文案 `guidance`；水平仪倾斜超阈值变橙 + `light`（每次越线仅一次）。

## 7. 文案清单

- 出框：「向左移动半步，避开画面边缘。」/「人物头顶出框了，后退一步。」
- 过小/过大：「再走近一步，让人物更占画面。」/「退后一点，人物快顶着边了。」
- 头顶裁切：「上面留一点空，不要裁到头顶。」
- 倾斜：「把手机端平，参考线会对齐地平线。」
- 升级例：「还要再低一点，让脚碰到下面的线。」
- 达标：「构图好了。」
- 无主体：「让被拍的人站进框里。」

（全部黑名单校验通过；动词/名词均为用户原声词汇）

## 8. 无障碍

建议条到达播报全文 + 方向语义（「建议：向左移动」）；达标播报「构图完成」；箭头动画不承载唯一信息（文字同步）；VoiceOver 开启时降低 HUD 动画幅度。

## 9. 对抗场景

- 逆光剪影：亮度粗判触发后，先建议「让被拍的人侧过身，别让太阳直射镜头」，再回构图问题。
- 背景强地平线 vs 室内无地平线：horizonTilt 缺省时只检手机倾斜（不虚报地平线）。
- 多人入画：取最大人物为引导对象；两人并排按整体外接框。
- 镜面/海报中的人形：置信度门槛过滤，不引导。
- 手持步行的自然晃动：One Euro 滤波 + 滞回，稳定场景60s无重复激活，验收前提见技术大纲§5。

## 10. 验收标准

- [ ] 五类问题全覆盖且优先级仲裁正确（自动化用例 × 每类 5 场景）
- [ ] 端侧检测 ≥15fps（A12+），检测延迟 ≤16ms/帧
- [ ] 恒定场景±2°微抖且不跨真实问题边界：60s无重复激活（真机+property测试）
- [ ] 建议→HUD 呈现 ≤100ms p95
- [ ] 达标收起 ≤400ms + `success` 触觉；随后下一问题按序出现
- [ ] 完全离线功能等价；过热降级链逐级生效且可恢复
- [ ] 建议文案零术语、零闪烁（crossfade ≥200ms）

## 11. 技术要点

- 全部判断收敛在 GuidanceEngine（纯函数，时间注入），UI 层不得自行判断（防抖三件套唯一生效点）。
- 指标：人物外接框归一化坐标、框高占比、头顶留白比、Canny 地平线角度（可缺省）、CoreMotion 滚转角、亮度直方图粗判逆光。
- HUD 渲染走 Metal 覆盖层与预览同帧提交（无撕裂）；建议条是 SwiftUI 层（低频）。
- guidance_followed 判定：建议出现后 T+6s 内指标进入解除区 = 跟随（采纳率埋点核心）。

## 12. 可用性测试脚本

1. 「把人拍完整、拍居中」——不解释五类问题，观察用户是否按箭头走位（任务完成率 ≥4/5）。
2. 故意逆光站位——观察建议是否被理解并可执行。
3. 连续 2 分钟手持轻微晃动——观察建议是否来回跳（主观「稳定」评价 ≥4/5）。

## 13. 测量口径补充

稳定性按技术大纲§5：恒定场景、±2°噪声且不跨真实问题边界时，60s无重复激活；正常达标、文案升级、新问题分别计数。guidance_followed仅在激活后6s内完成解除驻留时记录一次；之后达标可反馈成功，但不计采纳。
