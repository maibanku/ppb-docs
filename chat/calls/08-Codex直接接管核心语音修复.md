# Codex直接接管：核心语音通信修复

日期：2026-11-10。用户要求Codex直接开发，本轮已安全中断Claude Lead并由Codex直接修改、测试和部署；未继续把代码交给Claude执行。

## 修复范围

### 原生语音生命周期

- 连接失败、超时、发布失败、账号失效均由资源守卫停止音频、静音已创建音轨、关闭房间，避免失败后持续占用设备。
- 断开事件清除活动通话，释放设备与后台任务，允许重新拨号。使用connect返回的原始事件接收器，保留发布期间已到达的事件。
- 账号变化与取消信号可中断连接/发布；最终登记时再次校验账号代次与操作代次，阻止“已取消却迟到接通”。
- 退出登录监听先检查当前代次，再等待变化，避免订阅之前发生的退出被漏掉。
- 挂断先停止本地设备，再等待网络；取消仅清理匹配通话，纯本地收尾支持可选callBizKey，旧请求不能直接清理另一通电话。
- 多步HTTP与失败补偿绑定原账号代次，避免旧操作改用新账号的凭证。
- 双端抢接听时检查acceptedDeviceId，失败端不发送leave，避免误挂断成功端。
- 静音由全局状态改为音频引擎实例状态；没有通话时查询设备不再初始化硬件；原生也拒绝尚未实现的视频路径。

### 桌面交互

- 点击发起后立即显示拨号面；Create/连接尚未回包也可取消。
- 开始操作的迟到成功不能覆盖结束/取消，ACTIVE先于invoke回包不会退回响铃或清空计时。
- 失败原因在结果面可见，支持重新发起；恢复出的主叫入房状态不假装对方已接听。
- 已结束的原生快照不会从idle复活电话；重连补拉确认通话消失时清理本地媒体。
- 所有事件回调检查监听代次；旧账号回调失效；登出清理携带旧通话键。
- 拨号中允许最小化和取消；设备选择仅在实际通话阶段显示。

### 服务端

- 单聊任一已接听成员挂断会结束整通电话、清扫双方、关闭房间并通知对端；群聊个人离开继续保留其他人的通话。
- 接听已成功而SFU回调尚未到达时也允许单聊挂断，避免受回调时延影响。
- 接听、群拒绝/离开以及群成员入会均推进快照版本，避免前端版本闸丢弃参与者变化。
- 新增直接挂断、重复挂断、群聊个人离开与事件版本回归测试。
