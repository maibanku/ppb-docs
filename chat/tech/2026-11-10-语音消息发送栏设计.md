# 语音消息发送栏设计

日期：2026-11-10。状态：产品与交互设计，尚未实现。

## 1. 当前能力与范围

本次代码核查：发送栏已有表情、图片、文件/视频、截图；文件消息可按扩展名识别音频并播放，但没有录音入口、录音状态机和独立语音消息类型。当前后端类型已使用1至8，包括8富文本，不能覆盖现有类型。

目标：添加麦克风图标，形成录音→停止→试听→发送/重录/取消的闭环。这里是异步语音消息，不是语音通话。首版不包含通话、转文字、变声、暂停续录或后台录音。

## 2. 工具栏位置与视觉

顺序：表情 → 图片 → 文件 → 截图 → 语音。采用现有lucide麦克风线性图标，20px图形，至少32×32px命中区域；普通态无边框、中性色，hover轻背景，键盘焦点明确。禁用态同时有说明，不只降透明度。

工具提示：“语音消息”；aria-label同文。录音期间图标采用强调底色并显示状态点，辅以明确“录音中”文本；不能仅以红色表示状态。图标与文字不使用电话听筒，避免误解为发起通话。

不把录音设置拆成常驻复杂菜单，不在整个客户端中央放大型遮罩。录音面板位于当前发送区域，沿用正文宽度、圆角与同色系背景分组。

## 3. 四种界面

### 3.1 准备

点击麦克风展开语音面板，正文暂时隐藏但不卸载，文字草稿、图片与引用全部保留。面板展示“发送语音消息”“点击开始录音”和取消/开始录音按钮；此时不访问麦克风。焦点进入开始按钮。

首次实际开始时调用系统麦克风权限；拒绝后显示原因、重试或打开系统设置入口，不能永久转圈或反复自动弹权限。未授权前不显示“录音中”。

### 3.2 录音中

一行展示状态点、录音中、mm:ss和实时音量波形；底部显示取消与“停止录音”。建议正文高度112–144px，最终受发送区可用空间约束。实时音量不等于语音识别，不上传音频。

提出首版约束：最短1秒、最长60秒。50秒时显示剩余时间，60秒自动停止并进入试听，不自动发送。低于1秒说明“录音太短，请重试”，回准备态；不能生成空白消息。

录音期间禁用附件选择、截图与第二次录音，允许取消。时间与波形通过原生事件更新，前端不以定时器估算最终时长。无输入设备、设备中途断开或采集失败：停止并给出可重试提示。

### 3.3 试听

展示播放/暂停、时长与进度、简化波形；底部显示重录、取消、发送。完整录音可播放确认后再发送，不要求必须听完。

点击重录会替换现有录音，应先明确提示丢弃当前录音；取消返回原文字输入与附件草稿。停止播放并释放音频资源后才能开始重录。发送语音不会顺带发送原文字或图片；引用可以随本条语音发送，成功后才消费引用。

### 3.4 发送

发送按钮显示上传中/发送中，不允许重复点击。成功后恢复原输入框，将语音作为独立消息插入消息列表；失败保留录音和试听能力，显示重试与取消。上传失败重试上传；已取得文件键但确认不明，复用原clientMsgId重试，不能重复产生消息。

## 4. 交互规则

| 操作 | 规定 |
|---|---|
| Esc | 准备态关闭；录音中停止并询问是否丢弃；试听态关闭前确认丢弃 |
| Enter | 准备态不隐式录音；录音/试听不沿用文本Enter发送，按钮获得焦点时走正常键盘激活 |
| 中文输入 | 原文本草稿原样保留，不把录音快捷键混入输入法事件 |
| 切会话/账号 | 录音中先停止并询问丢弃；不能把录音继续挂到另一个会话。账号切换/登出强制停止并隔离清理 |
| 窗口失焦 | 录音中自动停止进入试听，提示“录音已停止”；不得在后台持续录音 |
| 多选消息 | 无录音时沿用隐藏输入区；录音中先处理录音退出，不能把活跃录音藏到不可见区域 |
| 断网 | 可录音和试听，未上传时发送按钮禁用并提示联网；不把尚无文件键的录音伪装为已排队 |
| 播放互斥 | 同时只播放一条语音；开始录音前暂停聊天音频和试听 |

MVP不跨重启恢复录音文件；窗口异常退出清理临时录音。正常切换导致丢弃前有确认，不能无提示吞掉内容。录音状态以服务器×账号×会话×epoch绑定，所有异步回调检查归属。

## 5. 消息区展示

使用独立语音气泡：播放/暂停图标、时长、简化波形与播放进度；沿用己方/对方气泡底色、头像和发送状态。宽度建议随时长缓慢增长但上下限固定（160–280px），窄消息区以可用宽度为上限。

下载前显示加载状态，失败提供重试；播放失败不标记为消息发送失败。禁止自动播放。播放后是否显示“未听”标记须有明确状态模型，不能与会话未读或已读回执混淆；首版不增加跨端“已听”回执。

会话摘要“[语音] 12秒”；引用摘要同义；复制操作不复制内部文件地址。保留下载、引用、撤回；转发必须先完成附件授权与类型兼容，未实现时不显示可用入口。旧端降级为可识别音频附件或提示升级，不能显示空消息。

## 6. 数据与协议

建议新增独立voice类型；9仅为待审核编号，不在设计阶段直接占用。字段：fileBizKey、durationMs、mimeType、可选waveform、结构版本。时长和MIME由后端读取或校验；客户端上报值不作为唯一事实。波形采用有限采样点（建议32个0–100整数），不传整段采样数组。

发送：原生录音到私有临时文件→封存草稿句柄→上传文件→建立会话附件引用→发送消息→服务端确认。WebView不获取录音绝对路径、麦克风原始流或身份凭证。数据库沿用消息主表及附件关系，是否增加类型元数据字段需先核查现有富文本扩展方案，不为UI单独造平行表。

历史查询、WS推送、发送确认、本地SQLite缓存和离线恢复必须保留一致元数据。格式选择以macOS/Windows录音、编码、播放和文件服务验证结果为依据；先跑通一套可验证编码，不仅凭文件扩展名宣称兼容。

## 7. 状态机

closed → ready → permission_pending → recording → preview → uploading → sending → closed。

失败按阶段回到ready/preview并保存可恢复内容；取消只销毁对应会话的录音句柄。原生拒绝重复start；stop/cancel/dispose幂等。recording期间任何退出路径最终都停止硬件采集；前端组件隐藏不是停止录音的替代。

## 8. 实施文件与任务

1. 先定义voiceDrafts纯状态机和VoiceRecorderPanel组件契约，建立设计预览（仅开发预览，不在生产暴露假录音按钮）。
2. Tauri新增录音模块和command：权限/开始/停止/取消/试听资源读取；macOS使用麦克风用途说明，Windows补对应设备错误处理。具体音频库需单独验证后锁定依赖。
3. MessageComposer新增麦克风按钮与语音面板；ChatController编排会话作用域、互斥播放、上传、发送与恢复。
4. ppb-base同步Proto、网关消息校验、IM保存/推送与文件授权，明确类型编号与兼容策略。
5. MessageList新增语音渲染器，本地缓存保留元数据，设置与系统权限入口连通。
6. 全链路通过后开放生产入口，未完成原生采集和后端发送前不得仅加一个可点击icon声称完成。

## 9. 验收

首次允许/拒绝权限、设备缺失/断开、短录音、60秒截止、重录、试听、取消、失焦、切会话、登出、多选切换；所有路径停止采集且草稿隔离。

真实本地双账号验证：录音→试听→上传→发送→接收播放→重进历史→下载→引用/撤回；模拟上传失败、确认丢失与重试，验证无重复消息。两种主题、键盘导航和窄窗下按钮都能访问。

隐私验收：完成/取消后麦克风占用释放；发送前无网络上传；日志不含音频内容、token和本地敏感路径。设计规格不代表这些条件已验收。

## 10. 当前库表支持程度与推荐调整

核查依据：ppb-base实际GORM模型、deploy/sql/ppb_im下DDL、Proto和消息收发服务；未直接查询运行中MySQL，因此以下是代码/建表契约结论，不代表已执行生产或本地实例迁移。

### 10.1 已经支持的部分

- im_message：msg_type为int8模型；会话、发送者、seq、状态、回复/转发和幂等键可完整复用。
- im_message.im_file_id指向im_file，一条语音一个音频文件正好符合现有单附件关系。
- im_file：已有会话现场、真实文件主键、文件业务键、文件名、大小和图片宽高；音频不使用宽高。
- file/file_blob：现有文件存储及MIME字段可复用。File.Mime是客户端声明，FileBlob.Mime是服务端嗅探，不能把前者直接当语音格式判定。
- 客户端SQLite：已有msg_type、content、file_info JSON字符串和pending_sends；语音元数据可以进入file_info对象，无需为每条语音新建客户端表。

### 10.2 当前不支持的部分

- 无独立语音消息类型；发送白名单仅支持1/2/3/6/7/8，直接传9会被拒绝。
- im_file及file_blob当前模型没有音频时长、波形；公共FileInfo也仅有键、名称、大小、宽高。
- push_fanout_service仅为图片/文件/视频装配普通附件，需要将语音纳入；历史、消息点查、管理视图与转发都需核查同类白名单。
- 录音权限、采集、试听和语音草稿并不是数据库已有能力。

结论：现有表支持“上传一个音频文件作为普通文件消息”，不等于已经支持“可录制、带可信时长与波形的语音消息”。

### 10.3 推荐MVP数据库设计

不新建voice_message平行表，不拆分会话或消息序号体系，im_message继续通过im_file_id引用语音文件。消息主表结构无需因语音增加一组专用列；新增类型编号需审核保留，不能只改SQL注释就宣称支持。

按现有“文件域真源→IM本地展示投影”结构扩展：

| 表 | 建议新增列 | 用途 |
|---|---|---|
| file_blob | media_duration_ms BIGINT NULL | 服务端解析的媒体时长；非音频/未知为NULL |
| file_blob | media_waveform_json TEXT NULL | 可选32点规范化波形，文件域解析生成 |
| im_file | media_duration_ms BIGINT NULL | 发送时复制可信媒体时长，历史读取不用逐条请求文件服务 |
| im_file | media_mime_type VARCHAR(128) NULL | 文件域可信MIME展示快照 |
| im_file | media_waveform_json TEXT NULL | 波形展示快照；NULL时使用普通播放进度条，不伪造波形 |

推荐波形格式：{"v":1,"samples":[0,12,40,80,...]}，最多32个0–100整数；此处省略号仅示意，不是可提交JSON。时长单位固定毫秒，语音MVP限制1000–60000ms；NULL与0不同，语音必须取得有效时长，不能用0兜底并发送。

这份扩展建议尚未修改代码或执行DDL。是否复用未来文件平台媒体元数据扩展，应在实施前再次检索，避免同义字段重复。

### 10.4 协议与写入规则

- common.FileInfo新增optional durationMs、mimeType、waveform字段，沿用业务键对外、不传跨库数字ID。
- 发送请求复用fileBizKey，不要求信任客户端填写duration；服务端读取已验证的文件元数据，验证是允许的音频格式、时长范围、归属和引用权限。
- 文件解析必须有资源/耗时上限；解析失败保持可重试，不创建“发送成功但不可播放”的语音。
- im_message与im_file投影在既有事务内一致落库；跨服务引用登记沿用幂等与补偿机制。
- 推送、历史、缓存、会话摘要统一使用同一语音元数据映射。新增字段允许旧端忽略，但未知类型仍需展示降级提示或设最低客户端版本。

### 10.5 迁移与实施顺序

1. 先查询实际数据库列和迁移历史，与模型/DDL对齐，确认是否已被其他任务扩展。
2. 增量添加nullable列；同步MySQL DDL、GORM模型、已有迁移入口与SQLite测试，不改写老数据或依赖AutoMigrate代替发布迁移。
3. 文件服务产出可信时长，按需生成波形；更新跨服务文件元数据协议与客户端。
4. IM增加语音类型和附件装配，验证幂等、权限、撤回与历史查询。
5. 最后开放录音UI与类型发送；旧版本服务在发布窗口内不得收到它不识别的语音类型。

验收至少包含：旧消息迁移前后可读；音频时长不能伪造；无权限文件拒绝；波形缺失仍可播放；确认重试仅一条消息；撤回不再回原附件；客户端重启历史恢复时长和播放入口。
