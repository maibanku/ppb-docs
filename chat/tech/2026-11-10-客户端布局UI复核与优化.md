## 当前布局及保留项

现有主界面采用导航轨道、可拖拽会话列表、聊天主列。会话列表默认 280px，范围 220–420px，支持折叠。标题栏 36px；个人入口在顶部；头像使用圆角方形；支持浅/深主题、焦点样式、分割条键盘操作。已有搜索与发起聊天/群聊入口，不应再复制一套。

保留原生网络、身份与消息状态机；本轮布局设计不改变 RPC、会话序号、发送幂等或账号隔离。

## P0：可用空间与输入区

现状：MessageComposer BODY_MAX=560，手动正文高度存 localStorage；clampBody 只处理固定上下限。高值恢复到矮窗口时可能挤占消息区。

要求：
- 根据聊天工作区实际高度分配空间，消息区域最低保留 200px；工作区不足时降低输入区上限。
- 输入区总高度上限=min(工作区高度的45%, 工作区高度-标题区-200px)。正文上限扣除工具栏、附件、引用和底部操作区实测高度。
- 观察容器 resize，窗口缩放、引用栏和附件栏增减时重新计算有效高度。
- 持久化用户期望高度，实际显示高度按当前可用空间 clamp；窗口恢复后可恢复偏好，不反复覆盖偏好。
- 输入区极小空间下内部滚动，不挤掉发送操作；保持双击/键盘复位能力。

文件：MessageComposer.vue、RichInput.vue；尺寸计算放纯 domain helper 或现有 composable，不在模板堆算式。
验收：1024×640、1280×800、1440×900；恢复最大高度、显示引用和3项附件后，最新消息与发送按钮仍可访问。

## P1：主背景与层次

现状：styles.css 同时存在早期半透明背景规则、统一背景规则和后置覆盖；最终视觉受顺序影响。统一灰底方向已经存在，不重新换主题。

要求：标题栏与主背景同色；导航轨道用稳定实底；会话列表与消息区通过轻边界分区；气泡、菜单、弹窗保留实体表面。以 surface token 表达职责，禁止继续在文件尾重复覆盖旧选择器。

先制作关键选择器清单，记录最终生效声明；逐组件迁移后移除被取代的声明。登录壳渐变独立保留，不误改为聊天背景。
验收：浅/深主题、菜单/弹窗/输入焦点状态都检查；纯样式修改不得改聊天行为。

## P1：会话列与标题区

会话列默认280px保持，短窗口下搜索区固定、列表独立滚动。条目采用统一高度节奏（建议60–64px，先截图确认密度），头像36px，主标题14px/中等字重，摘要12–13px。长名称截断，时间和未读数不被挤压。

聊天标题内容区建议56px；主标题单行，群人数/状态次级显示。搜索和详情入口保持32px点击区域；不新增未实现按钮。桌面窗口拖动区不得覆盖按钮和文本交互。

折叠态恢复入口保持稳定且不随消息列表滚动；窄窗口限制会话列占比，为聊天列保留有效宽度，而非直接把列压到文字不可读。

文件：ChatShell.vue、SessionList.vue、聊天头部组件、styles.css。

## P1：消息阅读节奏

宽窗口限制文本气泡阅读宽度：建议不超过640px，且不超过消息区可用宽度的72%；窄窗口放宽至约85%。文件卡不超过可用宽度，长URL及文件名可换行。

连续同人消息采用轻量分组，但不能误把不同发送者合并；群昵称清晰、时间次级，不在每行重复过量信息。具体密度应先比较当前截图，不能仅凭注释认定当前已经实现。

状态不能只靠颜色：发送中、失败/重试、撤回、图片加载失败有明确文本或可访问名称。图片固定比例占位，加载后不应造成大幅滚动跳动；用户阅读历史时新消息不强制拉底。

文件：MessageList.vue、messageClusters 等现有 domain 模型、styles.css。修改前确认其他任务是否正在处理同文件。

## P1：输入区操作与图文预期

工具栏保持同规格，静态中性色、hover和focus清晰；发送操作在固定底部动作区域或正文有完整让位，不能遮盖最后一行文字。中文输入法确认不得触发发送；快捷键设置与实际行为一致。

现有编辑内容与发送后显示必须明确属于“多条顺序连发”还是“一条富文本消息”。此项是独立产品决策，不能用 CSS 把多个消息伪装成一条、却保留不同撤回/重试语义。未升级协议前保持真实语义并清晰提示。

上传失败保留未发内容；切换会话后异步回填不能写入新会话；发送期间防止重复提交，同批剩余内容失败恢复需使用原会话快照。

## P2：弹窗、详情与空状态

使用现有 overlay 栈；Esc先关闭最上层、焦点回原触发按钮、背景不可误操作。普通表单建议480px上下但最大不超过视口减32px；长表单内部滚动，确认按钮始终可达。

区分无会话、无搜索结果、加载中、请求失败和未登录；失败必须能重试，不能统一显示“暂无数据”。删除会话、退群、解散群明确不同后果。

## 全客户端样式收敛：区域与按钮矩阵

设计原则：背景属于同一中性灰色系，通过亮度和实体表面形成层次；强调色仅用于主操作、选中状态和交互提示。紧凑化优先压缩装饰留白，保留可点击尺寸和文本可读性。不能全局清除所有 border。

| 区域 | 本轮处理 | 交互要求 |
|---|---|---|
| 通讯录 | 列表头轻背景；详情实体表面；取消逐行分割线 | 长名称截断与好友动作不变 |
| 成员详情 | 头尾轻背景，48px高度；取消硬分割 | 保留关闭、主操作和内部滚动 |
| 个人菜单/加号菜单 | 实体底色、无描边、阴影；个人信息背景分组 | 保留Esc、键盘焦点、外点关闭 |
| @候选/表情/更多 | 取消浮层边框，保留阴影；标签栏轻背景 | @键盘选择与输入法行为不变 |
| 建群弹窗 | 已选项、确认摘要用控件背景；底部区域轻背景 | 勾选框及已选状态保留 |
| 转发面板 | 实体表面+阴影，无描边 | 保留取消与目标选择 |
| 登录近期账号 | 背景容器替代描边 | 身份切换行为不变 |
| 图片预览 | 工具按钮取消外框，保留深色底、悬停和焦点 | 深色遮罩独立于主界面浅灰主题 |
| 主题选择 | 背景区分选中项，底部强调条替代整圈描边 | 明确当前主题与键盘焦点 |

保留边界：原生窗口控制装饰、截图画布工具的对比边界、错误/警告、勾选框、图片叠加角标、拖拽分割条、必要的表格结构。若继续收敛，需逐项验证语义，不对全部选择器机械替换。
