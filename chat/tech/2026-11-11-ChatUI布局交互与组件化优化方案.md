# Chat UI 布局、交互与组件化优化方案

日期：2026-11-11。范围：`ppb-chat/chat-desktop`，基于真实客户端截图、现有代码及测试复核。
目标：在现有业务上逐步优化；每个改动能单独验证、回退；新增功能不要求修改整个聊天页。

## 1. 当前情况与问题依据

### 1.1 实际界面观察

- 桌面端已有导航轨、可调会话列、聊天区、底部发送区；主体方向成立，不需要推倒重做。
- 截图可见图片、文字、合并转发卡片；消息右侧头像已沿固定列排列，应继续保留固定头像槽。
- 左列搜索、新建入口、会话项均可辨认；当前实际列表处于保存后的窄宽度，较长群名和摘要频繁截断。
- 发送工具图标大多各有灰底；文件、截图还有下拉箭头，多个按钮组同时产生视觉强调。
- 消息区与顶部、左列采用相近背景，方向符合既有要求；分区应继续靠表面层级和间距，避免补大量边线。
- 输入区调整高度、列表折叠、群设置侧栏都已有实现。需要统一尺寸策略与窄窗验证，不能仅凭一张宽屏图判断正确。
- 登录已收敛为外部浏览器 IAM：客户端不再呈现账号密码、验证码或本地历史账号选择。

### 1.2 代码现状（复核时统计）

| 文件 | 行数约值 | 当前职责 | 风险 |
|---|---:|---|---|

| `components/MessageComposer.vue` | 754 | 输入、拖高、表情、@、附件、截图、录音、通话入口 | 工具栏动作与输入状态混合 |
| `components/ChatShell.vue` | 675 | 页面、会话列拖拽、群侧栏、资料和快速入口 | 主框架逐步变成所有交互的宿主 |

### 1.3 现有布局事实

- 导航轨 64px；会话列默认 280px，最小 220px，绝对最大 560px。
- 会话列上限会按窗口宽度反推，现有聊天区保底 460px；折叠阈值 140px。
- 输入正文手动高度范围 88–560px；当前逻辑为消息区预留至少 220px。
- 这些策略分散在 ChatShell 和 MessageComposer 中；后续应集中为纯布局策略，再由各组件使用。

## 2. 借鉴的原则与取舍

- 微信/企业微信式桌面布局：稳定导航、稳定头像列、消息内容优先、工具操作次要。
- Teams/Slack 类工作聊天：搜索、消息操作和成员详情保留上下文；选中、悬停、焦点分别表达。
- 不复制产品品牌色、素材或未经验证的具体尺寸；参考交互习惯，再用本项目真数据验证。
- Fluent 2 的间距体系采用 4px 基准并通过距离形成分组；本项目采用 4/8/12/16/24px 主间距。
- 模态用于需要完成或明确放弃的任务；成员、群资料等上下文信息优先侧栏。不同弹层共享焦点与 Esc 规则。

参考：[Fluent 2 Layout](https://fluent2.microsoft.design/layout)、[Fluent 2 Accessibility](https://fluent2.microsoft.design/accessibility)、[Pajamas Modal](https://design.gitlab.com/components/modal/)。

## 3. 布局与样式需求

### 3.1 主框架

1. 保持“导航轨 / 会话列 / 聊天主列 / 可选详情栏”的空间模型。
2. 导航轨继续 64px；头像位于顶部，设置归底部；当前页仅一个强调状态。
3. 默认会话列保留 280px，用户调整值保留；窗口变窄时先夹紧列宽，达到最小后改详情栏为覆盖式抽屉。
4. 统一布局函数输入：窗口宽高、导航宽、列表宽、详情栏模式、发送区高度；输出有效宽高和是否覆盖式展示。
5. 拖拽时只改变尺寸，不改变当前会话；拖拽取消/组件卸载时移除全局指针监听。
6. 宽屏、窄屏、恢复窗口尺寸后不允许消息列横向溢出，不允许发送栏把消息区挤成零高度。

### 3.2 会话列表

- 行高以 60–64px 为目标档；头像 36px；标题与摘要采用两行结构，不靠加粗所有文字提高可读性。
- 名称与时间分开占位，时间不得压缩为半截；标题、摘要允许省略并保留完整可访问名称。
- 选中：低饱和背景；悬停：更轻背景；键盘焦点：明确焦点环。三者不能共用一条蓝色外边框。
- 未读徽标、免打扰、置顶占固定附属槽，避免摘要因状态变化左右跳动。
- 加号入口保持一次选择“发起聊天 / 发起群聊 / 添加朋友”，打开后焦点进入菜单，关闭回到加号。
- 搜索无结果与没有会话分别表达；清空搜索后恢复原列表位置。

### 3.3 聊天标题栏

- 抽取纯展示组件 `conversation/ConversationHeader.vue`，输入标题、人数、连接提示、是否显示群设置。
- 只发出 `search`、`group-settings` 意图，不接收整个 ChatController，不发请求。
- 标题长时省略且可悬停查看完整名称；搜索/设置按钮保留固定空间。
- 连接异常提示允许换行，不能把标题或操作推出视口；异常用可访问状态，不只靠颜色。
- 正常态背景沿用主背景，无底部强调线；标题与成员数有清楚的字号层级。

### 3.4 消息列表与气泡

- 固定头像列，气泡列 `min-width:0`；多行、长链接、图片、转发卡都不能改变头像右边缘。
- 文字宽度同时受列宽比例和阅读宽度上限约束；长链接允许断行，文件名独立省略。
- 图片保留比例；下载/失败/重试状态在各自消息内部表达，失败不撑开整行。
- 系统日期不做强卡片；日期、发送者、消息正文分别有稳定间距。
- 普通、悬停、选中、搜索命中分开：选中采用柔和底色/阴影；多选不再追加蓝色气泡描边。
- 多选操作栏占用发送栏位置，底部居中；退出多选恢复草稿和焦点；引用、转发等互斥动作退出旧模式。
- 引用跳转应有定位反馈；找不到原消息时给出明确结果，不能无反应。

### 3.5 发送栏

- 保留当前混排输入、附件暂存和统一发送机制，样式调整不改变发送幂等与失败重试规则。
- 普通工具按钮默认透明，不为每个图标铺独立灰底；悬停、展开和录音中才给对应背景。
- 文件、截图的主按钮与下拉箭头保持组合关系；两组之间用距离分隔，不增加边框。
- 默认图标点击区域至少 28px，标题区采用 32px；箭头可视觉缩小，但不能只有几像素可点击。
- 输入快捷键说明为辅助信息；窄窗时允许收缩/换行，不能挤掉工具入口。
- 发送按钮只突出可发送状态；禁用状态不使用高对比强调色。
- 图片、文件、录音发送前显示可移除的草稿，发送失败可重试，不能展示“看似成功”的占位数据。
- 输入框拖高时消息区同步缩小；视图高度减小时重新夹紧手动高度；滚动到底与阅读历史两种状态分开保持。

### 3.6 群、资料、设置和弹层

- 群资料作为聊天右侧上下文，宽屏可停靠，窄屏覆盖；同一份业务视图，布局壳决定展示方式。
- 弹层分三类：锚定菜单、上下文侧栏、确认模态。禁止每个业务单独实现遮罩、Esc 和回焦。
- 成员资料、群公告查看以阅读为主；创建、邀请、修改公告以表单为主，操作完成后刷新原上下文。
- 危险操作统一确认文案，主语和后果明确；不能只写“确定吗”。
- 设置按账户、外观、消息、设备、文件分功能面板；各面板独立草稿与保存状态，切换页签不触发其他设置保存。
- 关闭有未保存内容的表单需要确认；查看型侧栏关闭不应阻断用户。

## 4. 低耦合代码组织

### 4.1 三个层级

| 层级 | 示例 | 可以依赖 | 不承担 |
|---|---|---|---|
| 通用视觉原语 | IconButton、Popover 壳、Dialog 壳 | 主题 token、焦点基础能力 | 当前会话、HTTP、权限业务 |
| 业务视图 | ConversationHeader、消息内容视图、群成员行 | 明确的展示 props、领域类型 | 全局 ChatController、token、生命周期编排 |
| 页面编排 | MessageList、Composer、ChatShell | controller/composable/视图 | 重复实现图标按钮、遮罩与焦点基础行为 |

优先使用组合、单一职责和依赖倒置。不要把所有功能塞入一个“万能组件”；不要为了缩短行数生成大量透传 props。

### 4.2 建议接缝

- `common/IconButton.vue`：统一按钮尺寸、无边框、hover/active/disabled/focus。
- `conversation/ConversationHeader.vue`：会话标题与操作，不读取 controller。
- `conversation/MessageBubbleShell.vue`：头像、姓名、时间、气泡槽；不理解图片/语音内部渲染。
- `conversation/renderers/`：Text / Image / File / Voice / MergedForward 内容组件，统一 props 和事件契约。
- `domain/messagePresentation.ts`：纯转换，计算消息可见内容、可用操作；不访问 DOM 和网络。
- `composer/ComposerToolbar.vue`：工具布局，emit 动作；附件、录音、截图继续由原有业务出口处理。
- `composables/useComposerPanels.ts`：仅管理表情/文件/截图等互斥面板、锚点、关闭和回焦。
- `domain/chatLayout.ts`：宽高约束的纯函数，布局状态与持久化由 composable 持有。
- `styles/ui-tokens.css`：尺寸和间距；业务组件 scoped 样式消费 token，不继续向全局追加覆盖补丁。

### 4.3 禁止的耦合

1. 新视图组件不得接收整个 ctrl 再随意读写内部状态。
2. 子组件不得自行修改会话选择、发送状态或登录 epoch。
3. renderer 不自行上传文件或重试消息，只 emit 事件到现有发送链。
4. 通用 IconButton 不执行网络请求、不判断群主身份。
5. 不引入与现有 ChatController 平行的第二套业务状态机。
6. 不以 `setTimeout` 猜测登录、上传或发送是否完成。

## 5. 分步改造与验收

### 第一批：建立视觉原语和标题接缝

- 新增 IconButton，迁移标题栏及发送工具栏的常规图标按钮。
- 抽取 ConversationHeader，保留现有搜索和群设置事件。
- 移除发送工具栏默认独立灰块，统一按钮反馈；保留展开态提示。
- 验收：长会话名、连接错误、群人数、按钮可访问名称、disabled、防重复点击与原事件行为。

### 第二批：消息展示与列表交互分离

- 先抽取 Voice / File / MergedForward 这类内容边界清楚的 renderer。
- 再抽取 BubbleShell；MessageList 保留滚动锚定、选择和定位，不一次替换整个消息循环。
- 每种类型覆盖正常、失败、撤回、引用、转发、选择和历史回放；真实接口不变。
- 验收：长文本/超长 URL/大图/文件名/合并转发不造成头像错位；新消息不打断阅读历史。

### 第三批：布局策略与发送面板

- 集中列表宽度、详情栏断点、发送区高度规则；复用 pointer 清理与尺寸持久化。
- 面板打开状态收敛为单一互斥模型，避免多个布尔值同时为真。
- 验收：最小窗口、宽屏、连续缩放、拖高输入、多选切换、输入法组合、粘贴多图。

### 第四批：资料、群设置和设置页

- 复用抽屉/模态壳，拆分设置页签的独立状态和保存动作。
- 验收：成员权限变化、邀请失败重试、公告保存、关闭脏表单、Esc 栈和焦点返回。

## 6. 完成标准与回退

- 每批独立 commit；保留公共入口、消息协议、数据库结构，除非另有明确业务需求。
- 首轮只做界面与组件职责调整，不以 UI 重构名义迁移业务表或修改鉴权。
- 运行对应交互测试、TypeScript 检查、构建；有结构或生命周期变化时运行全量回归。
- 至少真实点击搜索、打开群设置、输入/取消引用、图片暂存、工具菜单、录音/通话入口。
- 对比前后截图的边距、对齐与可见操作；测试通过不等于视觉验收通过。
- 深色主题、窄窗口、长姓名、无数据、断线状态分别验证。
- 出现消息位置跳动、草稿丢失或操作入口不可达时回退对应批次，不叠加全局 CSS 修补。
