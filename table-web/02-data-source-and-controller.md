# 02 保留现有请求与状态逻辑

更新：2026-11-19。状态：待执行说明，尚未修改组件代码。

## 本轮原则

继续使用现有 ProTable 受控/非受控接入、fetch、内部查询状态、本地分页工具及游标工具。不引入新控制器，不重写数据源协议，不因样式拆分而改变状态归属。

## 必须保留的行为

| 行为 | 要求 |
| --- | --- |
| 编辑筛选 | 不自动请求，保留草稿与已提交条件区别 |
| 查询/重置 | 继续现有事件路径；新增控件不得导致重复请求 |
| 翻页与页大小 | 使用现有状态和事件，保持原分页约定 |
| 排序 | 继续现有 sort-change 和请求映射，新增列属性不改变接口契约 |
| 刷新和操作后刷新 | 保留原刷新入口与当前页面行为 |
| 请求竞态 | 保留 epoch 等旧响应保护 |
| 删除末页记录 | 保留有效页回退 |
| 本地切片 | 保留 computed 缓存，不在模板内联 slice |
| 游标降级 | 保留探测、提示、手动全部查看及已加载数量语义 |
| 范围/账号变化 | 保留选择清理和既有数据隔离逻辑 |

隐藏分页控件与获取全部数据不同。新增显示开关只能控制展示，不能自动将远程分页改成拉全量。筛选折叠、列宽变化、列显隐和密度切换均不得触发列表请求。

发现原有状态问题时记录具体证据；仅修复因本轮改动引入或阻塞本轮能力的问题，避免扩大为无关状态重构。
