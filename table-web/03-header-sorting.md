# 03 表头排序

更新：2026-11-19。状态：待实施规范。执行前先读 [README](./README.md)，本文不代表功能已实现。

> 本轮范围：在现有 ProTable 上增量实现本专题能力，保留旧公开 API 与请求状态；下述目标命名为示意，不要求引入独立列表组件或现有状态逻辑。以 [00 调整清单](./00-style-refactor-checklist.md) 为总范围。

### 排序

“第一行排序”按点击表头解释：升序 → 降序 → 取消。首轮单列排序，支持默认排序；取消后清除当前排序，重置则恢复默认排序。排序变化回第一页，保留 appliedFilters。

远程排序仅映射接口实际支持的字段；不支持的列不开放点击。本地完整数据排序后再切片，不修改源数组；约定空值位置、数值/文本/时间比较规则和稳定排序。多列排序后续增强，类型预留 sorts 数组，旧适配器只接收第一项且不可静默丢弃用户已开启的多列排序。

## 配置和事件

| 配置 | 目标行为 |
| --- | --- |
| sortable=false | 无交互入口、无错误排序提示 |
| sortable=true | 使用数据源声明的排序能力 |
| sortField | 列 key → API 白名单字段，不能拼接 SQL |
| sortMethod | 仅在本地完整数据模式调用 |
| defaultSort | 初次加载与重置使用 |
| sorts | 现有组件的排序状态；表头根据它渲染 |

默认排序字段不在当前可排序列时，不能给错误列显示箭头。表头点击、键盘 Enter/Space 与外部设置走同一 setSort 动作；同一次手势不触发底层和包装层两次请求。aria-sort 反映当前方向。排序提示和列宽拖拽入口不得互相抢事件。

## 本地排序约定

空值默认始终在末尾；比较器先处理空值，再按方向比较非空值。同值保留源顺序；数字按数值、时间按解析后的有效时间比较，文本使用应用 locale。非法日期视作空值。业务 comparator 明确返回负/零/正，不得排序修改源数组。

## 自定义表头与列隐藏

表头插槽负责标题内容，排序控件由外层表头结构保留。隐藏当前排序列不会自动改变已提交排序，可在工具栏显示当前排序摘要；若列因权限或元数据删除而失效，则清理非法排序并统一触发一次刷新。用户仅调整列宽/顺序不得请求。

## 多列排序增强

首轮交付单列；多列排序作为明确后续项：使用 sorts 数组表示优先级，显示 ①②，支持调整/移除优先级，并要求后端声明 multiSort 能力。后端只支持单列时不开放多列入口，不能截断后仍提示已按多列排序。后续必须补充真实请求与稳定排序测试。

## 验收

升序→降序→取消、默认排序、重置、回第一页、未提交草稿不进入排序请求；自定义表头仍能操作；不支持排序的数据源无伪入口；本地排序后分页；用户清空排序后表头图标和请求完全一致。
