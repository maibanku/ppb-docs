# 10 ProTable 样式改造执行步骤

更新：2026-11-19。状态：待执行说明，尚未修改组件代码。

## 执行顺序

1. 阅读 README、00 的调整清单与 09 的视觉规范，检查现有 ProTable、类型、样式、消费者和测试。
2. 在现有组件内统一容器、筛选、工具栏、边线表格、状态区域和底部分页。保留原事件及状态处理。
3. 增量支持列对齐、宽度/最小宽度、固定、自定义表头等配置，兼容旧 col 插槽及 format(row)。
4. 完成筛选展开/收起、时间快捷项、可选序号与分页展示、排序入口及列设置。按实际接口能力开放功能。
5. 使用同一个 ProTable 制作九种开发组合，验证用户管理和一个本地列表页面；不向生产菜单添加验收页面。
6. 按 11 运行回归、类型检查、构建与真实浏览器检查，记录结果和截图。

本轮不要求创建 ProList/useProList，不要求统一数据源，不迁移现有业务状态。03～08 中的能力在现有 ProTable 上增量实现，文档示例类型/插槽名通过兼容方式接入，不能强制所有消费者重写。

## 交付记录

在本目录新增 implementation.md，记录实际改动文件、增量 API、旧接口兼容、示例入口、截图、测试结果及未完成项。明确区分已实现、后续增强和环境限制。不要预写“已通过”。

多列排序仅在后端明确支持时开放；查询方案、URL 条件记忆、通用编辑表、虚拟滚动等保留为后续增强，不作为这轮样式改造完成条件。
